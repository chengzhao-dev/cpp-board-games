终端对局

一次落子已经把棋盘状态变成可结束的对局。这一章首次把井字棋动态库接到终端程序，并在 WSL Ubuntu 中完成配置、编译、测试和运行。构建与验收入口是 build-and-run.sh。

终端步骤

这一节先验证脚本与测试，再核对排版，然后输入坐标运行一局。

执行脚本

在装好 CMake 4.2、Clang 和 Ninja 的 WSL Ubuntu 中进入 games/tictactoe/01-cli-game，执行脚本。

WSL Ubuntu（工程目录）
./build-and-run.sh

脚本依次完成配置、编译、格式与静态检查、测试和管道棋谱，首次运行生成 build/ 目录并复用。各步对应的工具：

  • 配置：CMake（跨平台的构建系统）读取构建规则，在 build/ 下生成构建文件，目录由仓库根的 .gitignore 排除。
  • 编译：Ninja（构建执行工具）按构建计划把源码编译成可执行文件。
  • 格式与静态检查：clang-format 读取本目录的 .clang-format 核对源码排版，clang-tidy 检查常见缺陷模式。编辑器保存文件时读取仓库根的 .editorconfig。
  • 测试：CTest（CMake 自带的测试运行工具）运行 tests/ 里的测试。
  • 运行：管道棋谱送入可执行文件 app，打印对局画面与结果行。

核对结果

tests/ 里的 board_test.cpp 和 game_test.cpp 直接读头文件 board.h 和 game.h 来核对规则，测试不启动终端程序。GameTest 覆盖这些场景：

  • 拒绝不是当前玩家的落子。
  • 按行、按列和两条对角线获胜，含最后一子同时三连。
  • 棋盘下满且没有三连时记平局。
  • 对局结束后、棋盘格子被占用或坐标出界时落子被拒绝。
  • 历史按落子顺序保存。

成功时先确认工程验证完成：

  • 配置：CMake 配置成功，生成 Ninja 构建文件。
  • 编译与检查：编译、格式检查和静态检查退出码为 0。
  • 测试：CTest 报告全部测试通过。

随后确认端到端对局完成：末尾打印完整结果行 对局结果：X 获胜，与对局规则中的终局画面一致。两项都通过，本章验收完成。

查看排版

棋盘的文本排版由 cli.cpp 决定，结果标签由其中的 PrintGame 追加：

cli.cpp
  std::string board = "    0   1   2\n";
  const std::string rule = "  +---+---+---+\n";

列号对准棋盘格子中心，横线分隔每一行，行号写在左边框左侧。PrintGame 把棋盘文本与 对局结果：... 结果行写入调用方提供的输出流。井字棋动态库不做终端 I/O。

输入坐标

构建成功后，可在工程目录直接启动 app 输入行列，也可把让 X 获胜的棋谱送入标准输入：

WSL Ubuntu（工程目录）
printf '%s\n' '0 0' '1 0' '0 1' '1 1' '0 2' | ./build/bin/app

输入行列时，PlayToEnd 循环打印棋盘、读取坐标并调用 Game::TryPlace，非法输入时报告原因并要求重试。输出应包含完整结果行 对局结果：X 获胜。这次运行与脚本末尾的管道棋谱是同一组落子，画面组成见对局规则中的终局示例。

常见错误

反复提示

非法输入让 std::cin 进入失败状态，之后程序反复提示同一句：

  • 出错的原因：失败状态未清除时，下一次读入会立刻再次失败。
  • 正确的做法：先用 clear 清除失败状态，再按行丢掉剩余输入，然后重新提示。

找不到动态库

如果配置和编译成功，但运行时报告动态库无法加载，先确认命令在工程目录执行。

  • 回到井字棋工程目录，重新执行 build-and-run.sh。
  • 只清理可重建的 build/，再重新执行脚本。

自测问题

先不要展开答案，试着自己把回答完整说出来，再展开对照。说不出来的部分，回到对应小节对照正文。

  1. 管道棋谱走完后，终端打印的结果行是什么？

    查看答案

    对局结果：X 获胜。脚本末尾的管道棋谱与手动送入的棋谱使用同一组落子，走完后终端打印这行结果。

  2. 棋盘上印出的列号和玩家输入的数字是同一套吗？

    查看答案

    是同一套。棋盘上印的行列号和玩家输入的数字都从 0 开始，不用换算。
