构建、测试并运行终端对局

检查落子并判定终局已经把棋盘状态变成可结束的对局。这一章首次把井字棋动态库接到终端程序，并在 WSL Ubuntu 中完成配置、编译、测试和运行。入口脚本是 build-and-run.sh。

执行验证脚本

在 WSL Ubuntu 中进入 games/tictactoe/01-cli-game，执行一键验证脚本。

WSL Ubuntu（工程目录）
./build-and-run.sh

脚本依次完成 CMake 配置、编译、格式与静态检查、CTest 测试和管道对局。配置和编译首次生成 build/，后续测试与运行都复用其中的目标文件。tests/ 里的两个测试文件直接读井字棋动态库的头文件 board.h 和 game.h 来核对落子规则，测试不启动终端程序。

成功时应观察到这些稳定结果：

  • CMake 配置成功，生成 Ninja 构建文件。
  • 编译、格式检查和静态检查退出码为 0。
  • CTest 报告全部测试通过。
  • 管道对局输出 X 获胜。

查看终端输入输出

cli.cpp 先写列号，再逐行写行号和三格：

cli.cpp
  std::string board = "    0   1   2\n";
  const std::string rule = "  +---+---+---+\n";

空棋盘格子显示为空位，X 和 O 显示为字母。PrintGame 接收输出流和 Game，终端程序负责打印，井字棋动态库不承担输入输出。

PlayToEnd 在对局进行中打印棋盘、提示输入，并调用 Game::Place。输入不是两个整数或超出 int 范围时，程序清掉本行剩余内容并报告错误；负坐标、上界越界或格子已占用时，棋盘保持不变并要求重试。

在终端完成一局

构建成功后，可以在工程目录直接启动程序并输入行列。也可以把会让 X 获胜的棋谱送入标准输入：

WSL Ubuntu（工程目录）
printf '%s\n' '0 0' '1 0' '0 1' '1 1' '0 2' | ./build/bin/app

输出应包含 X 获胜。这次运行与脚本末尾的管道验收使用同一组落子，读者可以先观察交互，再用固定输入复现结果。

常见错误

非法输入后反复提示同一句

std::cin 失败后若不清标志，下一次读入会立刻再次失败。

  • clear 之后按行丢掉剩余输入，再提示。

脚本运行时找不到动态库

如果配置和编译成功，但运行时报告共享库无法加载，先确认命令在工程目录执行。

  • 重新从 games/tictactoe/01-cli-game 执行 ./build-and-run.sh。
  • 只清理可重建的 build/ 后，再重新执行脚本。

  2. 为什么列号要印在棋盘上方？

    查看答案

    CellPosition 的行和列从 0 开始。印出的数字和输入的数字是同一套，玩家不用在心里减 1。
