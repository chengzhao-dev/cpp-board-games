一次落子

棋盘存储写出的 Board 已经能保存每一个棋盘格子。这一章在 Board 之上完成一次落子。声明与实现分别在 game.h 和 game.cpp 里。

对局数据

落子前先记下下子的玩家、落子的格子、棋盘有没有写入、对局有没有结束。这一节先列出对局类型，再写出对局成员。

对局类型

对局玩家用枚举 Player 表示，先手使用 X 棋子：

game.h
/// 对局玩家。
enum class Player : std::uint8_t {
  kCross = 0,   ///< 先手：使用 X 棋子。
  kNought = 1,  ///< 后手：使用 O 棋子。
};

一次落子要带上目标位置和落子的玩家，用结构体 Move 表示：

game.h
/// 一名玩家的一次落子。
struct Move {
  CellPosition position;           ///< 落子的行列坐标。
  Player player = Player::kCross;  ///< 执行落子的玩家。
};

这次落子有没有写进棋盘，用 PlaceResult 表示：

game.h
/// 一次落子的处理结果。
enum class PlaceResult : std::uint8_t {
  kPlaced = 0,    ///< 落子已写入。
  kRejected = 1,  ///< 落子被拒绝，局面保持不变。
};

整局进行到了哪一步，用 GameResult 表示：

game.h
/// 对局的结果。
enum class GameResult : std::uint8_t {
  kInProgress = 0,  ///< 游戏进行中：对局尚未结束，可继续落子。
  kCrossWin = 1,    ///< X 获胜：达成三连。
  kNoughtWin = 2,   ///< O 获胜：达成三连。
  kDraw = 3,        ///< 平局：棋盘已满且双方均未三连。
};

对局成员

四个数据成员都在 game.h 的 private: 下，board_ 用 Board，current_player_ 用 Player，result_ 用 GameResult，history_ 按顺序保存 Move：

game.h
 private:
  Board board_;                                  // 对局的棋盘。
  Player current_player_ = Player::kCross;       // 当前轮到的对局玩家，X 先手。
  GameResult result_ = GameResult::kInProgress;  // 当前对局结果。
  std::vector<Move> history_;                    // 本局落子历史。

Game() 默认构造之后，四个数据成员是下面这样：

  • 棋盘：board_ 是空棋盘。
  • 轮次：current_player_ 为 Player::kCross。
  • 结果：result_ 为 GameResult::kInProgress。
  • 历史：history_ 还没有落子。

四项都在对象内部，读取函数可以查看，只有写入落子的函数会改它们。history_ 按落子先后排列，查询它就能回放这一局。PlaceResult 不在这四项里，它是后面 TryPlace 的返回值。

终局判定

落子写入棋盘后，Game 先检查有没有形成三连。接着判定对局结果是继续、获胜还是平局。

三连

HasPlayerLine 检查刚落子的玩家有没有连成一条线，写在 game.h 的 private: 下：

game.h
 private:
  /// 检查棋盘上是否已形成三连获胜线。
  ///
  /// @param board 被检查的棋盘。
  /// @param state 要比对的棋盘格子状态。
  /// @returns 任一行、任一列或任一条对角线上的三个棋盘格子都是 state。
  [[nodiscard]] static bool HasPlayerLine(const Board& board, CellState state);

实现写在 game.cpp 里，先准备两个检查助手：

game.cpp
bool Game::HasPlayerLine(const Board& board, CellState state) {
  const auto has_state = [&](CellPosition position) {
    return board.GetCellState(position) == state;
  };
  const auto has_line = [&](CellPosition a, CellPosition b, CellPosition c) {
    const std::array<CellPosition, 3> line{a, b, c};
    return std::ranges::all_of(line, has_state);
  };

has_line 把三个坐标收进数组交给 std::ranges::all_of，按行、列、对角线调用：

game.cpp
  for (int row = 0; row < kRows; ++row) {
    if (has_line({.row = row, .col = 0}, {.row = row, .col = 1}, {.row = row, .col = 2})) {
      return true;
    }
  }
  for (int col = 0; col < kCols; ++col) {
    if (has_line({.row = 0, .col = col}, {.row = 1, .col = col}, {.row = 2, .col = col})) {
      return true;
    }
  }

  return has_line({.row = 0, .col = 0}, {.row = 1, .col = 1}, {.row = 2, .col = 2}) ||
         has_line({.row = 0, .col = 2}, {.row = 1, .col = 1}, {.row = 2, .col = 0});
}

三类线正好覆盖八条可能的三连：

  • 三行：每行三个棋盘格子由循环里的三个坐标确定。
  • 三列：每列同样由循环里的三个坐标确定。
  • 两条对角线：主对角与副对角直接写出坐标，任一条满足就返回 true。

对局结果

棋盘只认棋子不认玩家，PlayerToCellState 把玩家换算成要写入的格子状态，定义在 game.h 里：

game.h
/// 由对局玩家得到应写入的棋盘格子状态。
///
/// Player::kCross 对应 CellState::kCross。
constexpr CellState PlayerToCellState(Player player) {
  return player == Player::kCross ? CellState::kCross : CellState::kNought;
}

三连没有出现时，对局也可能因为棋盘下满而结束，判定顺序是先胜负、再平局，ResultAfterMove 写在 game.h 的 private: 下：

game.h
  /// 判定落子后的对局结果。
  ///
  /// 刚落子的玩家获胜则判胜，否则棋盘下满判平局，都未发生则对局继续。
  ///
  /// @param board 落子后的棋盘。
  /// @param player 刚落子的对局玩家。
  [[nodiscard]] static GameResult ResultAfterMove(const Board& board, Player player);

实现写在 game.cpp 里：

game.cpp
GameResult Game::ResultAfterMove(const Board& board, Player player) {
  if (HasPlayerLine(board, PlayerToCellState(player))) {
    // 刚落子的玩家已连成线，先判胜负。
    return player == Player::kCross ? GameResult::kCrossWin : GameResult::kNoughtWin;
  }
  if (board.IsFull()) {
    return GameResult::kDraw;  // 未分胜负且棋盘已满，判平局。
  }
  return GameResult::kInProgress;  // 仍可继续落子。
}

IsFull 来自上一章的棋盘入口，只回答棋盘是否下满，三连判定由 HasPlayerLine 另行回答。Game 因此把两个答案组合成终局结果，棋盘本身不保存对局结果。

落子写入

类型、数据和检查都齐了，最后把一次落子接起来。Game::TryPlace 收下一次落子，声明在 game.h 里：

game.h
  /// 尝试执行一次落子。
  ///
  /// 落子合法时，把落子玩家的棋子写入棋盘并轮到另一名玩家。
  /// 对局已结束、落子的玩家不是当前玩家、坐标无效或目标棋盘格子已被占用时拒绝，
  /// 棋盘和轮次保持不变。
  ///
  /// @param move 待执行的落子。
  /// @returns 落子执行成功返回 kPlaced，被拒绝返回 kRejected。
  [[nodiscard]] PlaceResult TryPlace(const Move& move);

Game::TryPlace 在下面几种情况拒绝落子，返回 PlaceResult::kRejected，棋盘和当前玩家保持不变：

  • 对局已结束：结果已经确定，不再改变。
  • 没轮到落子：落子的玩家不是当前玩家。
  • 位置不可用：坐标无效，或棋盘格子已被占用。

实现写在 game.cpp 里，把校验、写入和判定串在一次调用里：

game.cpp
PlaceResult Game::TryPlace(const Move& move) {
  if (result_ != GameResult::kInProgress || move.player != current_player_) {
    return PlaceResult::kRejected;  // 对局已结束，或落子的玩家不是当前玩家。
  }

  const CellState state = PlayerToCellState(move.player);
  if (!board_.PlacePiece(move.position, state)) {
    return PlaceResult::kRejected;  // 棋盘拒绝落子，局面保持不变。
  }

  result_ = ResultAfterMove(board_, move.player);  // 落子写入后立即判定终局。
  history_.push_back(move);                        // 成功写入才记录落子历史。
  if (result_ == GameResult::kInProgress) {
    // 对局未结束才把轮次交给另一名玩家。
    current_player_ = current_player_ == Player::kCross ? Player::kNought : Player::kCross;
  }
  return PlaceResult::kPlaced;
}

成功的落子先用 PlayerToCellState 从对局玩家得到要写入的棋盘格子状态，再交给上一章的棋盘入口写入。被拒绝的落子不改任何数据成员，轮次、结果、历史和棋盘都保持调用前的样子。调用方从返回值就能分辨两种结局：kPlaced 只表示已经写入，对局仍是进行中才轮到另一名玩家；kRejected 表示没有写入，仍是同一名玩家重试。

常见错误

重复落子

第二次写入同一个棋盘格子时，Board::PlacePiece 返回 false，原有状态保留，先手的棋子才不会被后手覆盖。

误判平局

最后一子同时形成三连时，要先判定获胜，再检查棋盘是否下满，顺序颠倒会把获胜记成平局。

自测问题

先不要展开答案，试着自己把回答完整说出来，再展开对照。说不出来的部分，回到对应小节对照正文。

  1. 空棋盘开局，轮到 X。没轮到的一方来落子时，棋盘会改变吗？

    查看答案

    不会。落子的玩家不是当前玩家，TryPlace 返回 kRejected，棋盘和轮次都保持原样。

  2. 刚创建的一局对局，轮到谁落子？

    查看答案

    轮到 X。Game() 默认构造后，current_player_ 的默认值是 Player::kCross。

  3. 最后一子既让棋盘下满，又形成三连时，对局结果是什么？

    查看答案

    判获胜，不判平局。ResultAfterMove 先检查 HasPlayerLine，刚落子的玩家已经连成线就是获胜。只有未分出胜负时，才检查棋盘是否下满。
