渐进式路线

前面的章节沿主线逐个推进。本章给出从最小工程到 WebSocket 评估的完整推进顺序、每个编号目录的进入门槛与执行纪律；目录只有在真实实现并通过对应验收后才算存在。

查看推进路线

十个编号目录从最小工程推进到 WebSocket 评估，每个箭头都以上一个目录的验收通过为门槛：

对照目录与章节

井字棋代码目录下的每个编号目录都是一个完整项目：独立拥有 .clang-format、.vscode/、CMake、源码和测试，可以单独打开、构建和验证。章节编号与目录编号相差 1：章节 02 对应目录 01，此后逐项对应；先看清工程和本页是横向说明页。

守住目录门槛

下表列出每个目录的可观察行为、主要验证与进入下一层的条件。

代码目录 章节 可观察行为 主要验证 进入门槛 / 下一层条件
01-toolchain-probe 配置并运行最小工程 稳定输出和返回 0 配置、构建、CTest 工具链闭环通过；规则库、AI、Python 放在后续编号目录
02-board-and-state 棋盘与状态 初始状态可观察 GoogleTest 值类型与状态桩测试 不变量明确；终端解析放在 05
03-move-validation 落子合法性 合法动作占用空格、非法动作不改状态 规则单测 合法与非法分支稳定；回合循环放在 04
04-turns-and-terminal-rules 回合与终局 回合稳定切换、正确终局结果 流程与规则矩阵测试 终局不可继续；AI、Python 放在对应编号目录
05-cli-and-acceptance CLI 与分层验收 两人可完成一局，验收可重复 CLI smoke、ctest、格式、渲染 井字棋完成定义满足；共享引擎、JSON/HTTP 等真实需求出现后再评估
06-ai AI 与双人扩展 选择合法且合理动作 必胜、防守、稳定性 双人规则稳定；Web 交互等真实需求出现后再评估
07-python-subprocess Python 与 Web 过渡 可记录一局或批量运行 退出码、输出、超时 CLI 协议稳定；网络服务等真实需求出现后再评估
08-json-protocol 同上 可机器读取状态和结果 合法/非法消息 文本边界不足以支撑自动化；UI 细节等真实需求出现后再评估
09-http-fetch 同上 浏览器可请求和提交动作 状态码、ok、JSON 协议可独立测试；实时推送确有必要时再评估 WebSocket
10-websocket 同上 推送消息和关闭状态可控 open/message/error/close HTTP 已不足以满足需求

06 到 10 的目录只在真实开始实现时创建，不提前建立空目录。

遵守执行纪律

每个目录都记录目标、路径、命令、预期输出、失败定位和完成状态。一个目录未通过时，不继续叠加后续层。target、文件和测试在实际创建并运行后，才能记录为已完成。

延伸到其他棋类

四子棋、五子棋、黑白棋等后续项目采用同一渐进方式；当前只维护井字棋，工具与分层约定见先看清工程。
