棋盘与状态

配置并运行最小工程把完整流程压缩在一个可执行目标里。本章把规则核心拆成独立组件并编译成动态库，定义棋盘与状态的值类型，固定查询、落子与结果三个入口，并引入 GoogleTest 编写规则测试。对应实现在棋盘状态实现目录。

定义值类型与状态

棋盘与状态的类型定义集中在规则库的公共头文件 value_types.h：取值封闭的集合用 enum class，数据组合用 struct 聚合，常量与枚举子以 k 开头，全部定义在 tic_tac_toe 命名空间内。先固定棋盘，再定义玩家与动作，最后建立状态与结果。

棋盘尺寸与位置

棋盘固定为 3 行 3 列，尺寸用编译期常量表达；位置由行号与列号组成：

value_types.h
// 棋盘尺寸：行数与列数，都是 3。
inline constexpr int kRows = 3;
inline constexpr int kCols = 3;

// 棋盘位置，行与列都从 0 开始，取值 0 到 2。
struct Position {
  int row;
  int col;
};

kRows 与 kCols 是 inline constexpr 常量，编译期可见，调用方无需重复定义尺寸。Position 是纯数据聚合，不加行为。位置是否落在棋盘内由 IsValid 判定：

value_types.h
// 判断位置是否落在 3×3 棋盘内。
constexpr bool IsValid(Position position) {
  return position.row >= 0 && position.row < kRows &&
         position.col >= 0 && position.col < kCols;
}

constexpr 让这个判定在编译期与运行期都可执行。

玩家、棋子与动作

对局的两名玩家与格子内容都用 enum class 表达：

value_types.h
// 对局的两名玩家。
enum class Player {
  kX,
  kO,
};

// 格子内容；kEmpty 表示空格。
enum class Mark {
  kEmpty,
  kX,
  kO,
};

一次落子动作由目标位置与落子玩家组成：

value_types.h
// 一次落子动作：把玩家的棋子放到指定位置。
struct Move {
  Position position;
  Player player;
};

// 把玩家映射为它落下的棋子。
constexpr Mark MarkOf(Player player) {
  return player == Player::kX ? Mark::kX : Mark::kO;
}

MarkOf 回答“玩家落下的棋子是什么”：Player 表达对局身份，Mark 表达格子内容，两者互不替代。类型形式的语言依据在 cpp-notes 的枚举与命名空间与结构体与值类型两章。

状态、结果与规则接口

终局结果与落子处理结果各用一个 enum class 表达：

value_types.h
// 终局结果；规则补全前固定返回 kInProgress。
enum class GameStatus {
  kInProgress,
  kDraw,
  kXWins,
  kOWins,
};

// 落子动作的处理结果；当前只区分接受与拒绝。
enum class ApplyResult {
  kAccepted,
  kRejected,
};

调用者通过规则接口提交动作并获得结果，不直接写数组：

  • 终端适配层：把用户输入转换成动作；
  • 测试：直接提交动作并检查状态；
  • 规则接口：Apply 提交落子，MarkAt 查询格子，Status 报告结果。

动作只从外部进入规则接口，状态不反向依赖调用者。接口定义在 game_state.h：

game_state.h
// 3×3 棋盘的状态：查询格子、提交落子并报告终局结果。
class GameState {
 public:
  // 初始状态：全部格子为空。
  GameState();

  // 查询格子内容；position 必须合法。
  Mark MarkAt(Position position) const;

  // 落子：越界拒绝并保持棋盘不变，合法位置写入棋子。
  ApplyResult Apply(Move move);

  // 终局结果：完整规则补全前固定返回进行中。
  GameStatus Status() const;

 private:
  // 按行优先顺序存放 9 个格子。
  std::array<Mark, kRows * kCols> cells_;
};

本章实现边界

本章的规则实现只有越界保护与占格写入：Apply 拒绝越界位置，合法位置写入棋子；Status 固定返回进行中。占用判定、回合切换与终局判定分别属于落子合法性与回合与终局。状态不变量（格子只能为空或属于一名玩家、终局后不再接受落子）在补全规则时作为测试基准。

编写构建规则与库查找

值类型与接口定义完成后，构建规则把规则库编译成动态库，并让 CLI 与测试链接它。

规则库目标

tic_tac_toe/CMakeLists.txt 把核心编译成动态库：

CMakeLists.txt
# SHARED 生成动态库，产物经顶层规则归入 build/lib。
add_library(tic_tac_toe_core SHARED
  src/game_state.cpp
)

# C++20 随目标传播：链接本库的 CLI 与测试也按 C++20 编译。
target_compile_features(tic_tac_toe_core PUBLIC cxx_std_20)

# include/ 是公开接口目录，使用方按 tic_tac_toe/xxx.h 找到头文件。
target_include_directories(tic_tac_toe_core
  PUBLIC "${CMAKE_CURRENT_SOURCE_DIR}/include"
)

SHARED 让 add_library 生成动态库 libtic_tac_toe_core.so，而不是把库代码复制进使用方。PUBLIC 声明的是用法要求：C++20 与公开头文件目录随目标传播给链接它的 CLI 与测试。这层动态库划分的是单个游戏内的组件边界；跨游戏的共享库提取，要等至少两个游戏的真实实现证明棋盘、位置或规则操作语义稳定后再评估。

产物目录

顶层规则把产物分归两个目录：

顶层 CMakeLists.txt

CMakeLists.txt
# 可执行文件归入 build/bin，动态库与静态库归入 build/lib。
set(CMAKE_RUNTIME_OUTPUT_DIRECTORY "${CMAKE_BINARY_DIR}/bin")
set(CMAKE_LIBRARY_OUTPUT_DIRECTORY "${CMAKE_BINARY_DIR}/lib")
set(CMAKE_ARCHIVE_OUTPUT_DIRECTORY "${CMAKE_BINARY_DIR}/lib")

可执行文件落 build/bin/，动态库落 build/lib/。源码树没有 lib/ 目录，它是构建产物目录。

运行时库查找

可执行文件运行时从哪里找库，由一行目标属性固定：

apps/CMakeLists.txt

CMakeLists.txt
# 把库查找位置写进可执行文件：从 build/bin 出发找到 build/lib。
set_target_properties(tic_tac_toe_cli PROPERTIES
  BUILD_RPATH "$ORIGIN/../lib"
)

BUILD_RPATH 把查找位置写进可执行文件本身，$ORIGIN 表示可执行文件所在目录。机制、常见错误与替代方案的完整讲解在 cpp-notes 的构建动态库并运行程序一章，本仓固定采用这套约定。

一键脚本的测试与运行步骤再用临时环境变量加固：

build-and-run.sh

build-and-run.sh
# 只包住这条命令的库查找路径：主路径是可执行文件内的 RPATH，这里仅加固。
# 变量展开保留调用者已有的 LD_LIBRARY_PATH，命令结束即失效。
env LD_LIBRARY_PATH="$PWD/build/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}" \
  ctest --test-dir build --output-on-failure

env 只在命令运行期间设置 LD_LIBRARY_PATH，命令结束即失效；查找路径不写进任何全局配置。

用 GoogleTest 验证状态

规则测试从本章起用 GoogleTest 编写。首次配置时由 FetchContent 拉取源码并与工程一起编译：

tests/CMakeLists.txt

CMakeLists.txt
# 首次配置时经 codeload 拉取源码包，与工程一起编译。
include(FetchContent)
FetchContent_Declare(googletest
  URL https://codeload.github.com/google/googletest/tar.gz/refs/tags/v1.17.0
)
FetchContent_MakeAvailable(googletest)

版本固定为 v1.17.0，拉取一次后离线可复用。测试可执行文件链接 GTest::gtest_main，由它提供 main 适配。

测试文件覆盖初始状态、落子写入、越界拒绝与终局结果四类行为：

game_state_test.cpp

game_state_test.cpp
// 初始状态的 9 个格子全部为空。
TEST(GameStateTest, InitialBoardIsEmpty) {
  GameState state;
  for (int row = 0; row < tic_tac_toe::kRows; ++row) {
    for (int col = 0; col < tic_tac_toe::kCols; ++col) {
      EXPECT_EQ(state.MarkAt({row, col}), Mark::kEmpty);
    }
  }
}

// 合法落子返回 kAccepted，并把目标格子标记为落子玩家的棋子。
TEST(GameStateTest, ApplyMarksTargetCell) {
  GameState state;
  const Move move{{1, 1}, Player::kX};
  EXPECT_EQ(state.Apply(move), ApplyResult::kAccepted);
  EXPECT_EQ(state.MarkAt(move.position), Mark::kX);
}

TEST 定义一个测试用例，EXPECT_EQ 断言两个值相等，失败时报告并继续。测试直接提交动作并检查状态，不经过终端文本。

常见错误

运行时找不到 libtic_tac_toe_core.so

直接运行 ./build/bin/tic_tac_toe_cli 报 “error while loading shared libraries: libtic_tac_toe_core.so”。先确认 build/lib/ 下已生成该文件，再检查 apps/CMakeLists.txt 是否包含 BUILD_RPATH 一行；补回后重跑 ./build-and-run.sh，配置时查找路径才会写进新构建的可执行文件。用 ldd build/bin/tic_tac_toe_cli 验证，解析结果应落在 build/bin/../lib/。

ctest 报 No tests were found

脚本第 3 步输出 “No tests were found!!!“。原因是顶层 CMakeLists.txt 漏了 enable_testing()：没有它，子目录注册的测试不会进入 CTest。在 add_subdirectory(tests) 之前补上，重跑一键脚本后测试计数恢复为 1。

GoogleTest 源码拉取失败

首次配置在 FetchContent 下载源码包时超时或报网络错误。本仓固定经 codeload.github.com 下载 v1.17.0 源码包，网络恢复后重跑一键脚本即可续传；拉取完成后构建不再需要网络。

自测问题

先不要展开答案，试着自己把回答完整说出来，再展开对照；说不出来的部分，回到对应小节对照正文。

  1. 规则核心为什么单独编译成动态库，而不是把 game_state.cpp 直接编进 CLI？

    查看答案

    CLI 与测试都要使用规则核心。独立的库目标让两边链接同一份产物，核心改动只需构建一次，PUBLIC 用法要求也把 C++20 与头文件目录传播给使用方。这是“游戏核心不依赖终端”在构建层的落实。

  2. RPATH 与脚本里的临时 LD_LIBRARY_PATH 各解决什么问题？

    查看答案

    RPATH 把查找位置写进可执行文件，是随文件移动的长期主路径。临时变量只包住单条命令，用于加固与排查，命令结束即失效。两者都不改全局配置，避免影响其他程序。
