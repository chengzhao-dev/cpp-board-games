CLI 与分层验收

回合与终局补全了规则核心的判断能力。本章设计终端双人闭环与分层验收；对应实现在终端闭环实现目录，实现并通过验收前按设计页阅读。

串联终端闭环

终端闭环把规则核心接入终端交互，从开局到正常退出的步骤如下：

终端闭环流程
初始化
  -> 显示局面
  -> 读取当前玩家输入
  -> 解析并验证动作
  -> 非法：报告错误并保留当前回合
  -> 合法：更新状态并检查终局
  -> 未结束：切换玩家并继续
  -> 结束：显示结果并正常退出

终端适配层只处理输入、输出和循环控制；胜负判断始终留在规则核心。

执行分层验收

终端双人闭环的验收只覆盖本目录职责：CLI 冒烟检查能用真实输入走完最小终端流程并正常退出；规则仍由核心测试直接验证，不用 CLI 文本覆盖所有领域行为。CTest 在一键脚本内统一运行。

更广的改动与验证对应关系见下一节矩阵；工具链 smoke、棋盘值类型和规则矩阵分别归属对应编号目录。

圈定验证范围

改动落在哪一层，就验证哪一层。下表是全书分层验证矩阵：

改动 对应验证
构建规则或工具链 该目录 build-and-run.sh（配置、编译、CTest、运行）
棋盘和值类型 初始状态、边界、位置转换
规则 合法/非法动作、回合、胜负、平局
CLI 少量端到端输入、输出和返回码
AI 必胜、防守、合法动作、确定性
Python subprocess 启动、输入输出、退出码、超时
JSON 合法消息、非法消息、错误结构
HTTP 状态码、response.ok、JSON 内容
WebSocket 建连、消息、错误、正常关闭
Quarto、主题或代码块标题 verify_content.py 与根目录 quarto render
C++、CMake、Bash 或格式注释 bash -n、该目录 build-and-run.sh、clang-format --dry-run --Werror，命名检查用该目录 .clang-tidy

改 Quarto 时额外抽查链接、结构、filename 和响应式布局。改注释时确认注释与真实代码同步。

守住测试边界

AI、Python、JSON、HTTP 和 WebSocket 都要在各自目录增加独立测试；它们不能成为降低核心规则测试质量的替代品。核心规则测试用 GoogleTest 编写，在棋盘与状态引入；CLI 冒烟检查继续由 CTest 直接注册。
