# 全书统一术语与替换规则

修订史见 `git log`。术语在全书只用一个词，读者与编写者才不会各说各话；词表的自动执行在 `.agents/skills/quarto-book-project/checks.json` 的 `forbidden_terms`，正文规范条文仍在插件 `writing-quarto` 技能。

## 统一术语表

| 术语 | 含义 | 用法规范 |
| --- | --- | --- |
| 步骤 | 配置、编译、测试、运行中的单个环节 | 全书首次写全四步名，其后用「流程」「脚本输出」「日志」等集合指称；同段不与「终端」「CI」等名词并列堆砌；不用「四步」缩写，不指代目录 |
| 井字棋工程目录 | `games/tictactoe/`，收拢库、终端程序与测试的一份工程 | 读者正文用「井字棋工程目录」，不叫探针，也不叫最小工程 |
| 目录指称 | 指到具体目录的写法（如 `tictactoe/src/`、`apps/`、`tests/`） | 目录统称（「实现目录」式）首次出现写全路径；前文已写全路径的集合指称（如「测试目录」）不受限 |
| 章节互引 | 在正文中指到书的另一章 | 一律用对应章节 title 作链接文字（如「工程目录」）；相对指称（上一章、下一章、本章）可作主语，但须紧跟标题链接或标题名；例外：本章回顾的「下一章」预告不写链接，直述预告一句（页面导航已有前进按钮） |
| 配置与构建 | CMake 读取规则生成计划；Ninja 按计划编译 | 成对出现时用对照表，不重复展开 |
| 冒烟测试（smoke test） | 程序能启动且基本行为正确的最基础检查 | 编写者知道这个词；读者正文只有在该节已经用它讲本节任务时才放术语卡（写法见标识 `bg-qmd-block-loop-v1` 的知识文件），不用段落括号夹注。目录章不放 |
| 棋盘格子 | 棋盘上的单个实体 | 正文、类型注释和接口说明均用「棋盘格子」；不单独写「格子」 |
| 九个棋盘格子 | 棋盘上全部九格的合称 | 合称写「九个棋盘格子」，不写孤立「九格」（词表硬拦孤立「九格」）；「格子」无论单数复数一律写「棋盘格子」 |
| 棋盘格子坐标 | 棋盘格子的行列坐标 | `CellPosition` 的首次定义使用此词；说明行列范围时保留「行」和「列」 |
| 棋盘格子类型 | 棋盘格子中记录的 `CellType` | 首次定义与类型上一行注释使用此词；三种类型的名称、字符与行尾结果词见「棋盘格子类型」一节 |
| 对局玩家 | 参与当前对局的玩家 | `Player` 的首次定义使用此词；动作说明写「对局玩家」 |
| 三连 | 一行、一列或一条对角线上同方棋子相连 | 获胜判定统一用「三连」，不用「占满一行」「连成三子」；棋盘填满写「下满」 |
| 落子动作 | 目标棋盘格子坐标与对局玩家组成的动作 | `Move` 的首次定义使用此词；不把它简写成「动作」后再切换含义 |
| 井字棋动态库 | `tictactoe/` 目录源码编译成的动态库（`add_library(tictactoe SHARED)`，产物在 `build/lib`），供终端程序与测试链接 | 组件称谓写「井字棋动态库」；首次出现用一句可观察行为带出（如「整个目录编译成一个动态库，供终端程序调用」）；其它工程按实际形态写明动态库或静态库 |
| Ai 落子 | `ai.h` 的 `Ai::Choose` 产生的一次 `Move` | 读者正文称「Ai 落子」，不叫「对手模块」；电脑的一步由 `Ai::Choose` 产生后交给 `Game::TryPlace` |
| 对手 | `PlayerToOpponent` 换到的另一名玩家（先手对后手、后手对先手） | 对手只指另一名玩家；不写座位；电脑一侧写电脑，其落子称「Ai 落子」 |
| 声明 | 只引入名字、不提供实体的写法（如 board.h 里只写函数名与参数表的成员函数行） | 辨析仅用于编辑与评审；content 正文不贴「声明」标签，位置与实现写具体事实（见易混概念一节） |
| 定义 | 提供实体的写法：常量给出值、类型给出全部成员、函数给出函数体 | 「定义在 board.h / game.h」作位置动词保留；.cpp 侧沿用「实现写在 board.cpp」描述行为层；正文不与「声明」成对使用（见易混概念一节） |

## 棋盘格子类型

棋盘格子的三种类型是全书的三态定稿，画面、字符与取值三层分开写，不在一句里滑过去：

- **画面**：格子框里的空白、`X`、`O`。终端已有这一行（cli.cpp 的 `CellSymbol`）：`|   | X | O |`；从左到右就是三态。
- **字符**：只在讲 `CellSymbol` 或终端输出时写出 `' '`、`'X'`、`'O'`。
- **取值**：`CellType::kEmpty`、`kX`、`kO`。行尾结果词只有「空格子。」「X 标记。」「O 标记。」，枚举行尾注释与头文件逐字一致；「这一格」「某一格」是禁用写法（见「禁用与替换」）；一句不换对象的判定全文见标识 `bg-prose-theme-v1` 的规范文件。

扩展禁令（注释、正文、正例同一套）：

- 不写「除了 X 和 O，空格也是一种类型」「显示对应的字母」「画成什么样」「框里的空位」。
- 不把 `CellType` 叫做空格、空位、标记、棋子；`Player` 的「先手：使用 X 棋子。」、`PlaceCell` 概述动词「放置棋子」与排版规则的「半角空格」不受限。
- 中文注释和正文不用裸参数名 `cell_type` 充当类型的名字，改说「要写入的棋盘格子类型」或三个结果词；头文件 `@param cell_type` 仍可点名参数。
- 谈到棋盘格子是三态中的哪一种，用结果词；`IsFull` 那种一行匿名 lambda（`cell_type != CellType::kEmpty`）条件已经写在代码里，不另加注释。

页面怎么摆写在插件 `writing-quarto` 的步骤文件里；机械拦截在 `.agents/skills/quarto-book-project/checks.json`。

## 易混概念：声明与定义

声明将名字引入程序，定义提供名字所关联的实体——常量写出值、类型写出全部成员、函数写出函数体；定义本身也是声明，声明未必是定义。本文件另区分三组预防性词对：形参/实参、初始化/赋值、重载/重写，判定见下文对照表。判定看内容不看位置：只写函数名与参数表的成员函数行是声明，给出初始值、全部成员或函数体的写法是定义，无论它在头文件还是源文件。这组辨析是编辑与评审的内部口径：content 正文不贴「是定义／是声明」标签、不成对展开两者的区分，位置与实现直接写具体事实（「换算写在 board.cpp」「常量在头文件里给出值」），「定义在 x.h」式位置动词不受限（正例：04 章写「`PlaceResult` ……定义在 game.h 里」）。依据：cppreference「声明将名字引入（或再引入）到 C++ 程序中」「定义是足以使该名字所标识的实体被使用的声明」；C++ Primer「变量能且只能被定义一次，但可以被多次声明」。正文禁令见「禁用与替换」，正反对照见标识 `bg-chinese-style-wording-v1` 的知识文件「术语标签对照句」。

预防性词对（当前全书未启用，出现时按下表区分）：

| 易混词对 | 区分 |
| --- | --- |
| 形参 / 实参 | 形参是函数签名里的变量（parameter）；实参是调用时传入的值（argument） |
| 初始化 / 赋值 | 初始化在创建时给对象首个值；赋值覆盖已初始化对象的现值 |
| 重载 / 覆盖 | 重载是同名函数不同参数表，编译期选择；覆盖（写 `override`）是派生类覆盖基类虚函数，运行期生效，本仓不用「重写」 |

禁用与替换三张表在 `forbidden-terms.md`（标识 `bg-forbidden-terms-v1`），本文件不再保留第二份。
## 通用规则

- 一个概念全书只用一个词；同义词不得轮换（最小工程与探针、编号目录与阶段）。
- C++ 关键字与字面值（`true`、`false`、`nullptr` 等）在正文指称时一律用行内代码原样书写，不写中文译名；叙述布尔概念（如「布尔值」）可用中文词。
- 术语首次出现处就近放术语 callout，规则见标识 `bg-chapter-skeleton-v1` 与 `bg-heading-hierarchy-v1` 的知识文件；本表只管「用哪个词」，不管「怎么解释」。
- 标题不使用正文之后才解释的术语；标题里的词必须是读者此刻已认识的或字面自明的。标题规则见 `heading-fit.md`。
