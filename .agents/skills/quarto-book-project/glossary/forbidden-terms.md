# 禁用与替换

拆自 `bg-terminology-v1`（`project-terms.md`）的三张禁用表；术语表与棋盘格子类型留在原文件。

## 禁用与替换

本表按对象列出必须替换的用词：章节互引、术语、布尔字面值、结构体成员叫法等都在这里。

| 禁用 | 替换 |
| --- | --- |
| 第 N 章式编号指称（「第 1 章」等，正文与标题均不用） | 章节标题链接：用对应章节 title 作链接文字；章内页互链保持 `.qmd` 相对路径 |
| 课（指称书的单位：「这一课」「第 N 课」「每课」「前五课」「课程」） | 章（「这一章」「第 N 章」「每章」「前五章」） |
| 链路、四步（缩写指称） | 全书首次写全「配置、编译、测试、运行」，其后用「流程」等集合指称 |
| 阶段（content 正文） | 具体路径 + 首次平实说明「`games/tictactoe/` 是井字棋的唯一工程目录，能独立配置、编译、测试和运行」，此后用「工程目录」「这个目录」指代 |
| 探针 | 井字棋工程目录；不把目录叫做探针 |
| 最小工程 / 最小程序 | 井字棋工程目录 |
| 第一版 | 去版本化：范围用「井字棋」，完成用「能在终端下完一局」 |
| 切片 | （已随「阶段」一并停用，见上行替换） |
| 自足 | 具体能力表述（能独立配置、编译、测试和运行） |
| 裸写「CLI」（指称章节） | 章名用「终端程序」，对象写终端程序 |
| 悬空指代（「这条路线」「这条流程」「这套流程」「这三个常量」「它们」等；先行词不在同句或紧邻句，或只在代码围栏里；延伸到自测题干的「这个／哪个」——题干合上书单独可读——与节首句以「这些／这个／这一步」作话题的前指，同句列不出对象名即悬空） | 写成具体对象：井字棋学习路径、配置—编译—测试—运行、文件名、`kBoardRows` 等标识符 |
| 讲义口导航（「下面分别精读」「如下分别说明」） | 直接进入对象：目录树后直接接正文，或一句点明要看的文件名 |
| 「下一节／上一节」式预告与回指（读者正文） | 新节首句直接接住上文；章末「下一章」保留 |
| 破折号夹心句（正文） | 冒号引出解释，或拆成两句 |
| 正文引语用直引号或直角引号 | 全角双引号 “ ” |
| 刻意保持 / 刻意……（作者姿态修饰） | 直接陈述对象做了什么、不包含什么 |
| 只可能 / 不可能来自（诊断断言） | 写成可核对的排查范围 |
| 只 / 仅 / 唯一 / 一律 / 永远 / 一定 / 必然（正文范围断言） | 删掉后句义不变就删；需要限定范围时写出尺寸、条件、文件名或入口。「只读」「只写」作固定术语保留 |
| N 段命令定义…（元计数导语） | 直接点名对象：这段规则定义可执行目标 app，规定产物目录、源文件和 C++23。 |
| 语法细节留到…（真正用到时再展开） / 本章只需认清…（渐进披露元叙述） | 直接陈述对象和结果（如「这段程序对外可见的结果只有两处：…」），延后内容保持沉默 |
| 「X 只包含：」排除式清单口 | 正面陈述「项目要处理这些内容」，用无序列表枚举 |
| 读懂 / 看懂 | 理解 / 确认 / 查看 |
| 弄清 | 理解 / 确认 / 查看 |
| 动手前 / 咱们 / 搞定 / 别慌 | 进入实现前先确认…；删除对读者的招呼语 |
| 本章规划 / 落点是 / 类型名只是设计方向 / 尚未对应可运行目录 / 落地 | 直接写这一章要交出的结果，并链到已有源文件 |
| 务必 / 严禁 / 千万不要 / 千万别 | 直接陈述动作或可观察后果 |
| 绝对不要 / 绝对不能 / 绝对禁止 / 绝对必须 / 绝对不行 | 写成可核对的条件或范围 |
| 标明 | 注明 / 写出 / 标出 |
| 技术基线 | 直接列出工具与用途（如「实现用 C++23，构建规则由 CMake 编写、Ninja 执行」） |
| smoke test（正文英文直写） | 冒烟检查加中文行为描述（如「用真实输入走完一局并正常退出」） |
| 跑通 | 执行 / 完成 / 走完（视语境） |
| 重建 | 重新生成（构建产物）/ 重新编译（源码） |
| 这正是…的原因 | 正面因果：因此… / 所以… |
| X 与 Y 是两个容易混淆的词（对照表元标签开场） | 先写各对象在做什么，再用一句关系句（如「配置改计划，构建按计划编译」）引出对照表 |
| 回到对应小节重读 | 回到对应小节对照正文 / 核对要点 |
| 接口桩 / 桩 | 直接写接口名称与行为边界（如「固定查询、落子与结果三个入口」；尚未实现的规则写明留待后续章节补全） |
| 静态到动态 | 直接写链接方式与变更内容（如「本目录把规则核心编译成动态库」） |
| 单独的「格子」（正文与类型注释） | 棋盘格子 |
| 「这一格」「某一格」（指棋盘上的格子） | 棋盘格子（行尾结果词见「棋盘格子类型」） |
| 格子内容 | 棋盘格子类型 |
| 棋子或标记（指 `CellType`） | 棋盘格子类型；棋盘格子是哪种类型时用结果词 |
| 规则库（组件称谓） | 井字棋动态库；其它工程按实际形态写明动态库或静态库 |
| 对局交流绑定媒介（「交流只发生在终端上」式全称限定） | 写交流的形态而不写死媒介，如「一局对局通过文本交流完成：玩家输入行列，程序打印棋盘和结果」；「终端」只指称终端程序、终端界面等具体对象 |
| 「固定」「遵循同一套规则」式表述（一律停用） | 章确定约定用「确定」；行为列举导语直接点名列表内容；不变量直陈事实；预定输入写「这组输入」 |
| 职责 / 负责 / 承担（「承担源码职责」「目录职责」「负责调用」式角色指称与角色动词） | 直接写对象保存、实现或检查什么（如「`tests/` 目录保存动态库的测试」「`Game` 判定对局是否结束」） |
| 分进（生僻动词搭配，如「源码分进三个目录」） | 放在 / 分成 / 由……组成（按语境，如「井字棋工程有四个目录」） |
| 拗口动宾，如「得出胜负与平局」 | 直接写交付对象（如 H2 用「终局判定」）；正文改说「落子后判定对局是否结束」 |
| 用实现细节当章节主叙事，如把「三连算法」当 H2 或 title | 「三连」是胜负判定的实现细节，可一句带过；H2/title 写读者面对的结果（如「终局判定」） |
| 用「是定义」「是声明」「……的声明」给代码实体贴标签，或成对展开声明与定义的区分（含把完整定义称「声明」） | 位置与实现写具体事实：「换算写在 board.cpp」「常量在头文件里给出值」；「定义在 x.h」式位置动词保留 |
| 函数原型 | 函数声明 / 成员函数声明 |
| 公开段 / 私有段（指类里 `public:` / `private:` 下的声明） | 写 `` `public:` `` / `` `private:` `` 下（或之后）；成员分别称「公开成员 / 私有成员」 |
| 公共成员（指 `public:` 成员） | 公开成员 |
| 成员变量（作主称呼） | 数据成员 |
| 方法（作主称呼，指成员函数） | 成员函数 |
| 字段（读者正文指结构体成员） | 成员按语义叫名字：`position` 是棋盘格子的坐标，`player` 是落子的玩家，同一句用同一种叫法；C++ 术语仍称数据成员，不把「字段」当它的别名 |
| 返回假／返回真／为真／为假（指称 C++ 布尔字面值） | 返回 `false`／返回 `true`（行内代码原样书写） |
| 语言课旁白（正文讲解 C++ 语言机制或风格指南条目，如「翻译单元」「纯数据聚合」「取值封闭」「数据组合用」「按 Google 风格」「命名遵守」「语言依据」） | 只写工程上的对接与验证：谁编译谁、谁读取、怎么验证；语言机制与风格条目不进正文 |
| 执 X / 执 O（棋类行话称棋子归属） | 写「先手：使用 X 棋子。」「后手：使用 O 棋子。」 |
| 座位（指另一名玩家：「另一座位」） | 对手或另一名玩家 |
| 并列量名后接光秃的「总数」（「和总数」「、总数」两个接续面） | 写全被计量的对象，如「棋盘格子总数」 |

读者页不单设路线章。正文要写学习顺序时，直接列出各章标题，不写「这条路线」。

改写案例见标识 `bg-chinese-style-wording-v1` 的知识文件。

## 禁用与替换：领域指称与旁白

术语「阶段」不能写进读者正文，其他领域指称与语言旁白同样禁用：

| 禁用 | 替换 |
| --- | --- |
| 映射 / 翻译（领域换算注释与工程旁白） | 由 A 得到 B（如「由对局玩家得到棋盘格子类型」） |
| 位置（指 `CellPosition`） | 棋盘格子坐标 |
| 用有符号整型承载 / 坐标字段为什么选定宽有符号 | （删除；选型论证不进工程正文） |
| 裸 `Result`（正文把 `GameResult` 简写成 `Result`；裸 `Place`、`History`、`CellAt` 同理） | 源码完整标识符：枚举类型写 `GameResult`，成员函数写 `Game::GetResult`、`Game::TryPlace`、`Board::GetCellType` |
| 非法落子 | 无效落子（「非法输入」「不合法写入」按对象保留） |
| 经规则接口读写 / 通过接口交互 | 写具体成员与动作（如「调用 `Game` 的成员读写棋盘」） |
| 枚举成员释义表 /「每个状态码对应…」释义段 | 禁止「每个状态码对应」和以 `类型::kName：` 开头的释义项。取值列表只写在代码围栏前，一项一个 `kName` 加一句选法，见标识 `bg-qmd-block-loop-v1` |
| 状态不反向依赖调用者 / 动作只从外部进入 | 写可观察边界（如「`Game` 不调用终端程序，也不读键盘」） |
| 层名（终端适配层、规则核心、规则接口）首次出现无定义 | 首次出现用一句可观察行为定义（如「规则接口是 `Game` 暴露的成员函数」），图节点用日常说法 |
| 公共头（含「公共头文件」「公共头 board.h」式省略） | 点名具体对象：文件名（`board.h`）、「动态库 `include/` 下的头文件」、「该头文件」；目录树注释写全「库对外头文件」 |
| 公共值类型 | 值类型，并点名文件或清单（如「`board.h` 里的尺寸、坐标和格子类型」） |
| 公共定义（反复总称） | 首次出现列清单（哪些定义、各是什么），后文用「这些定义」或文件名指代 |
| 公开头文件（目录树行尾注释） | 库对外头文件 |

## 禁用与替换：压缩隐喻与过短句

| 禁用 | 替换 |
| --- | --- |
| 契约（读者正文） | 点名文件与定义（如「`board.h` 供终端程序与测试读同一组棋盘尺寸」） |
| 契约链 | 写清头文件里有哪些定义、谁读取、谁调用（如「终端程序打印棋盘和测试遍历棋盘格子都读这三个定义」） |
| 状态外壳 | 写具体对象（如「棋盘格子的存储与结果状态码」「`Game` 保存的对局结果」） |
| 地基 | 写可观察的前置条件（如「规则接口稳定后，AI 才有可以调用的入口」） |
| 执行纪律 | 写具体约束（如「目录门槛与验收顺序」） |
| 闭环 | 写具体流程或结果（如「从开局输入到正常退出的一局」「终端双人完整对局」） |
| 消费 / 谁消费（读者正文） | 读取 / 调用 / 按…编译（写清谁对什么做什么，如「构建按计划编译源码」） |
| CLI 打印（及同类电报省略） | 完整主谓句（如「终端程序打印棋盘」） |
