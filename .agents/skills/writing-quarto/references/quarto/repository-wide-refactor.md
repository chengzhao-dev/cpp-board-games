# 全仓 QMD 重构

用于同时重构根入口、游戏入口和全部 `content/**/*.qmd` 的任务。它补充单章写作规则，不替代章节骨架和领域路由。

## 范围

先读取 `_quarto.yml`、根 `index.qmd`、所有 `content/**/index.qmd` 和 `content/**/*.qmd`。再读取对应阶段路由表、任务矩阵、直接引用的源文件、构建脚本和校验脚本。两仓对照时分别保留 board-games 的游戏阶段模型与 cpp-notes 的 part/chapter 模型。

## 排除

`_book/`、`.quarto/`、`_freeze/`、`temp/`、`games/**/build/`、`code/**/build/` 和其他 `scope.py` 标记的生成物、缓存不作为源内容改写。工作树已有未提交改动必须保留，不用 reset、clean 或 checkout 恢复。

## 章节递进

设计页先固定读者可观察的输入、输出和规则；布局页只说明目录、文件职责和依赖方向；状态与规则页再展开实现和终局；终端或验收页最后讲配置、编译、测试和运行。标题按实际任务命名，数量是预算而不是承诺；不要在早期页面预告或执行后续验收动作。

## 收口

全仓重构后，核对导航与路由表、标题层级、章节链接、源码摘录、命令和输出。先运行增量验证定位问题，再对所有 QMD 执行全量 `verify_content.py`/`run.py verify`，最后在仓库根目录渲染 Book。涉及知识库时同步索引、健康检查和评测；涉及代码时用实际构建、CTest 或示例验证核对文档。

## 两仓边界

只统一治理、写作递进、验证和目录契约。board-games 保留 `bg-*`、游戏阶段和游戏构建；cpp-notes 保留 `cpp-*`、`writing-cpp`、任务矩阵和示例验证。不复制另一仓的领域正文或专用规则。
