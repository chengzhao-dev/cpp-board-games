# 文档内容写作

## 文件关系先于单页润色

多个页面一起修改时，先确定入口、索引和正文的职责。根首页只回答「这是什么、从哪个游戏开始」，游戏落地页只安排顺序，正文负责一个可完成的任务。前置页面不提前展开后续命令，正文不重复落地页给出的路线。

包含实际源码和构建结构的章节，应在第一次展示源码前加入目录树，展示前核对真实磁盘。目录树细则见知识库 `bg-qmd-element-cases-v1`。

## 页面增长与拆页

教学页达到知识库 `bg-content-budget-v1` 的 token 上限（整章 5000 token）后，按读者任务拆页或上调本仓阈值，不做「上篇/中篇/下篇」式机械切分。每页只改变一个主要工程变量或回答一个可验证问题。每个新页面都登记到 `_quarto.yml`、游戏落地页与阶段路由表（`.agents/skills/cpp-development/references/stages/<game>.md`），并拥有独立的代码路径。

超限先判断内容是否必要：凑字数句删除，必要讲解保留并按读者任务拆页。长代码不得以内联围栏绕过预算；先下沉为 `games/` 仓库源码，再在页面中摘录关键片段。

## 标题与页面角色

- 章节标题由 YAML `title:` 提供，页面内不再写同文本的 `# H1`，正文从 `##` 开始。标题建议值见知识库 `bg-file-title-naming-v1`。
- `##` 与 `###` 不手填序号。`number-sections: false` 时序号只能手写，增删小节后会与目录和交叉引用不一致，本仓禁用手填序号。
- C++ 代码块默认内联摘录关键片段：逐字摘自 `games/**` 源文件，省略处直接省略不写标记行；filename 只写短显示名。片段细则以知识库 `bg-qmd-element-cases-v1` 为准。
- 任务区的每个 `##` 对应一个可验证结果。只有概念或结构、没有独立验收的内容并入引言或相邻任务。
- 标题只写读者要完成的任务，标题后的首句直接兑现承诺。
- 新手必须掌握的内容和引言说明放正文。引言用连贯段落交代动机、范围和全章路线。代码块前交代本步目标、执行环境和预期变化，代码块后只保留必要的后续动作、结果和少量解释；块内 `//` / `#` 注释已写明的意图不在块后同义复述（对照见知识库 `bg-chinese-style-cases-v1`「块后复述注释」）。Callout 只承载非主线、确有独立价值的风险、版本差异或可选替代；不重复正文动作或成功判据，不用于装饰层级，也不放进引言。
- 需要失败分支时，先用 `## 常见错误` 按症状列出 `###`，再用 `## 自测问题` 承载自测题，最后以 `## 本章回顾` 收束。不设置章末集中式资料区。

## 重构与事实核对

重构默认在原文基础上进行：先读取原文件、相关引用和任务边界，再局部调整结构、表达和衔接。只有用户明确要求，或原结构无法安全修复时，才删除后重新生成。目录、文件名、版本号、命令输出和工程结构等可从磁盘获得的内容，必须先实际获取。无法确认时只写检查方法，不伪造事实。

局部删除或移动内容后必须回读切口，并为后文仍引用的动作保留「触发时机 → 状态变化及原因 → 可观察结果 → 下一步」的最短闭环。后文出现悬空的「然后、因此、此时、重启、再次」等承接时必须重写切口，不能只按表面冗余删除过渡句。

改标题等于改锚点。改完用 `run.py check --profile fast` 和 `run.py render` 核对交叉引用。

## 配置文件与 CMake

`CMakeLists.txt`、YAML 等声明式文件使用原生注释；CMake 命令讲解的职责句写法见知识库 `bg-qmd-element-cases-v1`。CMake 术语优先采用 [CMake 官方中文文档](https://cmake.com.cn/cmake/help/latest)。

## 文档类型边界

这套「目标、解释、验证、少重复」原则也适用于 skill 与 `.agents/knowledge/`，但它们优先保持短小、可检索和可执行。Skill 与说明文档默认使用段落、表格、编号步骤和代码块，不为凑结构加入图片或 Mermaid。

README 遵循 GitHub Markdown。根目录 `README.md` 是在线阅读链接的唯一入口，根目录 `index.qmd` 不重复该链接。`AGENTS.md` 只保留硬性执行规则。

## 行内代码与链接

- YAML `title`、Markdown 各级标题和导航文本不使用反引号。标题中的技术名词直接写成普通文字。
- 反引号只包裹需要精确识别的技术对象：命令、工具、参数、文件名、路径、配置键、API、标识符和包名。普通概念、平台和产品名称不自动加反引号。
- 同一对象在同一章节内必须使用一致的标记方式。
- 指向仓库文件时写成可跳转链接，不用反引号包住路径冒充链接；仓库内路径链接统一用 GitHub 绝对链接（目录 `tree/main/<路径>`、文件 `blob/main/<路径>`），行文中首次写全路径、其后用中文短描述指称。规则见知识库 `bg-quarto-conventions-v1`。
- 代码块来源链接嵌进同节导语句子里，不单独成行贴在围栏上方；整行仅为一个链接的「裸链接行」一律改写成含对象与动作的完整句子。代码块标题 `filename` 是短显示名字符串，不写 Markdown 链接。
- 中英文之间保留空格。链接标签两侧的间距按标签内首尾字符决定，标签内不写反引号。
- 正文只保留读者当前动作必需的外链。手册、完整参数列表和上游项目文档在首次需要该资料的任务中就地链接，不设章末集中区（10 章参考资料是唯一的合法停靠位）。

写完章节后用 `run.py check --profile fast` 检查链接与结构。标记边界与间距依据检索：

```powershell
& .agents/skills/governing-agents/scripts/run.ps1 kb-search "行内代码 链接间距" --domain quarto-writing
```

## 文档元素

元素选择服务于结构与可读性，不以装饰为目的。

### 代码与媒体

- 可复制示例使用 `{.语言 filename="标题"}` 属性围栏：命令块写执行位置（如 `WSL Ubuntu（仓库根目录）`），文件内容写真实文件名短名，输出写场景名（如「运行效果」）。标题只声明来源，正文只说明当前动作。
- 同一小节内递进依赖的同源片段（后块直接使用前块已展示的常量、类型或函数，中间只有短导语）先判合并：满足判定就并为一个围栏，块前一句导语交代这组递进定义（对象 + 谁调用），块后用无序列表分项讲注释未覆盖的职责与调用方，摘录仍按源码相对顺序逐字取行。并列契约、被图或独立验证盒子打断、bash 脚本分步不合并。判定四条件与豁免清单见知识库 `bg-qmd-element-cases-v1`。
- 图片提供 Alt 文本和说明。图表标注坐标轴与单位。
- 仓库文件使用可跳转链接。短技术标识使用行内代码。

### 代码与图的桥接

代码块引出图（`{mermaid}` 流程图或 `{python}` 坐标图）时按固定序列组织，图是可选中段，不能替代结论句：

1. 代码块前的引导句交代这段代码解决什么；
2. 代码块；
3. 代码块项目解释：紧跟代码块的无序列表或正文，只补注释未覆盖的工程信息（谁调用、职责边界、与邻块关系）；没有项目解释时整步省略；
4. 桥接句：说明下面的图核对代码已讲清的哪条关系（新信息，不复述引导句与项目解释）；
5. 图（`{mermaid}` 或 `{python}`，含 `fig-cap`）；
6. 图后描述只补图外的新信息或从图带走的结论，再进入下一块；小节以图收尾时，从图带走的结论可并入桥接段，图后不再追加孤句。

项目解释不得插队到图之后：禁止「导语 → 代码 → 图 → 再解释代码项」，图后正文不再回头讲代码块内的对象。代码块与图之间只有空行、或图后不接结论直接进入与图无关的下一块，都视为堆叠；结论已并入桥接段的小节收尾图除外。反例与改写对照见知识库 `bg-qmd-element-cases-v1` 与 `bg-coords-diagram-v1`。

图的放置另有三条边界：

- **一图一事**：一张图只核对一条已讲清的关系。图需要同时表达两条关系时，拆成多张图，或按关系拆成多个 `###`，每节一图。
- **同主题相邻**：代码块与图必须是同一对象的两种呈现。下一块与图主题不同时，先用一句正文收束本对象，再另起 `###`；禁止「代码 A → 一句拐弯 → 图讲 B → 再贴代码 C」的同节混排。
- **图不承载正文未写的新信息**：图中的每个框、箭头或标记都能在图前正文找到对应对象与关系；读者需要新概念才能读懂的图，先在正文补出该概念，再放图。

### Callout 提示框

只用内置 5 类，自定义 `.callout-*` 类会被静默丢弃。语义按读者的动作选择：

| 想表达 | 类型 | 典型内容 |
|---|---|---|
| 解释原理或术语边界 | `note` | 术语卡、为什么这样设计 |
| 更优做法或替代路径 | `tip` | 可选替代、快捷写法 |
| 风险与易错点 | `warning` | 破坏性命令、版本差异 |
| 深入机制 | `important` | 读者可跳过但不影响成功 |
| 严重且不可逆 | `caution` | 数据丢失、需要停手确认 |

带标题的 Callout 使用 `::: {.callout-note title="中文标题"}`，标题由块属性提供，块内不再写 `##` 标题。Callout 放在它所补充的段落或小节内容的最后面，前后各留一个空行；术语卡是唯一就近放置的例外，紧跟术语参与的那段解释之后。必经步骤不进 callout。结果型 Callout 的边界见知识库 `bg-section-focus-density-v1`。

参数解释默认使用短无序列表。Callout 不承载必经命令或构建命令，也不把唯一成功判据写成脱离正文的脚注。

### 可折叠答案

`## 自测问题` 的思考题需要自测时，答案紧跟对应列表项，使用站点级 `.answer` 组件：

```markdown
1. 问题？

   ::: {.answer}
   答案导语（列表型答案先交代对象与顺序）。
   1. 步骤。
   :::
```

- 只有读者可以先自行回答、再核对结论的内容才折叠。定义、命令和必经判据留在正文。
- `.answer` 由 `.agents/skills/writing-quarto/scripts/answer-disclosure.lua` 渲染为默认收起的原生 `details.answer-disclosure`，摘要固定为「查看答案」。正文不手写这段 HTML。
- 答案只使用本章已经讲解的概念，内部不使用 `h1`–`h6`。

### 交叉引用

交叉引用使用真实标题生成的锚点，引用前确认目标页面存在。本项目不手写英文 `{#id}`，标题锚点由中文标题派生；跨章节引用用章节标题链接，不用「第 N 章」。

需要本仓的渲染与链接依据时，检索知识库 `bg-quarto-conventions-v1` 与 `bg-mermaid-conventions-v1`。
