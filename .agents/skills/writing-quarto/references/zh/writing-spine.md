# 写作流程：工序唯一入口

所有写作类任务（写章、润色、增量改规则）先读本文件按写作工序走，禁止跳过写作流程直接通读 references 或知识库。冲突裁决：knowledge 条文 > skill how > cases 对照 > 脚本启发式。

本轮不改写根 `AGENTS.md`；同一步只打开登记的那一个文件和那一个 `##`；本轮已经读过的文件不重复读。

## 写作工序

从定任务到过闸依次走完；后一步发现前一步没做完，退回那一步，不在当前步补结构。每步只打开该步登记的文件与 `##`；执行 how 在 `references/zh/writing-howto.md` 对应节。

| 步骤 | 动作与产出 | 登记的依据与 how |
| --- | --- | --- |
| 1 定任务 | 读者做完能做什么，一条成功路径；语言课禁令、否定式预告、不写「下一节」在此判 | `chapter-writing.md`「叙事范围」；`bg-chapter-structure-v1`「六段块序列」；howto「定任务」 |
| 2 定结构 | 章与节顺序、一节一个结果、标题与正文对齐；标题归并规则见下；二三级正文 token 区间见 `bg-chapter-structure-v1`「分层上限」 | `chapter-writing.md`；`bg-chapter-structure-v1`「标题分层」「分层上限」；`bg-section-density-v1`；`bg-paragraph-craft-v1`「章级」「节内」「小节标题与正文对齐」；howto「定结构」 |
| 3 排列内容块 | 引言、代码或图、块后、Callout 的顺序；一个围栏只放正在讲的那一块（紧邻常量与其直接使用行除外）；未定义名字的调用链整段删除 | 权威是 `bg-qmd-element-cases-v1`「内容块前后的闭环」；`authoring.md`；checklist 见 `bg-paragraph-craft-v1`「块链检查清单」 |
| 4 定段落 | 先确认单位（这一段是散文段、列表项还是表格单元格），再套规则；一段一个对象、段间 given-new、主概念 1–3 个；拆核四步在此，不管句内分句次序 | `bg-paragraph-craft-v1`「段落规则」「拆核四步」「一次对话」「概念负荷」「段间」「段内同义堆叠禁令」；`bg-chinese-quality-v1` 段落级审查 |
| 5 定句子 | 先确认单位（围栏内不是句子，列表项不当散文句改），再套规则；设计说明的分句角色链：事实 → 约束 → 因此选择；对象先行、一句一动作、先条件后结论（含公式讲解）、拉链句判定与三条改写在此；节首与句内代词按「代词不能代替未写出的对象」核对 | `bg-paragraph-craft-v1`「句内骨架」「拉链句」「过简断裂禁令」「罗列短句成段禁令」「代词不能代替未写出的对象」「一次对话」；`bg-chinese-quality-v1`「句序与段落形态」 |
| 6 定用词 | 术语、语域、主动语态、禁用词；不改句序。「由 X 完成」在此改主动句，改完露出第二个核退回定段落 | `bg-terminology-v1`；`bg-chinese-voice-register-v1`；`bg-cpp-chinese-terms-v1`；`verify_content.py` 词表 |
| 7 定版式 | 标点、中英空格、列表还是散文、加粗、导语句数、源文件链接密度；列表是版式选择 | `bg-chinese-quality-v1`「标点与中英混排」；`bg-paragraph-craft-v1`「列表选择」「加粗使用」；`bg-chapter-structure-v1` 导语限额；`bg-qmd-element-cases-v1` |
| 8 对案例 | 只说明某一步的前后对照，标题或首行标明工序；改写不得违反更早的工序 | `bg-chinese-style-cases-v1`（低频章级对照在 `cases/appendix/`） |
| 9 过闸 | `verify_content.py`、`check_zh_lint.py`、`quarto render`、clang-format；只检查，不发明新句，WARN 记台账 | 闸项登记各自守卫的工序，见 `.agents/skills/testing/references/verification-matrix.md` |

三家教材只补层，不新开步骤：learncpp 补章外形（定任务：标题只承诺一件读者做完能做的事，开头写读完能做什么，不可缺少的新概念当场说明），其课末测验对应章末「自测问题」；C++ Primer 补章内顺序（定结构：先用白话列出要做的事，零件讲完再讲调用它们的程序，由易到难，最难的组装放最后），其 Chapter Summary 对应「本章回顾」；cppreference 补单个函数小节的内部顺序（排列内容块：声明、一句行为、实现，示例不出现在行为句之前）。三家都不引进的部分：不设 Defined Terms 式术语表，不把测验拆进各节，章首不列完整类接口。

### 工序分层（增量润色与全章重构共用）

九步的先后不变；增量润色按步走，全章重构按下面三层把该层全部重组：

- **章级（1–2）先定删留，不动句子。** 定任务只写「读者做完能做什么」和必须删的语言课、否定预告；定结构只排 `##` / `###`、常见错误和自测题。自测题在这一步就写成自洽的一问一答，题干写出对象名、不留给定句子再补；不留到定句子再发明。
- **节级（3–4）只拆块和段。** 排列内容块决定引言、围栏、块后、Callout 的顺序，一个围栏只放正在讲的那一块；定段落用拆核四步把一段里的两个对象拆开、删掉换说法的辅句。这一步不改分句次序。
- **句级（5–7）才逐句拆开再写回去。** 定句子对每一句做完再进下一句：一个动作、事实然后约束然后选择、不是拉链句、主语是工程对象；需要拆的拆成两句，需要并的并成一句因果。定用词只换术语和主动语态，不改刚排好的句序；定版式只处理标点、列表、加粗和链接。
- **第 8 步不是再写一遍。** 对案例发生在离开每一步之前：这一步的改写去对照该步的正反例；全章写完后回读，发现违反更早工序就退回那一步。
- **第 9 步一章一闸。** 过闸不发明新句。

### 标题归并（在第 2 步执行）

- 标题只留对象名：先圈出目录里要扫到的对象，删掉指示（这一步、这次）、过程动词（记下、收进、用到）和数量（三种、九个），再检查同一二级下的三级标题句式是否一致；数字与形式见标识 `bg-chapter-structure-v1` 的知识文件「字数硬限」，不双写规则。
- 固定收尾「常见错误」「自测问题」「本章回顾」不合并、不降级；常见错误下面的症状继续用三级标题。
- 任务级二级标题只保留读者能单独做完的一件事。只负责解释下一块代码、命令或图的，降为三级标题；短到没有独立观察步骤的，连三级标题也不留，并进相邻正文。
- 一个任务级二级标题下设三级标题时至少两个；只有一个时并入二级标题正文，或补出同级标题。依据是阮一峰《中文技术文档的写作规范》的标题原则：二级标题是文章的主要部分，三级标题是它下面的步骤；同级标题避免只出现一个。
- 二三级正文 token 区间（单一任务节 200–1200、多任务节每节 400–1200、任务级三级 120–480、症状三级 60–240）的判定数字写在 `bg-chapter-structure-v1`「分层上限」，由 `verify_content.py` 判失败。

注释是同一条工序的支线，不另建中心：`bg-comment-style-v1` 在定句子决定注释回答哪一类问题，在定版式决定行尾还是上方、列宽 100；`bg-google-cpp-style-v1`「行宽 ColumnLimit」只保留为什么是 100，怎么断行指向注释文件。键值配置、过程脚本（`.sh` 与 CMake）和 Python docstring 都走 `bg-comment-style-v1`；段标题与摘录同源走本章工序。改 `.clang-format`、`.clang-tidy`、`.clangd` 这些文件时走 `.agents/skills/cpp-development/references/cpp-spine.md`。

## 增量链（改规则）

1. 查权威矩阵（KNOWLEDGE.md「按任务定点取用」表）→ 只改一个合并后文件的对应 `##`。
2. 新规则必须先标明工序：能放进已有 `##` 就放进去；只有尺度变了（如现在没有的「事实核对」）才允许新开一步。禁止再写一条不标明步骤的禁令，禁止为同一判断新增知识文件。
3. 超 Parent/L2 体量上限时先拆 `##` 再写。
4. 同步更新写作流程 / SKILL / KNOWLEDGE / cases / 闸 / eval。
5. `kb-index` → `kb-check` → `kb-eval`。
