# 中文技术文档写作原则

本文件是所有中文内容的最高优先 how 规则。规则冲突时，以读者能否完成当前任务为准。本仓的语气语域判定（`bg-chinese-voice-register-v1`）、术语与禁用词（`bg-terminology-v1`）、段落与列表细则（`bg-paragraph-list-style-v1`）保留在知识库，本文件只写可执行的通用做法，与知识文件冲突时以知识文件为准。

## 先让新人完成任务

- 开篇说明读者在做什么、完成后能得到什么，不先铺陈历史、架构和完整背景。
- 每页只保留一条成功路径。高级选项、边缘情况和内部实现后置，不能阻塞第一次成功。
- 保留标准术语，但首次出现时用一句白话解释；术语卡用就近的 callout 承载（写法见 `authoring.md`）。缩写先写全称。
- 不假设读者知道工具名、命令参数、目录布局或错误输出代表的含义。

## 句子要短，术语要稳

- 一句话只推进一个动作或结论。超过 40 字且包含多个动作时拆分。
- 操作使用「确认、创建、查看」等动词，不用被动句和名词化表达。
- 同一概念只使用一个称呼。英文标识保持大小写。
- 正文不用分号。连续出现三个「的」时改写。正文不使用破折号夹心解释：解释用冒号引出，或拆成两句。
- 多中心判定口诀：删掉任一分句后句子中心仍然成立，原句就是多中心句，按中心拆成两句；分号不得用来给块前导语挂 cpp-notes 外链；跨仓链默认不写，若保留须工程点后尾置「若要系统阅读…」，禁止「写法依据见」等依据句。
- 相邻句子用因果、承接或对比关系连接，不用同义句重复中心。删掉一句后前后仍然通顺，说明这句只是重复。
- 确认一个中心主题后，用衔接词把相关动作组织成连贯句；禁止把各自成句、互不衔接的罗列式短句机械堆进一段，每句单看成立不等于段落成立（对照见知识库 `bg-chinese-style-cases-v1`「罗列短句成段」）。
- 禁止目录式堆砌：一句话只推进一个结果，章引言与节引言不用顿号串联多个交付物或动作。删改口诀：把清单删掉后读者仍能说出「本章成功判据」，这份清单就应下沉到对应小节；引言只保留唯一结果的承诺，细节交给正文。
- 删除「众所周知」「简单来说」「完全可以」等没有信息的修饰。禁用词以 `scripts/verify_content.py` 词表为准。
- 正文提及枚举类型与成员函数时写源码完整标识符（`GameResult`、`Game::Place`），不设「概念简称」层；架构层名首次出现用一句可观察行为定义；讲读写路径先说屏幕上发生什么，再点名成员，最后一句边界（对照见知识库 `bg-chinese-style-cases-v1`「零基础可懂的读写路径与层名定义」）。
- 禁止接口清单压缩段：公开接口用场景 → 代码 → 块后工程补白；不得把私有成员、成员名单、`const`、`[[nodiscard]]` 压进同一段旁白（对照见同知识库「接口清单压缩段」）。
- 枚举成员的含义写在源码行尾注释里，正文不复述成释义列表或释义段；正文只写谁调用、如何验收、与邻章关系（规则见 `chapter-writing.md`「叙事范围」）。

## 信息按动作排列

每个任务按「目标 → 执行 → 结果 → 必要解释」排列：

1. 先说明这一步要解决什么。
2. 给出最少命令或操作。
3. 给出稳定、可观察的成功结果。
4. 只解释继续操作所需的细节。

失败分支放到「常见错误」。可选说明放到任务末尾，或直接删除。删除后不影响首次成功的内容，不应出现在主线。凑字数句（统计性凑句、导航复述段）一律删除；删除判据见知识库 `bg-paragraph-list-style-v1`。

## 格式要降噪

- 命令、参数、路径、文件名和标识符使用行内代码；Ubuntu、Windows、VS Code 等平台名作普通名词时不加。
- 可复制命令使用指定语言的代码围栏，命令与输出分开。
- 标题和导航不使用行内代码。中英文之间保留空格。
- 列表用于并列或顺序关系。表格只用于比较允许多个属性的内容：同一主题的属性合并成一张表，不按小节拆成多张薄表；只有一两列信息或右侧大量留白时改用句子或列表。
- Callout 只放可跳过的提示，不承载必经步骤和唯一成功判据。

具体元素写法见 `references/quarto/authoring.md`，终端步骤见 `references/quarto/terminal-validation.md`。

## 写完后逐段删除

对每个段落依次检查：

- 删掉后影响当前任务吗？不影响就压缩或删除。
- 段落是否同时承担两个以上动作？是就拆分。
- 同一小节的连续同源代码围栏是否构成递进依赖链（常量 → 类型 → 使用它们的函数）？是就先合并为一个围栏，再润色整链导语与块后列表，不拆成多块；对照见知识库 `bg-chinese-style-cases-v1`「递进片段合并」。
- 段落是否推进了两个互不依赖的并列对象？是就按对象拆段，新段段首补一句衔接；对照见知识库 `bg-chinese-style-cases-v1`「单段混并列对象」。
- 代码块后的段落是否在翻译块内注释？是就删除，只留注释没覆盖的新信息；对照见知识库 `bg-chinese-style-cases-v1`「块后复述注释」。
- 读者能否指出完成后要观察什么？不能就补结果。
- 正文、代码块和回顾是否重复同一句话？重复就只留一处。
- 新术语是否由当前动作自然引出？不是就后置。标题与论据只准使用读者已建立的术语，未建立就删除或下沉到概念建立后的章节（规则见知识库 `bg-paragraph-cohesion-v1`「小节标题与正文对齐」，对照见同库「小节标题抽象与首句无中心」）。
