# Skill: reviewing-code

对提交、改动或指定文件做只读缺陷审查，只报有实质影响的缺陷，不提主观风格琐碎意见。

## 适用场景

- 审查改动、PR 或指定文件的正确性、安全性、现代 C++ 规范符合度与文档契约。
- **不适用**：动手改文件（审查与修改不混做），本次改动之外的历史问题不报。

## 任务路由

| 审查对象 | 读取 |
|---|---|
| 游戏阶段代码与工程 / `.qmd` 正文与排版 | `references/review-checklists.md`（两类都涉及时按需加载，不读无关规则） |

## P0 硬约束

1. 只读：严禁修改文件、提交代码、推送分支。
2. 只报本次改动引入且有据可查的缺陷。能由编译器、sanitizer 或 `run.py build <game>/<stage>`（CTest）拦截的问题，直接指出违规点并引用规则。
3. 每条缺陷必须给位置与可操作建议，按 P0 → P3 排序。无缺陷时输出 `No findings.`。
4. 只有能证明未定义行为、内存破坏或渲染失败的缺陷才定为 P0/P1。

## 工作流程

1. 确认范围（`git status` 或用户指定文件），只读范围内文件与必要上下文。
2. 按路由加载领域规则逐条比对，输出按级排序的缺陷列表，附风险概括与测试建议。

## 输出格式

```text
[P1] 悬挂引用风险 — games/tic-tac-toe/02-board-and-state/tic_tac_toe/src/game_state.cpp:28
一段说明：问题场景、成因与可操作的修复建议。
```

## 完成判据

`[ ]` 每条缺陷都能指向规则出处与具体位置。`[ ]` 未修改任何文件。`[ ]` 结论可直接据此行动。
