# 成段材料收录流程（intake）

用户丢来一段要归档的材料（总结、目录草图，有时夹一条别的任务如修 CI）时，不把整段贴进一个文件，也不照草图新建一套和固定路径冲突的目录。先出落点计划，用户确认后再改文件。

## 步骤

1. 先拆开。归档材料是一件事；修 CI、改游戏、改章节是另一件事，分开列，不写进同一个文件。
2. 每条材料只选一个落点。已有同一 `kb_id` 或同一主题文件时，改那一处，不新建第二份。
   - 删掉就会每轮做错：根 `AGENTS.md` 加一条短约束。长说明不进这个文件。
   - 现在是什么、现在怎么做：`.agents/context/` 里已有的那份（项目、架构、工具链、术语、对应规范）。
   - 步骤、命令、完成判据：已有技能的 `references/`。没有独立工序时不新建技能。
   - 为什么否决、和谁对照过：`knowledge/` 的取舍短文。
   - 正反例：`knowledge/` 的 `cases/`。
   - 过去做错过、下次要避开：`memory/`。
   - 某一次失败的症状、根因和修复：`incidents/`，并在 `INDEX.md` 登记。
   - 给读者看的说明：`content/**/*.qmd`，不进 `.agents`。
   - 井字棋工程事实只进 cpp-board-games；语言机制只进 cpp-notes。
3. 草图若要求把 `AGENTS.md`、`skills/` 或 `mcp/server.py` 搬进 context，计划里写明不搬，并给出上面的替代落点。
4. 计划只包含四列信息：原句要点、目标路径、动作（补一节、改已有节、或不收）、会同时瘦掉的重复段落。不在这一步改文件。
5. 用户确认之后才写。写完更新 `context/README.md` 或 `KNOWLEDGE.md` 里的那一行路由；新 `kb_id` 才补 `eval_set.py`。然后跑本仓 `check --profile fast`；动了检索正文再 `kb-index`、`kb-check`、`kb-eval`。

未确认的落点计划不算已归档。确认后仍遵守一条规则一个路径，不用这次收录把条文再复制回 `AGENTS.md` 或技能清单。
