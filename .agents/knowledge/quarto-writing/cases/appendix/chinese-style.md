# 中文写作的章级定稿对照（附录）

本文件是低频章级对照附录，不进检索索引与评测；仅人审或用户点名时读。规则与通用对照见标识 `bg-chinese-style-cases-v1` 的知识文件。

## 操作节删除离题辩白

以 02 章运行一键脚本节为对照。脚本节标题是「怎么跑、看到什么」，嵌在块后的「幂等 / 跳过 / 配置漂移」长论与标题无关，新人缺语境；删除后主线（执行脚本 → 核对输出）仍闭合，「必须重跑配置」已由「修改 CMakeLists 后行为没变」排查节与脚本注释覆盖：

```text
不佳（操作节内的工程取舍长论）：
脚本每次都重新执行配置，而不是判断 build/ 已存在就跳过。配置是幂等的，重复执行结果一致，只花一两秒；编译仍由 Ninja 增量进行。跳过式写法反而危险：改动的配置参数进不了旧的缓存，产生难以察觉的配置漂移，排错成本远高于省下的时间。

改写（整段删除；代码注释保留一行意图，排查节保留归属）：
（块后直接进入下一小节「核对输出定位卡点」。）
```

判定信号：段落回答的是「为什么这样设计」而不是「这一步做什么、看到什么算成功」；删掉后首次执行不受影响。

## 作者信息与读者路径分开

作者如何筛选目录、安排写作不属于读者路径。正文用一句话同时交代对象和动作，不把整理过程写进章节。

## 密集引言拆分

多个独立概念压进一段时拆开，但拆的形态由引言规范收敛（规则见标识 `bg-chapter-structure-v1` 的知识文件）：任务概览并入承接句，正文小节承担展开，预览列表不再使用。以 02 章引言为对照：

```text
不佳（旧形态，一段七概念 + 预览列表）：第 1 章界定了……本章开始第一个实现切片：……最小链路完整走通——CMake 配置 → 编译 → CTest 测试 → 运行程序。链路一旦打通……
1. **CMake 配置**：…… 2. **编译**：…… 3. **CTest 测试**：…… 4. **运行程序**：……
接下来按链路顺序展开：……

改写（承接段一句话概览，无列表）：先看清工程确认了工具、项目内容与分层实现。本章不写游戏逻辑，只在最小工程目录上把完整流程执行一遍；GoogleTest 等第三方框架留到棋盘与状态出现真实规则后再引入。
```

拆分信号：原段出现两处以上括号补充和破折号、同时回答「做什么、在哪、不做什么、按什么顺序读」四个问题。改写后四问分别由承接句、仓库链接、范围句和正文小节顺序回答，不再单设预览。

## 冒烟测试退出码与输出收束

以 02 章自测「为什么还要用 PASS_REGULAR_EXPRESSION」为对照。先写清退出码证明什么、不证明什么，再写输出断言拦住什么，最后一句才落到两条一起构成冒烟；禁止口号句悬在段末、前文未铺垫：

```text
不佳（口号悬尾，前文未铺垫“两条一起”）：
返回 0 只证明进程正常退出，不能证明程序行为正确。断言输出文本可以拦住“返回 0 但输出异常”的假成功，让冒烟测试同时覆盖退出码和基本行为。

改写（引言 → 列表 → 收束）：
退出码 0 只说明进程正常结束。

- 它不能证明标准输出符合约定。
- PASS_REGULAR_EXPRESSION 拦住“返回 0 但输出异常”的假成功。

退出码与输出断言同时满足，才算本章的冒烟测试通过。
```

判定信号：段末出现「让……同时覆盖……」式口号，而正文未先分清两条机制各自证明什么。

## 列表项长度均衡定稿

以 01 章两个引导词列表与 02 章目录职责列表为对照。同列各项字数相差两倍以上时扫读节奏断裂：01 章「行列号」项约 55 字而「棋盘格子」项约 22 字；02 章「终端程序」项约 60 字，夹带「更换终端界面时改的是这个目录，井字棋动态库保持原样」的分层长论。改写保留各引导词的完整句，删去可由他处覆盖的论据（分层细节由 02 章自测「为什么终端程序可以使用井字棋动态库」的答案承载），把各项收进同一字数带。

判定信号：同一列表内最长项与最短项相差约一倍以上；长项的第二句是删掉后主线仍闭合的理由句。

## 下一章预告归位定稿

以 03 章「读写棋盘格子」收尾为对照。改稿前收尾第二句写「`Game` 在下一章决定轮到谁落子、何时获胜和何时平局」，与章末本章回顾的预告重复（规则见标识 `bg-paragraph-craft-v1` 的知识文件「句子规则」）。改写后收尾只留「调用方只给出坐标和要写入的状态，数组和下标换算都留在 `Board` 私有段。`Board` 到此完成棋盘格子的全部读写」，下一章预告由本章回顾独自承担。

04 章引言同类：改稿前引言末句写「终端输入输出留到构建、测试并运行终端对局（`05-terminal-play.qmd`）」，整句删除——引言只写本章要交出的对象，后章预告由本章回顾独自承担。

判定信号：章引言或任务节收尾出现「留到」「在下一章」式后章指向，或下一章才展开的成员名；同一预告在收尾与回顾两处出现。

## 04–07 章同类归位定稿

以 04 章判定节与四章常见错误小节为对照，一次归位四类：结果映射列表不混测试覆盖——04 章「得出胜负与平局」前两项是 `GameResult` 映射，第三项 `GameTest` 覆盖范围移成图后单句，原「这一局面在 `GameTest` 里记为 X 获胜」与图注重复，一并替换；常见错误小节只有导语句加单项列表时整节折成一句（规则见标识 `bg-paragraph-craft-v1` 的知识文件「列表选择」，04/05/06/07 共五处）；列表项里不混另一类观察——06 章难度列表第 3 项第二句「双方都用它从空棋盘下完，结果是平局」与 `OpponentTest` 句重复，删去后三项回到纯难度定义；裸文件名首次点名挂 blob 链接——05/06 章的 `board.h`、`game.h` 与两处 `build-and-run.sh`（对照见标识 `bg-chinese-style-cases-v1` 的知识文件「口语开场与规划套话」）。

判定信号：结果映射列表里出现测试覆盖项；### 小节正文只有导语加一个列表项；列表项的第二句是别处已有的观察；正文反引号源文件名同句无链接。
