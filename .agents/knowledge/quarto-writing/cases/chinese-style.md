# 中文技术写作的句段与措辞案例

依据 cpp-notes 仓库 `chinese-style-cases.md` 适配本仓库，保存段落、句子和措辞的正反对照。低频的章级定稿对照在 `appendix/chinese-style.md`（不进检索索引，仅人审时读）。

## 正确形态正例

不需要改写的正确形态长这样，写正文时可直接对照：

```text
正确（段落导语：工程语境 + 一句判断依据）：
这段构建规则定义可执行目标 app：先规定产物目录，再列出源文件，最后声明 C++20。
三条命令各管一步，读者按顺序核对即可。

正确（收束句：指向可观察结果）：
看到 Hello, World! 后，就完成了本章的实践目标。

正确（排查句：可核对的排查范围）：
第一次配置、编译、测试失败时，排查范围限定在工具链与构建规则；工程不含游戏逻辑。
```

正例的判定条件：主语是工程对象；一句话一件事；验收句指向能看到的结果而不是宣告章节状态。

## 长句与连接关系

连接词必须表达真实因果、时序、转折或条件。一个句子出现三个以上动作、多个「并且」或多个括号时拆分，并保留明确主语：

```text
不佳：完成 A 后通过 B 使用 C，并根据 D 判断 E，最后处理 F。
改写：完成 A。接着使用 B 执行 C。根据 D 检查结果，满足条件后处理 F。
```

需要一句话交代多个条件与同一结果的对应关系时保留长句，拆开反而让读者在短句间拼接。

## 分号与句长

```text
不佳：先执行 A；再执行 B；完成后检查 C，不通过时回到上一步。
改写：执行 A，再执行 B。完成后检查 C。不通过时回到上一步。
```

「两个并列主谓分句可用分号并列」的旧豁免已废除：凡是删掉任一分句中心仍成立的分号句，都按多中心句或拉链句改写（对照见下文「拉链句」与「导语多中心与分号挂外链」）；指令链与「冒号后堆叠分号解释」仍按上文与对应案例改写（`verify_content.py` 的分号检查不再豁免行内代码主语）。

## 拉链句

一句话把两组对象两两配对，删掉任一配对、剩下的仍能单独成立，原句就是拉链句：读者要按顺序把左组一一配到右组，且两个配对共用同一个判据（判定与三条改写见标识 `bg-paragraph-craft-v1` 的知识文件「拉链句」；工序链、同物两处与回顾不按拉链判）。以 03 章章首改稿前与 04 章改稿前为对照：

```text
不佳（一句两组配对：「棋盘格子在哪、上面是什么」分别交给两个类型；还提前点了后文才定义的类型名，并用「写进代码时」元叙述）：
在[确定对局规则](01-rules.qmd)的画面里，玩家用行列数字选中棋盘格子，落下的棋子显示为 X 或 O。写进代码时先把两类信息分开，棋盘格子在哪、上面是什么，分别交给 `CellPosition` 和 `CellState`。

改写（两条改写都触发时先「推迟」：章首只留顺序的两句白话，不点类型名；类型名留在各自小节的块前导语）：
在[确定对局规则](01-rules.qmd)的画面里，玩家用行列数字选中一个棋盘格子。接着再记这个格子上显示的棋子。
```

```text
不佳（「各说一层」把 PlaceResult 与 GameResult 的分工配进一句，删掉任一配对另一照常成立）：
落子结果和对局结果各说一层：`PlaceResult` 回答这一次落子写进棋盘没有，`GameResult` 回答整局对局进行到了哪一步。

改写（两个类型已在前文各配导语和围栏，分工不再复述，直接进入下一块）：
（整段删除。下一块改为一句桥接：这些类型由类 `Game` 的四个数据成员使用，都声明在 `game.h` 的 `private:` 下。）
```

判定信号：一句里两组对象两两配对、删任一配对仍成立；「分别交给」「各说一层」「分别是」出现在同一句里连接两组对象。改写顺序：推迟（只留顺序白话，类型名下放）→ 拆句（后句用「因此 / 所以 / 接着」接前句对象）→ 一项一行（三项以上进列表）。`check_zh_lint.py` 对读者正文的「分别交给」「各说一层」硬拦。

## 罗列短句成段

以 01 章「观察一局对局」改稿前为对照。三个短句各自成立、句间无衔接，读起来像清单；分号还把显示棋盘与拒绝非法输入两件事串进一句（规则见标识 `bg-paragraph-craft-v1` 的知识文件「罗列短句成段禁令」）：

```text
不佳（三个独立短句堆成一段，句间无衔接；分号串两个中心）：
两名玩家轮流在 3×3 棋盘上落子。程序显示棋盘并提示下一位玩家；输入越界、占用或格式错误时说明原因并保持棋盘不变。

改写（一个中心主题，衔接词组织成连贯句，分号改写）：
两名玩家轮流在 3×3 棋盘上落子：程序每一轮都先显示棋盘，再提示接下来轮到谁。行列越界、格子已被占用或格式错误时，程序会说明原因并保持棋盘不变，要求重新输入。
```

判定信号：段内句子逐句可删、互不引用；句间没有承接、因果或时序词；删掉分号后的任一分句中心仍成立。真正并列、需要扫读的项改用列表，不做伪连贯。

## 过简断裂段

以 04 章「查看对局接口」节导语改稿前为对照。与「罗列短句成段」的分工：那条打句号清单，本条打逗号切断与过简两句各丢一个事实——每截单看都合法，段却不成篇，读者要自己补「因为／所以／其中」（规则见标识 `bg-paragraph-craft-v1` 的知识文件「过简断裂禁令」与「概念负荷」）：

```text
不佳（四截并列：对象 → 文件位置 → 入口个数 → 私有存储，截截换新主语、新事实）：
一局对局落在类 `Game` 上，定义在 game.h 里。`public:` 下留五个入口，棋盘存储收在对象内部：

改写（主概念只留类 Game；文件与「对外入口／内部棋盘」作次要展开，去掉「五个」统计）：
一局对局由类 `Game` 编排。它把棋盘和对局进度收在对象内部，对外只露出查询与落子入口；声明在 game.h。
```

```text
不佳（opponent.h 不做的事与 ChooseMove 的行为两截并列，无回指）：
opponent.h 不打印棋盘，也不读取键盘。`ChooseMove` 读当前对局，返回当前玩家的一次合法 `Move`。

改写（先对象后行为，第二句用「它」接住 opponent.h）：
opponent.h 不打印棋盘，也不读取键盘。它只声明落子选择：`ChooseMove` 读当前对局，返回当前玩家的一次合法 `Move`。
```

判定信号：逗号、句号后的分句引入新主语或新的行内代码标识，且无回指词、无承接词；删掉该分句后上下文照样成立，说明它只是被并列甩出的另一截。改写时收敛主概念，用给定信息衔接次要展开；时序句「进入目录，执行入口」合法（后一分句接住前一分句的动作）。

opponent.h 那组的改写只解决过简断裂；定稿进一步把「不打印、不读取」的否定边界让给常见错误节，正文只写「opponent.h 只声明落子选择：…」（否定式预告见标识 `bg-paragraph-craft-v1` 的知识文件「句子规则」）。

## 自然段多中心未拆

以 03 章无标题引言改稿前为对照。一段同时承担承接上一章、交付物清单、源文件位置与摘录声明四件事，第二句还用顿号串四个交付物。章引言的形态契约（标识 `bg-chapter-structure-v1`）已改为「单段 ± 列表」：多中心时并段或改列表，禁止拆成两个散文段（拆段触发表见标识 `bg-paragraph-craft-v1` 的知识文件「段落规则」）：

```text
不佳（一段四职责，顿号串四个交付物；拆成三个散文段同样违规）：
[对应工程目录](…)已经指出井字棋动态库的头文件位置。这一章只处理棋盘：棋盘格子如何定位、状态如何保存、下标如何换算，以及无效访问如何拒绝。本章的代码写在头文件 board.h 和源文件 board.cpp 里。本章摘录源码服务于讲解，片段不保证与源文件逐字一致，也不等于文件内顺序。

改写（单段：承接 + 本章交付 + 源文件位置嵌在段末句；摘录声明整句删除）：
[对应工程目录](…)已经指出井字棋动态库的头文件位置。这一章实现可以检查坐标的棋盘读写，接口与实现分别在头文件 board.h 和源文件 board.cpp 里。
```

判定信号：一段内出现「承接 + 清单 + 位置 + 声明」四项中的两项以上；章引言用顿号串三个以上交付物；章引言出现两个散文自然段（首个 `##` 前两个非列表段落块）；「本章摘录源码服务于讲解」「片段不保证与源文件逐字一致」「不等于文件内顺序」等摘录免责句出现在读者正文。`check_zh_lint.py` 对免责句硬拦，`verify_content.py` 对两个散文段引言判失败。

## 对局交流不绑定媒介与行为刚性表述

以 01 章观察一局对局节改稿前为对照。把交流绑定到具体媒介、把行为写成刚性属性，都会在后续编号目录更换界面或引入协议时与前面冲突（禁用与替换见标识 `bg-terminology-v1` 的知识文件）：

```text
不佳（媒介绝对化，「只发生在」把对局交流写死在终端）：
一局对局的交流只发生在终端上：玩家输入行列，程序打印棋盘和结果。

改写（写交流的形态，不绑定媒介）：
一局对局通过文本交流完成：玩家输入行列，程序打印棋盘和结果。
```

```text
不佳（「固定」落在程序行为上，读作硬编码）：
对局中的每一步回应和结束判定都是固定的：

改写（行为列举导语直接点名列表内容，与章 title 对齐）：
两名玩家轮流在 3×3 棋盘上落子，每一次输入，程序都按下面四项行为回应：
```

```text
不佳（「固定」落在章叙述上，读作把约定硬加给读者）：
这一章只固定一局井字棋要做什么：玩家怎么落子、输入不合法时怎么处理、对局什么时候结束。具体实现不在这一章展开。

改写（章确定约定用「确定」；收尾否定句删除，「只」已表边界）：
这一章只确定一局井字棋要做什么：玩家怎么落子、输入不合法时怎么处理、对局什么时候结束。
```

判定信号：媒介名词（终端、协议、界面）出现在「只」「都」「总」等全称限定里修饰对局交流本身；或出现「固定」式表述——章叙述、程序行为与不变量一律停用「固定」，分别改写为「确定」、点名行为清单的列举导语与直陈事实（「编译期就是 9 格」「长度不变的 `std::array`」）。「只发生在」仍可用于局部实现事实（换算只发生在 `Board` 内部、写入只发生在 `Place`）。抽象指称的铺垫要求见下一案例。

## 无铺垫的规则指称

以 01 章明确对局行为节改稿前为对照。规则本体尚未给出就指称「同一套规则」，读者不知道「同一套」对着什么、规则里有什么；抽象指称必须落在读者已经看得见的对象上：

```text
不佳（规则未给出先指称，句子顺序也把交流形态放在对局构成之前）：
一局对局通过文本交流完成：玩家输入行列，程序打印棋盘和结果。两名玩家轮流在 3×3 棋盘上落子，程序的每一步回应都遵循同一套规则：

改写（先对局构成、再交流形态，导语直接点名下面的四项行为）：
两名玩家轮流在 3×3 棋盘上落子，一局对局通过文本交流完成：玩家输入行列，程序打印棋盘和结果。每一次输入，程序都按下面四项行为回应：
```

判定信号：句中出现「同一套」「这套」「以下规则」等指称，而所指对象在前文尚未出现 → 先给出对象再指称，或直接点名列表内容。

## 角色总述段

以 02 章查看井字棋工程目录节改稿前为对照。总述句只给目录派角色（「承担源码职责」「说明职责」），不介绍目录里有什么，读者拿到的是名头不是内容；导语直接点名列表将展开的信息维度：

```text
不佳（三处都在派角色：列表导语、build/ 排除句与树引出句都挂在「职责」上）：
井字棋动态库、终端程序和测试目录分别承担源码职责。……构建过程生成的 `build/` 目录不属于源码职责，里面存放可执行文件与动态库文件。目录和文件在目录树中的位置如下，每行的行尾注释说明职责：

改写（导语引出列表；四个目录含 `build/` 一次列全，列表后不再补段）：
井字棋工程有四个目录：……- **构建产物**：`build/` 目录由构建过程生成，存放可执行文件与动态库文件。……目录和文件的位置如下，每行的行尾注释说明这一行是什么：
```

判定信号：正文出现「职责」「负责」「承担」等角色指称或角色动词（词表硬闸见 `verify_content.py` 的 FORBIDDEN_TERMS）；导语只派角色不预告列表内容；并列成员（含 `build/` 这类生成物）不在同一列表列全、列表后另起段落补列成员 → 改为点名内容维度的引出句，成员一次列全，角色信息由列表项的具体内容承载。

## 块后并列事实段拆引导词列表

以 01 章查看终局输出节改稿前为对照。块后一段串起三个以上并列区域的事实（版式、显示规则、结果行），句句完整却仍是多中心段，各项对应输出的哪一部分全靠读者自补；三项以上优先成列表（规则见标识 `bg-paragraph-craft-v1` 的知识文件「列表选择」）：

```text
不佳（块后一段四句各讲一个区域，顺序与对应关系全靠读者自补）：
行列号印在棋盘上，和玩家输入的数字同一套：列号 `0`、`1`、`2` 排在棋盘上方，分别对准三个棋盘格子的中心，行号写在左边框的左侧。玩家按棋盘上印的数字输入行列，无需换算。空着的棋盘格子显示为框里的空位，已落子的棋盘格子显示 X 或 O。末行的 `对局结果：X 获胜` 报告对局结果，平局与 O 获胜也用这一行显示。

改写（一句引言说出阅读动作，引导词列表按输出阅读顺序排列）：
从上往下读这段画面，依次会看到三处信息：

- **行列标记**：列号排在棋盘上方，行号写在左边框左侧，和玩家输入的数字同一套。
- **棋盘格子**：空格子显示为框里的空位，落子后格子里显示对应的 X 或 O。
- **结果提示**：末行的 `对局结果：X 获胜` 报告获胜方，平局与 O 获胜也用这一行显示。
```

判定信号：块后一段出现三个以上句号句、各句对象可与并列区域一一对应、删任一句其余仍成立 → 拆引导词列表并按阅读顺序排列；引导词取输出中的区域名。两项且能写进一句的保留正文。

## 列表字数带失衡

同列各项字数相差两倍以上或引导词相差 4 字以上时，扫读节奏断裂（计量口径见标识 `bg-paragraph-craft-v1` 的知识文件「列表选择」）。以 03 章失败策略列表改稿前为对照：

```text
不佳（引导词长度差 6 字，长项夹带对局频次旁白）：
- **出界坐标**：说明调用方算错了行列，没有可返回的棋盘格子，`GetCellState` 直接抛出 `std::out_of_range`。
- **目标棋盘格子已被占用**：在对局里随时会发生，`PlacePiece` 返回 `false`，棋盘保持不变，调用方另选棋盘格子就行。

改写（引导词收进同一字数带，删去可由正文覆盖的频次旁白）：
- **出界坐标**：说明调用方算错了行列，没有可返回的棋盘格子，`GetCellState` 直接抛出 `std::out_of_range`。
- **棋盘格子被占用**：`PlacePiece` 返回 `false`，棋盘保持不变，调用方另选棋盘格子就行。
```

判定信号：同一列表内最长项冒号后字数 ≥ 最短项 × 2，或引导词相差 ≥ 4；长项的第二句删掉后主线仍闭合。章级定稿对照见标识 `bg-chinese-style-cases-appendix-v1` 的知识文件「列表项长度均衡定稿」。

## 输出引言的结构元词

以 01 章查看终局输出节二轮改稿前为对照。引言向读者描述输出文本自身的结构分类，读者要先换算一遍才知道看什么；引言直接说出阅读动作与关注点，结构与顺序交给随后的引导词列表呈现：

```text
不佳（引言给输出贴结构元标签，「并列」描述的是文本而非棋盘）：
这段输出从上到下包含三个并列部分：

改写（说出阅读动作与关注点，三项由引导词列表承接）：
阅读这段画面时，可以依次关注三处：
```

**定结构（04 章「记下对局数据」下两个三级标题）：**

```text
不佳（「记下」是过程动词，「这一步」「用到的」是指示与关系，对象「类型」被挤到末尾；「收进这一局」同样只留下「局」这个对象）：
### 记下这一步用到的类型
### 收进这一局

改写（标题只留对象名；「落子类型」会漏掉整局结果，四个类型合称「对局类型」，`Game` 的四个数据成员合称「对局成员」）：
### 对局类型
### 对局成员
```

判定信号：标题字数合规，但删掉指示（这一步、这次）、过程动词（记下、收进、用到）后对象才露出来；同一二级下的三级标题一半是动宾、一半是名词。
