# 章节标题命名与字数硬限

标题二选一与层级约定的通用 how 见 `writing-quarto` 技能 `.agents/skills/writing-quarto/references/quarto/basics.md`；本文件保留本仓字数建议与反例（依据 cpp-notes 实测标题风格，经用户确认）。

## 字数硬限

| 层级 | 长度 | 形式 |
| --- | --- | --- |
| YAML `title` | 6-12 个汉字 | 动词短语，优先「动作 + 对象（+ 结果）」 |
| `##` 二级标题 | 2-10 个汉字 | 动词短语 |
| `###` 三级标题 | 2-12 个汉字 | 动词短语或症状句 |

## 形式规则

- 一律**不加冒号、破折号、括号补充说明**；并列结构可用顿号或逗号连接（如「区分声明、初始化与赋值」）。
- 不堆「教程」「详解」「学习」「验证：」等泛化或解释性后缀；标题让读者预先知道这一页/节要完成什么，而不是只知道宽泛主题。
- 标题与导航不使用行内代码（`CMakeLists.txt` 这类名字不进标题；标题写「构建规则」「一键脚本」等表达）。
- 标题只用读者此刻已认识的词或字面自明的词，不使用正文之后才解释的术语（统称禁用清单见标识 `bg-terminology-v1` 的知识文件）。
- 固定收尾节名固定复用：`常见错误`、`自测问题`、`本章回顾`。
- 英文文件名（kebab-case）承担稳定路径职责，中文 title 承担理解职责，两者不必逐字翻译。
- 例外：游戏落地页（`_quarto.yml` 中 part 引用的 index.qmd）title 即游戏名（如「井字棋」），不受 6-12 汉字硬限；副题信息放 description 与落地页引言，后续其他游戏同样处理。

## 反例与改写

| 不佳 | 改写 | 原因 |
| --- | --- | --- |
| `工具链验证：从配置到运行` | `配置并运行最小工程` | 冒号后缀解释、动词不前置 |
| `构建定义：CMake 与 CTest` | `编写构建规则` | 冒号 + 专名堆叠 |
| `一键验证：build-and-run.sh` | `构建并运行` | 文件名进标题 |
| `认识阶段目录` | `查看工程包含的文件` | 未定义统称进标题 |
| `读懂探针源码` | `理解最小程序源码` | 术语黑话进标题；「读懂」改中性「理解」 |

## 命名检查

改 title 不改文件名，除非主题边界或页面职责变化；改动后 `quarto render` 检查右侧目录与书内导航显示。
