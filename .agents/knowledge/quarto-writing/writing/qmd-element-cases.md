# Quarto 教学元素与衔接案例

元素语法与选择的通用 how 见 `writing-quarto` 技能 `.agents/skills/writing-quarto/references/quarto/authoring.md`；本文件保留本仓片段标注、表格、Callout 与命令讲解细则，供编写和评审章节正文时对照。

## 代码块 filename 标注

来源文件、执行位置、输出场景写在代码块标题里，正文不重复「下面是 xxx 的源码/一段命令」这类视觉上已存在的信息。

**片段优先**：每个 `##`（或 `###`）只展示正式代码里与本节任务最相关的一块并精讲，默认内联摘录，不用 include 拷贝整个文件；紧邻常量与其直接使用行合成的单围栏算「一块」（判定见下文「内容块前后的闭环」）：

````markdown
```{.cpp filename="main.cpp"}
#include <iostream>

int main() {
 std::cout << "Hello, World!\n";
 return 0;
}
```
````

- 片段必须逐字摘自源文件，禁止改写、合并或重排源代码行；注释与空行可以省略，省略处直接省略，不写任何标记行。
- **filename 一律短显示名**：只写 `main.cpp`、`CMakeLists.txt`、`build-and-run.sh`、`01-cli-game/` 这类短名；禁止把 `games/...` 或 `shared/...` 深层路径塞进标题栏。完整位置由章引言的 GitHub 链接和目录树提供；`verify_content.py` 用本章内、代码块之前 basename 匹配的最近一条 blob 链接解析真实路径再做片段核对。
- **filename 不写链接**：`filename="..."` 是纯文本短名，禁止塞 Markdown 链接；`resolve_fragment_source` 的解析只认正文句子里的链接，标题栏写链接既渲染不出可点样式，也会被 `verify_content.py` 判失败。
- **blob 链接嵌进导语句**：GitHub blob 链接写在同节导语的完整句子里（正例：「apps/CMakeLists.txt 用一行目标属性固定运行时库查找」，其中文件名是 GitHub 链接的锚文本），禁止整行仅为链接单独成行贴在代码围栏上方（可夹空行，`verify_content.py` 判失败）。悬空的裸链接行既不像正文也不像说明，读者扫读时只剩一个锚点。
- **摘录链接每章每条仓库路径至多一条**：章引言是全章链接位，首次点名源文件并挂链接（如「声明在头文件 `game.h`，实现在源文件 `game.cpp`」，这两个名字是该章仅有的源文件链接）；后文和各节导语改成行内代码，不再包 `[]()`，导语讲块里要看的标识符；同一章摘录另一阶段目录的同名文件时，在切换处再挂一条不同 URL（对照见标识 `bg-chinese-style-cases-v1` 的知识文件「摘录链接密度」；`verify_content.py` 对同章同 URL 重复判失败）。本条挂在写作工序的定版式。
- 片段内注释硬限：每处实现注释（`//` 或 `#`）不超过 2 行、单行不超过 100 列（与源文件 `ColumnLimit: 100` 同一口径；正文散文的 40 字限不套到代码注释），只写这段代码做什么；CMake/Shell 等命令型片段每条命令保留一行意图注释。Doxygen `///` 声明块（概述、空 `///` 与细节）是声明骨架的一部分，摘录随源保留，不受此限。命名惯例、官方建议、未来演化等规范说理一律不进代码块；术语卡和可跳过的操作提醒可以进 callout，注释怎么写、行尾先写什么、`///` 与 `@` 标签怎么分工只留在 `.agents`，面向作者的进知识文件。
- 首讲某段源码的章节不省略源码既有的职责注释：注释是读者读到的第一层讲解；「注释与空行可以省略」只服务后续章节复现已见代码。源码缺注释先按标识 `bg-comment-style-v1` 的知识文件补注释，摘录逐字继承；自明成员按该规范不注，不因「全部注释」补自明行。
- 讲解段只解释片段中实际出现的代码；片段没有展示的内容要么补进片段、要么进 callout，不在正文列表里讲代码外面的东西。
- include 短代码降级为可选手段：仅用于确实需要完整展示且很短的文件，并仍须包在带语言标注的围栏代码块内（包裹规则见标识 `bg-quarto-conventions-v1` 的知识文件）。
- 手动命令块标注执行位置，如 `filename="WSL Ubuntu（仓库根目录）"`。
- 输出效果类代码块（运行效果、预期输出）filename 只写场景名（如「运行效果」）；终端样式、颜色等展示细节写进正文，不进 filename。输出摘录用单独一行 `...` 表示省略的工具输出，与源码片段的省略是两回事。

## 代码块门槛

不是每段代码都值得出围栏。**值得出围栏**：类型布局（常量、枚举、结构体、类的声明）、多步或非显然的控制流、需要与图核对的公式实现，且块前有工程动机导语。

**禁止出围栏**：

- 单次比较或直接 `return` 的平凡实现（判例：`IsValidPosition` 的两行 `return` 比较）——改写入口列表 + 失败策略列表，对照见标识 `bg-chinese-style-cases-v1` 的知识文件「过简实现围栏」。
- 仅为证明「源码有此函数」而贴出的实现。
- 打断小节中心的硬插块。

## 类与多函数摘录的垂直空白

摘录 `class` 或多函数片段时**保留**源码中函数之间的空行，禁止为省行数坍缩成函数注释贴着下一声明；省略部分成员时，被保留的相邻函数之间仍空 1 行；同一 access 段内最后一组数据成员与函数之间空 1 行，数据成员组内不空行（规则与矩阵见标识 `bg-comment-style-v1` 的知识文件「类声明垂直空白」）。与「逐字摘录」冲突时以源码空白为准：教学缩略可删成员，不可删「函数间距」惯例。

## 内容块前后的闭环

一个段落只推进一个对象。小节内出现代码块、列表或表格时，按「引言 → 块 → 结尾（可选）→ Callout（可选）」组织：块前用一句完整导语交代为什么看它（对象、谁调用、做什么）——对象写成读者要在块内观察的代码标识符（常量、类型、函数名），只报出处、不点名块内对象的「X 都定义在 board.h 里：」不算导语，读者对不上句中概念与围栏里的名字（对照见标识 `bg-chinese-style-cases-v1` 的知识文件「摘录导语只报出处」）；点名也不得退化为「`X` 做A、`Y` 做B」式的逐条释义，对象要组织进为什么看它的句子里（对照见标识 `bg-chinese-style-cases-v1` 的知识文件「逐条释义代替动机」）；块后只在有注释未覆盖的新信息时写一句；引言写判断依据，不写「如下：」式的空引导（GitHub 风格指南同款要求：解释文字放在代码块前面，而不是塞进代码注释）。导语预告的对象本体必须出现在导语句里，不得隔着代码块在块后才给出；算式不是例外：程序里的算式就是围栏里与源码相同的那一行（如 `return` 行），导语只交代对象与出处，读者正文不另排数学模式（禁公式项列表，对照见标识 `bg-chinese-style-cases-v1` 的知识文件「公式与换算讲解段」）。

一个函数小节内部按「声明、一句行为、实现」排列，示例不出现在行为句之前；同一小节出现多个围栏时按阅读顺序排，读者要跟着读懂的行内代码标识符，其行为必须已经出现过——上一章、上文，或同一小节里紧挨着的声明和一句行为。编号步骤、节首概览或章引言用后文才定义的名字串起一条必须看懂的过程的，整段删除，不改写后留在原位；调用方的实现里第一次见到被调用函数、而该函数要到后面小节才讲的，调整顺序；点名后文章节的函数而那一章并不讲解它的，删掉也不补进那一章。允许：用读者已认识的词预告本节要做的事；同一小节内声明和一句行为紧挨代码；上一章已经讲过的名字。

同一 `##`/`###` 内 ≥2 个代码围栏时，先看是否是紧邻常量与其直接使用行：常量紧接着被下一行使用时，可放在同一个围栏。类型定义和后一步使用它的函数是两步，即使函数用到该类型也分成两块——一个围栏只放正在讲的那一个声明或函数，不把整份头文件、整份类或整条调用链贴进同一个围栏；后一个函数的函数体里可以调用已经讲过的名字，但不把那些函数的实现再贴一遍。每块前一句导语；`{python}` / `{mermaid}` 图或独立验证盒子打断处保持拆块。旧口径「同一小节递进片段必须合并为一个围栏」收窄到此：只有常量紧接着被下一行使用时才放在同一围栏。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「递进片段合并」。

每个拆开的围栏都用默认形态「一句导语 → 围栏 →（可选一句桥到下一块或图）」；禁止块前半句、块后再挂多行自然段讲同一对象。可合并的块前与块后并成块前一句；简洁边界仍适用（标识 `bg-paragraph-craft-v1`）。细则与对照见标识 `bg-paragraph-craft-v1`、`bg-chinese-style-cases-v1`「多代码块一句导语」。

以代码块为中段，导语讲工程语境（这段代码为什么存在、为什么此刻看它）；若有块后句，只讲注释没覆盖的新工程关系。语法细节不逐行展开。导语与块后都禁止关键字释义当开场：不写「X 是 `inline constexpr` 常量」「用 `enum class` 表达」「用有符号整型承载」「坐标字段为什么选定宽有符号」式语言课或选型旁白（除 01 设计章外工程 qmd 禁选型外链），改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「语言课旁白与工程旁白」。

块后四条硬禁令：

- **禁止正文复述围栏内注释**：代码块内 `//` / `#` 注释已写明的意图、产物路径或字段含义，块后正文不得同义再讲一遍；块后只写注释没覆盖的新工程信息（谁调用、如何验证、与邻块或图的关系）。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「块后复述注释」。
- **禁止单段夹杂多个并列对象**：同一段只推进一个对象，对象切换必须新起段并用一句关系衔接；可「一段 + 配套列表」，但列表项不得跨对象拼装。递进依赖链不算并列：先按上文递进合并判定并成一块、块后列表分项，不按本条拆段。多代码块小节里每段最多一句 + 一个配套块。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「单段混并列对象」「递进片段合并」。
- **禁止块后悬空指代围栏内的实体**：块后段落首次提及代码块引入的常量、类型或函数时点名标识符；先行词只出现在围栏里（不在任何句中）时，不得用「这三个常量」「它们」式省称开场。导语或前段已逐一点名后，后文才可用集合指称回指（与标识 `bg-terminology-v1` 的知识文件「公共定义」行同界）；建立多个对象的关系时用一句写全谁约束谁、谁派生自谁（模板见标识 `bg-terminology-v1` 的知识文件「禁用与替换」的契约链行）。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「块后悬空指代」。
- **禁止块后正文逐条释义代替设计动机**：块后散文段落不是成员清单的重写，连续的「`标识符`＋动词短语」释义只回答「是什么」，要写出为什么这样设计、对调用方意味着什么，释义只在服务动机的句子里出现；公式的每一项同样不拆成列表项，用连贯因果句递进。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「逐条释义代替动机」。

渐进披露不进正文：语法细节延后展开是 Agent 侧写作策略，禁止把策略写成对读者的话——「语法细节留到后续章节真正用到时再展开」「本章只需认清……」这类元叙述一律不出现在 `content/**`；正文直接陈述对象和结果（如「这段程序对外可见的结果只有两处：……」），需要延后的内容保持沉默即可。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件，禁用词见标识 `bg-terminology-v1` 的知识文件。

列表与表格同律：表格前用一句完整的话交代它回答什么问题，表格后补一行读者该取走的结论；列表前用完整句引出，列表后只在需要收束判断时补结尾段。命令是输入，输出是观察，正文是判断依据，三者不混在同一代码块。

多命令块：块后逐条讲解改用无序列表，每项格式为「行内代码标识符 + 全角冒号 + 一句职责」（如 `` `set`：把运行产物目录设为 `build/bin`。``），描述从简、不展开参数细节；命令与标识符沿用行内代码标记，不叠加加粗（标记规则见标识 `bg-terminology-v1` 的知识文件）。引言与收束按上段列表通则，不再按命令分段成多个段落。完整规则见标识 `bg-paragraph-craft-v1` 的知识文件；有先后顺序的排查步骤仍用有序列表。

代码块导语禁用「N 段命令定义」式元计数：用职责顺序（先…再…最后…）点名对象，不叫读者回数段落；改写对照见标识 `bg-qmd-elements-cases-v1` 的知识文件「代码块导语元计数对照」。

## 代码与图的桥接

代码块引出 `{mermaid}` 图或 `{python}` 坐标图时按固定序列组织：代码块 → 桥接句 → 图（含 `fig-cap`）→ 图后新结论。固定序列的完整写法见 `writing-quarto` 技能 `references/quarto/authoring.md`「代码与图的桥接」，两条硬边界：

- 代码块与图之间必须有桥接句，说明图要核对代码已讲清的哪条关系；中间只有空行视为堆叠（`check_docs.py` 的 DOC-E11 只要求相邻围栏留空行，空行不等于桥接正文）。
- 图后先给「从图带走的结论」或图外新信息，再进入下一块；小节以图收尾时，结论可并入桥接段，不在图后孤悬一句。图注已写明的信息不复述。坐标图计入盒子密度（口径见标识 `bg-coords-diagram-v1` 与 `bg-section-density-v1` 的知识文件），同一 `###` 默认不超过两个主线盒子。
- 一图一事、同主题相邻、图不承载正文未写的新信息：一张图只核对一条已讲清的关系；代码与图主题不同时收束本对象再拆 `###`，禁止「代码 A → 短句拐弯 → 图讲 B → 再贴代码 C」的同节混排（三条边界的写法见 `references/quarto/authoring.md`「代码与图的桥接」）。
- 图前段只讲本页可见的对象，且单一主题：描述版式的句子其对象必须同页可见，引用前章画面时复述读者需要的关键事实（如行列取值 0 到 2），不指称前章画面的版式（「画面上方是列号」式会让读者翻回前章）；调用方行为等第二主题移出图前段（03 章定义坐标范围节两段并一段的改稿对照）。

图不能替代结论句：桥接句与图带走的结论缺任何一处，读者只有图没有判断依据。正反对照见标识 `bg-qmd-elements-cases-v1` 的知识文件「代码与图桥接对照」。

## 短表与宽表

- **短标签 + 长说明两列表**：包 `::: {.compact-table}`，并设 `tbl-colwidths="[22,78]"`，不靠浏览器均分。
- **单元格都短的对照表**：只用 `::: {.compact-table}`。
- **列多或单元格长**（验收矩阵、路线图）：不用 compact；优先减列、拆表或把长句外移正文；宽表依赖既有横向滚动。
- 主题 CSS 全宽（`width: 100%`）、左对齐，与正文同宽不居中。表前一句问什么，表后一句结论。
- Pipe 表原生 `colwidth` 在本栈无效时用 Quarto `tbl-colwidths`；不为单表写 raw HTML。

## 盒子密度

盒子指代码块、表格、提示框、引用块、图表容器。密度阈值与权衡的唯一出处见标识 `bg-section-density-v1` 的知识文件：单个 `##` 的主线盒子控制在两个左右，相邻盒子最多一处，每两个盒子之间至少有一段交代判断依据的话；修法是补承接正文，不是删盒子。

## Callout 克制且尾置

任务提醒型 Callout 只承载可跳过的提醒，使用 Quarto 内置类型（note/tip），放在任务末尾而不插在主线动作之间；不重复紧邻正文的命令、成功判据。影响当前操作的内容不能靠提示框隐藏。块后讲解列表与 Callout 也不得以第三种说法复述相邻正文已合并陈述的事实（同义合并规则见标识 `bg-paragraph-craft-v1` 的知识文件）：成功条件已在正文点名后，列表只映射机制，Callout 只补术语或列表未写明的一点（如 CTest 对 `COMMAND` 默认要求退出码 0），不重讲一遍故事。

术语解释型 Callout 是就近放置的例外：承载术语卡，紧跟术语首次真正使用处，不计入尾置限额。一句同位短语能说清的说明保留行内括号，不升级为 Callout：

```markdown
::: {.callout-note title="术语：冒烟测试（smoke test）"}
业界对“程序能启动且基本行为正确”这类最基础检查的叫法。……
:::
```

Callout 位置：说明型与术语卡 Callout 都放在它所补充的段落或小节内容的最后面，即解释文字全部出现之后再放盒子，不插在代码块与其解释之间。「紧跟使用处」指跟在该术语参与的那段解释后面，不是紧跟代码块。

术语卡不得是一行词典卡：正文只剩一句定义、判定条件留在别处时，把判定条件并入术语卡，或把定义并回正文、删除空卡。02 章冒烟测试的定稿形态是列表映射命令、术语卡收束：卡内同时写业界叫法与通过条件（退出码 0 与输出断言同时满足），不再另设一句短段。

## 标题导语

`##` 下不强制写导语。只有导语补充任务顺序、前置条件、范围或标题没有表达的结果时才保留；把标题换一种说法的导语删除。代码块前不固定用冒号：完整动作句用句号收束，只有「如下/以下/例如」明确引出代码或输出时才用全角冒号。

## 目录树与多命令块

- 目录树给行尾注释交代文件职责，树后正文不再逐行复述注释；只展示当前任务需要的文件，缓存和构建产物按需展开。
- 行尾注释写成名词性职责短语（如 `# 顶层构建规则`、`# 定义动态库目标 tictactoe`），同棵树语气一致；禁止在注释里用全角冒号挂解释（`# 顶层规则：产物目录与组件组合` 改 `# 顶层构建规则`），`verify_content.py` 对树内 `：` 判失败。解释若长到一个短语装不下，说明该文件的职责需要正文交代，不塞进树注释。
- 行尾注释用职责抽象、与同棵树其他注释保持同一层级：目录写角色（`# 动态库`、`# 终端程序`），实现目录写“X 实现”（`# 动态库实现`、`# 终端程序实现`），产物目录写存放物（`# 构建产物目录`、`# 可执行文件`）；不在注释里点名下层具体文件名（`# cli.cpp 与 main.cpp` 式列举回答“里面有什么文件”，不回答“负责什么”），文件分工留给讲实现的章节。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「树注释点名文件与问答式读法句」。
- 一个代码块内的多条命令职责彼此独立时，逐条子注释说明用途（防止新手把诊断命令当修复命令重复执行）；顺序执行的同一流程不强制加注释。读者只需执行其中一条时，拆成独立代码块并写明取舍时机。

## 执行位置判据

故障定位第一步是确认执行位置和前置状态，给可观察判据而不是模糊要求：Shell 场景用 `pwd` 看路径结尾，工程场景用特征文件（如 `CMakeLists.txt`）存在性判断。

## 命令介绍模式

讲解工具链命令（CMake、CTest 等）时：命令名用行内代码，每条命令一句话职责；参数只在影响当前理解时展开，完整语义不进正文；默认不放官方文档链接，需要深入时由章末参考资料或确实反直觉处的单个链接承担。

职责句点名对象类型与配合关系：`target_compile_features(app PRIVATE cxx_std_20)` 写作「要求可执行目标 `app` 使用 C++20；`PRIVATE` 只作用于该目标」，禁笼统「给目标声明…只约束这个目标自己」。命令中的路径展示真实值：直接写变量本体（如 `set(CMAKE_RUNTIME_OUTPUT_DIRECTORY "${CMAKE_BINARY_DIR}/bin")`），正文用 `build/bin/...` 描述落地位置；不引入 `<binary-dir>` 式占位符，也不在正文解释占位符与真实变量的对应关系。
