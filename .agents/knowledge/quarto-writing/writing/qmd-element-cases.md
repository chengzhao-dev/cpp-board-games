# Quarto 教学元素与衔接案例

元素语法与选择的通用 how 见 `writing-quarto` 技能 `.agents/skills/writing-quarto/references/quarto/authoring.md`；本文件保留本仓片段标注、表格、Callout 与命令讲解细则，供编写和评审章节正文时对照。

## 代码块 filename 标注

来源文件、执行位置、输出场景写在代码块标题里，正文不重复「下面是 xxx 的源码/一段命令」这类视觉上已存在的信息。

**片段优先**：每个 `##`（或 `###`）只展示正式代码里与本节任务最相关的一块并精讲，默认内联摘录，不用 include 拷贝整个文件：

````markdown
```{.cpp filename="main.cpp"}
#include <iostream>

int main() {
 std::cout << "Hello, World!\n";
 return 0;
}
```
````

- 片段必须逐字摘自源文件，禁止改写、合并或重排源代码行；注释与空行可以省略，省略处直接省略，不写任何标记行。
- **filename 一律短显示名**：只写 `main.cpp`、`CMakeLists.txt`、`build-and-run.sh`、`01-toolchain-probe/` 这类短名；禁止把 `games/...` 或 `shared/...` 深层路径塞进标题栏。完整位置由同节正文中的 GitHub 链接和目录树提供；`verify_content.py` 用同 `##` 节内、代码块之前 basename 匹配的 blob 链接解析真实路径再做片段核对。
- 片段内注释硬限：每处注释不超过 2 行、单行不超过 40 字，只写这段代码做什么；CMake/Shell 等命令型片段每条命令保留一行意图注释。命名惯例、官方建议、未来演化等规范说理一律不进代码块，面向读者的写进对应 callout，面向作者的进知识文件。
- 讲解段只解释片段中实际出现的代码；片段没有展示的内容要么补进片段、要么进 callout，不在正文列表里讲代码外面的东西。
- include 短代码降级为可选手段：仅用于确实需要完整展示且很短的文件，并仍须包在带语言标注的围栏代码块内（包裹规则见标识 `bg-quarto-conventions-v1` 的知识文件）。
- 手动命令块标注执行位置，如 `filename="WSL Ubuntu（仓库根目录）"`。
- 输出效果类代码块（运行效果、预期输出）filename 只写场景名（如「运行效果」）；终端样式、颜色等展示细节写进正文，不进 filename。输出摘录用单独一行 `...` 表示省略的工具输出，与源码片段的省略是两回事。

## 内容块前后的闭环

一个段落只推进一个对象。小节内出现代码块、列表或表格时，按「引言 → 块 → 结尾（可选）→ Callout（可选）」组织：块前用一两句引言交代为什么看它（在哪里、执行后会发生什么），块后说明看到什么算成功或下一步是什么；引言写判断依据，不写「如下：」式的空引导（GitHub 风格指南同款要求：解释文字放在代码块前面，而不是塞进代码注释）。

以代码块为中段，块前导语与块后解释的 token 量大致均衡，谁都不明显超过对方：导语讲工程语境，这段代码为什么存在、为什么此刻看它；解释讲工程关系，这段代码的哪些部分被下游消费、如何被验证。语法细节不逐行展开，留到用到处。

渐进披露不进正文：语法细节延后展开是 Agent 侧写作策略，禁止把策略写成对读者的话——「语法细节留到后续章节真正用到时再展开」「本章只需认清……」这类元叙述一律不出现在 `content/**`；正文直接陈述对象和结果（如「这段程序被下游消费的结果只有两处：……」），需要延后的内容保持沉默即可。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件，禁用词见标识 `bg-terminology-v1` 的知识文件。

列表与表格同律：表格前用一句完整的话交代它回答什么问题，表格后补一行读者该取走的结论；列表前用完整句引出，列表后只在需要收束判断时补结尾段。命令是输入，输出是观察，正文是判断依据，三者不混在同一代码块。

多命令块：块后逐条讲解改用无序列表，每项格式为「行内代码标识符 + 全角冒号 + 一句职责」（如 `` `set`：把运行产物目录设为 `build/bin`。``），描述从简、不展开参数细节；命令与标识符沿用行内代码标记，不叠加加粗（标记规则见标识 `bg-terminology-v1` 的知识文件）。列表前保留一句引言交代工程语境，列表后需要时补一句收束或尾置 Callout；不再按命令分段成多个段落。完整规则见标识 `bg-paragraph-list-style-v1` 的知识文件。有先后顺序的排查步骤仍用有序列表（列表选择规则同前）。

代码块导语禁用「N 段命令定义」式元计数：

```text
不佳：可执行目标由三段命令定义：输出目录、源文件清单和语言标准：
改写：下面这段规则定义可执行目标 tic_tac_toe_cli：先规定产物目录，再列出源文件，最后声明 C++20。
```

## 短表与宽表

- **2–3 列、单元格短**（对照词、目录映射）：用 `::: {.compact-table}` 包裹 pipe 表；主题 CSS 全宽（`width: 100%`）、左对齐，与正文同宽不居中。表前一句问什么，表后一句结论。
- **列多或单元格长**（验收矩阵、路线图）：不用 compact；优先减列、拆表或把长句外移正文；宽表依赖既有横向滚动。
- Pipe 表 `colwidth` 在本栈无效，不采用；不为单表写 raw HTML。

## 盒子密度

盒子指代码块、表格、提示框、引用块、图表容器。密度阈值与权衡的唯一出处见标识 `bg-section-focus-density-v1` 的知识文件：单个 `##` 的主线盒子控制在两个左右，相邻盒子最多一处，每两个盒子之间至少有一段交代判断依据的话；修法是补承接正文，不是删盒子。

## Callout 克制且尾置

任务提醒型 Callout 只承载可跳过的提醒，使用 Quarto 内置类型（note/tip），放在任务末尾而不插在主线动作之间；不重复紧邻正文的命令、成功判据。影响当前操作的内容不能靠提示框隐藏。块后讲解列表与 Callout 也不得以第三种说法复述相邻正文已合并陈述的事实（同义合并规则见标识 `bg-paragraph-cohesion-v1` 的知识文件）：成功条件已在正文点名后，列表只映射机制，Callout 只补术语或列表未写明的一点（如 CTest 对 `COMMAND` 默认要求退出码 0），不重讲一遍故事。

术语解释型 Callout是就近放置的例外：承载术语卡，紧跟术语首次真正使用处，不计入尾置限额。一句同位短语能说清的说明保留行内括号，不升级为 Callout：

```markdown
::: {.callout-note title="术语：冒烟测试（smoke test）"}
业界对“程序能启动且基本行为正确”这类最基础检查的叫法。……
:::
```

Callout 位置：说明型与术语卡 Callout 都放在它所补充的段落或小节内容的最后面，即解释文字全部出现之后再放盒子，不插在代码块与其解释之间。「紧跟使用处」指跟在该术语参与的那段解释后面，不是紧跟代码块。

术语卡不得是一行词典卡：正文只剩一句定义、判定条件留在别处时，把判定条件并入术语卡，或把定义并回正文、删除空卡。02 章冒烟测试的定稿形态是列表映射命令、术语卡收束：卡内同时写业界叫法与通过条件（退出码 0 与输出断言同时满足），不再另设一句短段。

## 标题导语

`##` 下不强制写导语。只有导语补充任务顺序、前置条件、范围或标题没有表达的结果时才保留；把标题换一种说法的导语删除。代码块前不固定用冒号：完整动作句用句号收束，只有「如下/以下/例如」明确引出代码或输出时才用全角冒号。

## 目录树与多命令块

- 目录树给行尾注释交代文件职责，树后正文不再逐行复述注释；只展示当前任务需要的文件，缓存和构建产物按需展开。
- 一个代码块内的多条命令职责彼此独立时，逐条子注释说明用途（防止新手把诊断命令当修复命令重复执行）；顺序执行的同一流程不强制加注释。读者只需执行其中一条时，拆成独立代码块并写明取舍时机。

## 执行位置判据

故障定位第一步是确认执行位置和前置状态，给可观察判据而不是模糊要求：Shell 场景用 `pwd` 看路径结尾，工程场景用特征文件（如 `CMakeLists.txt`）存在性判断。

## 命令介绍模式

讲解工具链命令（CMake、CTest 等）时：命令名用行内代码，每条命令一句话职责；参数只在影响当前理解时展开，完整语义不进正文；默认不放官方文档链接，需要深入时由章末参考资料或确实反直觉处的单个链接承担。

职责句点名对象类型与配合关系：`target_compile_features(tic_tac_toe_cli PRIVATE cxx_std_20)` 写作「要求可执行目标 `tic_tac_toe_cli` 使用 C++20；`PRIVATE` 只作用于该目标」，禁笼统「给目标声明…只约束这个目标自己」。命令中的路径展示真实值：直接写变量本体（如 `set(CMAKE_RUNTIME_OUTPUT_DIRECTORY "${CMAKE_BINARY_DIR}/bin")`），正文用 `build/bin/...` 描述落地位置；不引入 `<binary-dir>` 式占位符，也不在正文解释占位符与真实变量的对应关系。
