# 书面语气与语域判定标准

本文件定义 `content/**/*.qmd` 的正向语气标准。禁用词表（标识 `bg-terminology-v1` 的知识文件）回答「不能用哪个词」，本文件回答「合格的句子写成什么样」；通用句式降噪见 `writing-quarto` 技能 `.agents/skills/writing-quarto/references/zh/writing-principles.md`。起因是全书语气轴不一致：开场页是讲义口语，规划页引言混用规划元叙述与刻板措辞，需要一条可判定的语域基准。

## 目标语域

中文技术工程文档语域：陈述、可核对、主动语态。句子完整，包含动作、对象与顺序；允许自然衔接词，不堆砌「必须 / 应当 / 予以」。

## 两轴禁例与允许写法

| 轴 | 禁止 | 允许 |
| --- | --- | --- |
| 口语讲义腔 | 动手前、咱们、搞定、别慌；开场「先弄清三件事」式讲义口 | 进入实现前先确认…；确认 / 理解 / 查看 |
| 刻板公文腔 | 必须显式、永远、应让…；堆砌禁词后的电报省略 | 写成可观察条件或后果；完整陈述句 |
| 规划元叙述 | 本章规划、落点是、类型名只是设计方向、尚未对应可运行目录 | 直接写本章要解决的问题与目录路径；实现状态用「实现并通过验收前按设计页阅读」一句收束 |
| 人称 | 正文寒暄式第二人称开场 | 正文以工程对象为主语；「你」仅用于本章回顾与自测指令 |

## 句段改写步骤

段落或句子不合格时按序执行：

1. 一段只留一个主题，多余主题拆段；
2. 段首写中心句，其余句子服务中心句；
3. 超长句或一句多动作拆句，每句保留动作、对象与顺序；
4. 相邻两段同义复述时合并为一段；
5. 过渡句只写在话题切换处；
6. 操作节只保留动作与可见结果。

## 判定信号

- 口语信号：出现对读者的招呼（动手前、先弄清、咱们）或寒暄式开场。
- 公文信号：删去「必须 / 应当 / 予以 / 永远」后句义不变，说明这些词只承担语气；改为写出不满足时的后果。
- 元叙述信号：句子主语是「本章 / 本页 / 写作计划」，内容讲的是章节安排而非工程对象；实现状态说明全页至多出现一次，规划页固定放在引言。

## 对照案例

01 章开场，讲义口换成书面陈述：

```text
不佳：井字棋动手前先弄清三件事：用哪些工具、项目要处理哪些内容、代码按什么层次实现。
改写：进入井字棋实现前，先确认三件事：使用哪些工具、项目要处理哪些内容、代码按什么层次实现。后续章节都在这些边界内推进。
```

规划页引言，元叙述堆叠换成三句模板（承接、设计问题、目录与状态；承接句在正文中用章节标题链接）：

```text
不佳：本章让单次动作可靠起来，先明确交付的行为与测试边界；内容的落点是 games/tic-tac-toe/03-move-validation/…本页是规则设计页，尚未对应可运行的实现目录。
改写：棋盘与状态建立了状态模型。本章定义单次落子的合法与非法处理及其测试边界；对应实现目录是 games/tic-tac-toe/03-move-validation/，实现并通过验收前按设计页阅读。
```

引言三句模板的结构位置见标识 `bg-chapter-page-pattern-v1` 的知识文件；逐句改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件。
