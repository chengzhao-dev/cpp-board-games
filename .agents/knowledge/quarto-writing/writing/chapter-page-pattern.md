# 章节页面骨架与职责边界

章节骨架的通用 how 见 `writing-quarto` 技能 `.agents/skills/writing-quarto/references/zh/chapter-writing.md`；本文件保留本仓六段骨架的判定细节、游戏首末章职责与规划页降级形态，作为 `content/**/*.qmd` 的骨架标准。

## 六段块序列

```text
无标题引言 → 任务序列（2-4 个 ##）→ ## 常见错误 → ## 自测问题 → ## 本章回顾
```

读者在正文里依次进行四种认知活动：确认来对了地方、完成可验证的动作、确认理解了关键关系、确认获得了什么。各段各服务一种活动，顺序由「读者先要知道什么才能看懂下一步」决定。

- **无标题引言**：第一个 `##` 之前，承担三件事——承接上一章的结果、说明本章要解决的具体问题、交代读者将要获得的整体认识（含范围边界与完整示例位置）。不放 Callout，不写后续章节内容，不解释术语。采用无标题引言，**取代**此前「引言并入第一节目标」的写法。引言容纳多个独立概念时不再压成一段，链路/步骤用有序列表、范围边界用无序列表，每段仍只承担一件事；拆分规则见标识 `bg-paragraph-list-style-v1` 的知识文件。内容量硬限：引言由「承接 1-2 句 + 至多 1 个结构化元素（列表或表格）」构成；范围边界能并入承接段时不成列表；不写复述标题结构的结尾导航段。承接与回顾中引用其他章节一律用章节标题链接，不用「第 N 章」（规则见标识 `bg-terminology-v1` 的知识文件）。任务概览默认并入承接句，正文小节就是任务的展开；预览列表仅当任务没有对应正文小节时使用（02 章四项工作列表已按此删除）。
- **任务序列**：每节一个可验证结果。判定标准是任务结束时存在一个读者能自己复述的检查动作；只有「读完了解释」的内容并入相邻任务。概念 → 最小示例 → 操作 → 验证 → 边界，先让读者看到行为再解释规则。实现章的任务序列固定为「目录树总览 → 设计与实现（源码）→ 构建规则 → 测试验证」：设计节按「数据 → 动作 → 结果」三步同构建模，每步先写游戏语义，再写本仓类型形式（`enum class` / `struct`）与接口名，步骤结构跨章复用，设计范围以「本章实现边界」收束；构建规则不先于设计与实现出现。内容量硬限：`##` 开头承接正文不超过 2 句，`###` 开头不超过 1 句，写完直接进入代码、命令或列表；超出即为凑字数信号，禁令见标识 `bg-paragraph-list-style-v1` 的知识文件。
- **常见错误**：服务失败后回来的读者。每个症状一个 `###`，标题后第一句写触发条件和可观察现象，正文给定位 → 修复 → 验证三个动作，最后把读者送回主线。入门章节只保留最可能遇到的 2-3 项，不是完整 FAQ。
- **自测问题**：服务刚跑通主线、需要确认理解的读者。每章 0-7 道针对关键因果的「为什么」题，没有高价值问题时不添加；固定导语「先不要展开答案，试着自己把回答完整说出来，再展开对照；说不出来的部分，回到对应小节对照正文。」；答案写在 `::: {.answer}` 围栏 div 内，由 `.agents/skills/writing-quarto/scripts/answer-disclosure.lua` 渲染为默认收起的原生 `<details>`；答案只使用本章已讲过的概念。
- **本章回顾**：服务已经成功的读者。1-2 句段落（不是 bullet 列表），句式「你已经能 <能力>。下一章 <预告>。」。
- **游戏首末章职责**：游戏首章（横向说明页）额外承担流程前段的读者摘要——短需求形态、目录与层次、模块职责与模块间数据、开发环境与真实选型，并写出本游戏 STAR 的 S/T；末章承担完成要点（如何配置编译、依赖约定、如何运行、如何测试，指向阶段 `build-and-run.sh` 与 CTest）与 STAR 的 A 摘要与 R（可观察成果、可优化点与延后项，链到渐进式路线章门槛表）；中间实现章的「常见错误」承接流程步骤 ⑦ 的报错记录（症状 → 定位 → 修复 → 验证，依据见标识 `bg-engineering-storyline-v1` 的知识文件）。首末章不堆运行调试全过程，中间章不复述整套八步或完整 STAR。
- **降级形态**：**规划页**（尚未实现的设计章节，如井字棋 04-06、08-10）与**横向说明页**（跨章节说明，如井字棋 01、07）可不设常见错误与自测问题。规划页由无标题引言、动词短语 `##` 任务序列与 `## 本章回顾` 构成：回顾句式为「本章固定了…。下一章 <预告>。」，不以「你已经能」开头（能力句留给实现后补齐的六段骨架），实现时替换为标准回顾并补常见错误与自测。横向说明页由无标题引言与动词短语 `##` 构成，最后一个正文节以边界句收束。规划页引言按三句模板书写：承接上一章结果（章节标题链接）、本章要解决的具体设计问题、对应实现目录用中文锚文本的 GitHub 链接给出（未创建目录用 `tree/main/` 路径，创建前 404 属预期），后接一句「实现并通过验收前按设计页阅读」。引言不写行内代码路径，也不写「目录编号比章节」式编号旁注；编号差只在渐进式路线章说明。语气标准见标识 `bg-chinese-voice-register-v1` 的知识文件；章级总分总与段间衔接见标识 `bg-paragraph-cohesion-v1` 的知识文件。

## 标题分层

- `##` 承担大任务，且要让读者看出它承担本章 title 中的哪部分：title 是「配置并运行最小工程」时，构建规则节对应「配置」、一键脚本节对应「运行」，各节首句显式点明这层对应。
- `###` 承担 `##` 内部可独立执行、观察或验证的子任务（源码阅读、产物检查、具体故障症状）；一个 `##` 内含多个连续子流程时用 `###` 分步。
- 只有解释或一两句结论的内容不升级为标题；正文最多保留到 H3，不写 `####`。
- 一个 `##` 只承担一个可验证结果；标题写成宽泛主题时读者无法判断做到什么程度才算完。
- `##` 出现多个连续子流程、或篇幅触达 token 预算（见标识 `bg-content-budget-v1` 的知识文件）时，强制拆分为 `###` 子小节，不整块下压。
- 标题只用读者此刻已认识的词或字面自明的词，不使用正文之后才解释的术语。
- 层级结构遵循阮一峰[《中文技术文档写作风格指南》](https://github.com/ruanyf/document-style-guide)标题章：不跳级（一级标题下不直接出现三级标题）、避免孤立编号（同级标题只有一个时省略）、下级标题不重复上级标题的名字。

## 术语与验证策略

- 术语在**首次真正使用处**就近放术语 callout，不用段落括号夹注（写法见标识 `bg-qmd-element-cases-v1` 的知识文件）；一个同位短语就能说清的（如 CTest（CMake 自带的测试运行工具））可保留行内括号。面向新人的正文不堆砌入门前置名词（walking skeleton 这类术语直接删除）。
- 页面写出的验证结论必须与证据强度匹配：命令能定位、版本能输出、程序能编译运行是不同层级，不能用弱观察替代强证明。
- 涉及阶段目录结构的章节：先给目录树，再按树顺序逐项说明（链接格式见标识 `bg-quarto-conventions-v1` 的知识文件）。
- 全书统一术语与替换规则见标识 `bg-terminology-v1` 的知识文件。
