# 章节页面骨架与职责边界

章节骨架的通用 how 见 `writing-quarto` 技能 `.agents/skills/writing-quarto/references/zh/chapter-writing.md`；本文件保留本仓六段骨架的判定细节和井字棋各章职责，作为 `content/**/*.qmd` 的骨架标准。没有对应源文件的章不进 `_quarto.yml`。

## 六段块序列

```text
无标题引言 → 按独立任务划分的任务级 ## → ## 常见错误 → ## 自测问题 → ## 本章回顾
```

任务级 `##` 按独立读者任务和可验证结果划分；2–4 个只是常见预算，不是必须凑足的配额。固定收尾节不计入任务数量，着陆页不套用任务级标题上限。上限用于防止页面失控，不要求把独立任务机械降为 `###`；第一章可以没有「常见错误」。

读者在正文里依次确认来对了地方、完成可验证的动作、理解关键关系并确认获得的能力。各段服务一个认知结果，顺序由「读者先要知道什么才能看懂下一步」决定。

- **无标题引言**：第一个 `##` 之前，承担三件事——承接上一章的结果、说明本章要解决的具体问题、交代读者将要获得的整体认识（含范围边界与完整示例位置）。不放 Callout，不写后续章节内容，不用「后面的 X」式前向指称引入后续章节才建立的结构件（如「实现放在后面的编号目录里」），范围边界只写本章不展开什么，不解释术语。采用无标题引言，**取代**此前「引言并入第一节目标」的写法。引言容纳多个独立概念时不再压成一段，链路/步骤用有序列表、范围边界用无序列表，每段仍只承担一件事；拆分规则见标识 `bg-paragraph-list-style-v1` 的知识文件。内容量硬限：引言由「承接 1-2 句 + 至多 1 个结构化元素（列表或表格）」构成；范围边界能并入承接段时不成列表；不写复述标题结构的结尾导航段。承接中引用其他章节一律用章节标题链接，不用「第 N 章」；本章回顾的下一章预告不写链接，直述预告一句（页面导航已有前进按钮），两者均见标识 `bg-terminology-v1` 的知识文件。任务概览默认并入承接句，正文小节就是任务的展开；预览列表仅当任务没有对应正文小节时使用（02 章四项工作列表已按此删除）。原 front matter `description` 的定位信息并入引言承接句，信息只保留引言一处、不同义两存；章节 qmd 不写 `description`（字段出处见 basics.md）。
- **任务序列**：每节一个可验证结果。判定标准是任务结束时存在一个读者能自己复述的检查动作；只有「读完了解释」的内容并入相邻任务。概念 → 最小示例 → 操作 → 验证 → 边界，先让读者看到行为再解释规则。井字棋各章的任务节以该章标题里的对象为准，不把每一章都写成「目录、设计、构建、测试」四节。设计范围以这一章能在 `01-cli-game` 里核对的源文件收束。内容量硬限：任务级 `##` 通常不超过 4 个；`##` 开头承接正文不超过 2 句，`###` 开头不超过 1 句，写完直接进入代码、命令或列表；超出即为凑字数信号，禁令见标识 `bg-paragraph-list-style-v1` 的知识文件。交付清单或纯边界说明不单独设 `##`，并入引言或相邻工程总览节；同一头文件中连续的值类型优先按一个可验证结果归并到同一任务节。
- **常见错误**：服务失败后回来的读者。每个症状一个 `###`，标题后第一句写触发条件和可观察现象，正文给定位 → 修复 → 验证三个动作，最后把读者送回主线。入门章节只保留最可能遇到的 2-3 项，不是完整 FAQ。
- **自测问题**：服务刚跑通主线、需要确认理解的读者。每章 0-7 道针对关键因果的「为什么」题，没有高价值问题时不添加；固定导语「先不要展开答案，试着自己把回答完整说出来，再展开对照；说不出来的部分，回到对应小节对照正文。」；答案写在 `::: {.answer}` 围栏 div 内，由 `.agents/skills/writing-quarto/scripts/answer-disclosure.lua` 渲染为默认收起的原生 `<details>`；答案只使用本章已讲过的概念。题目同样必须能由本章正文回答：答案依据须是正文已写明的内容，正文没讲的概念不设题；若问题值得问，先在正文补上依据再设题。
- **本章回顾**：服务已经成功的读者。1-2 句段落（不是 bullet 列表）：「你已经能 <能力>」中的能力必须对应本章任务节交出的结果，可复用任务节关键词，不写正文没有的抽象总称（如「按输入、输出和终局」）；「下一章 <预告>」不写链接，直述预告一句（页面导航已有前进按钮），预告不引入下一章才建立的术语。回顾的每个说法都要能在正文找到出处，禁止空泛能力句或只写预告；正文任务节变化时同步改写回顾。
- **井字棋各章职责**：首章只固定可观察的输入、输出和对局约定，不写类型名或构建命令。布局章只建立编号目录与文件职责，不提前完成终局、配置、编译、测试或运行。棋盘章说明格子状态，规则章再展开落子约束与终局判定，终端章最后承接输入输出以及配置、编译、测试和运行验收。后续扩展章只引入新增行为，并与对应代码阶段核对。语气标准见标识 `bg-chinese-voice-register-v1` 的知识文件；章级总分总与段间衔接见标识 `bg-paragraph-cohesion-v1` 的知识文件。

## 标题分层

- `##` 承担大任务，且要让读者看出它承担本章 title 中的哪部分：标题应描述本页当前交付的读者结果；布局页不使用「配置并运行」作为标题，除非该页确实让读者完成并验证这些动作。
- `###` 承担 `##` 内部可独立执行、观察或验证的子任务（源码阅读、产物检查、具体故障症状）；一个 `##` 内含多个连续子流程时用 `###` 分步。
- 只有解释或一两句结论的内容不升级为标题；正文最多保留到 H3，不写 `####`。
- 一个 `##` 只承担一个可验证结果；标题写成宽泛主题时读者无法判断做到什么程度才算完。
- `##` 出现多个连续子流程、或篇幅触达 token 预算（见标识 `bg-content-budget-v1` 的知识文件）时，强制拆分为 `###` 子小节，不整块下压。
- 标题只用读者此刻已认识的词或字面自明的词，不使用正文之后才解释的术语。
- 任务级 `##` 承担一个概念组或一项可独立交付的任务：单个类型、单个枚举或单个函数的小节不独占任务级 `##`，与相邻概念并成一组再按 `###` 分步（03 章反例：`定义坐标范围`、`保存格子状态` 曾各自独立成 `##`，粒度低于任务级，已重排为「认识棋盘格子」与「读写棋盘格子」两个概念组）。
- 标题与内容匹配：标题动词承诺的动作必须是本节正文实际让读者完成的动作——正文只要求观察的行为用「观察、查看、核对」类动词，不用「走完、完成」类只在真实操作节成立的动词；任务级标题不与页面 title 共用「看懂」「看」这类核心动词，页面 title 已承诺的认识动作由正文兑现，标题换用更具体的动词；二级标题的宾语要涵盖其下三级标题的宾语，读者从标题序列能看出各节分工，不写比正文更宽或更窄的承诺。改写对照见标识 `bg-file-title-naming-v1` 的知识文件反例表。
- 层级结构遵循阮一峰[《中文技术文档写作风格指南》](https://github.com/ruanyf/document-style-guide)标题章：不跳级（一级标题下不直接出现三级标题）、避免孤立编号（同级标题只有一个时省略）、下级标题不重复上级标题的名字。

## 术语与验证策略

- 术语在**首次真正使用处**就近放术语 callout，不用段落括号夹注（写法见标识 `bg-qmd-element-cases-v1` 的知识文件）；一个同位短语就能说清的（如 CTest（CMake 自带的测试运行工具））可保留行内括号。面向新人的正文不堆砌入门前置名词（walking skeleton 这类术语直接删除）。
- 页面写出的验证结论必须与证据强度匹配：命令能定位、版本能输出、程序能编译运行是不同层级，不能用弱观察替代强证明。
- 涉及阶段目录结构的章节：先给目录树，再按树顺序逐项说明（链接格式见标识 `bg-quarto-conventions-v1` 的知识文件）。
- 全书统一术语与替换规则见标识 `bg-terminology-v1` 的知识文件。
