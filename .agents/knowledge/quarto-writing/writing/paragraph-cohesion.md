# 段落衔接与结构模型

起因是各章行文缺乏统一的衔接方式。中文写作对段落衔接的抽象描述分三层：文章级结构方式（总—分—总、并列式、递进式、对照式）、段落展开方式（递进式按步骤或因果层层推进，并列式枚举无先后关系的要点）、段间衔接手段（过渡词、过渡句、过渡段实现承上启下，首尾照应收束全文）。本文件把它落成 `content/**/*.qmd` 的执行标准；段内降噪与删改的通用做法见 `writing-quarto` 技能 `.agents/skills/writing-quarto/references/zh/writing-principles.md`。

## 章级：总—分—总

- **总起**：无标题引言承接上一章并给出本章任务，规则见标识 `bg-chapter-page-pattern-v1` 的知识文件。
- **分述**：正文 `##` 序列沿一条主线递进展开，每个 `##` 是一个可验证结果。
- **收束**：本章回顾照应引言提出的任务；首尾照应要求回顾能对上引言的承诺，不引入新概念。回顾的句数、句式与承接正文的要求以标识 `bg-chapter-page-pattern-v1` 的知识文件为准。
- 已有源文件的章要补齐自测与回顾。没有源文件的章不进目录。

## 节内：递进式为默认，并列式处理枚举

- 有先后或因果的内容用递进式展开：概念 → 示例 → 操作 → 验证（顺序依据见标识 `bg-chapter-page-pattern-v1` 的知识文件），段落顺序与执行顺序一致。
- 无先后关系的要点（边界清单、原则枚举）用并列式：并列内容优先成列表，不强行排序成递进（列表选择规则见标识 `bg-paragraph-list-style-v1` 的知识文件）。
- 同一小节内不混用：一条主线递进到底；并列枚举整体作为一个环节嵌在递进中。

## 段间：过渡句只在话题切换处

- 需要过渡的位置：段落话题或对象发生切换时（上一段讲 A 命令，下一段讲 B 命令；上一节配置，下一节运行）。同一段内句子推进、或下一段直接继续当前对象时，不加过渡。
- 形式：一句，放在新段段首，先接住上文（点明与上段的关系或结果），再引出本段中心。范例（02 章注册冒烟测试节首句）：「可执行目标之外，同一份构建规则还注册了本章唯一的自动化检查」——前半句接住上文的可执行目标，后半句引出新对象。
- 边界：过渡句服务主线判断，不复述标题结构。「接下来先看…再看…然后…」式导航复述段仍然禁止（规则见标识 `bg-paragraph-list-style-v1` 的知识文件）；`##` 开头承接不超过 2 句、`###` 不超过 1 句（规则见标识 `bg-chapter-page-pattern-v1` 的知识文件）。
- 下一节首句同时是上一节的承接位：写完上一节结尾后检查下一节首句是否接住读者，不在上一节尾部再补预告句（与凑字数禁令同源）。
- 相邻段落同义合并：相邻两段各自换一种说法讲同一事实时合并为一段，由后段的机制或结论接住前段的对象；合并后其余段落、列表和 Callout 不得再以第三种说法复述该事实。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件。
- 相邻两段不得各成独立说明书：第一段讲工具、第二段讲目录而彼此无衔接时，第二段段首要接住第一段的对象（工具基线 → 这些工具在编号目录上如何使用）；只删不接，两段仍然是两个条目。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件。
- **外链默认零条；禁止突兀依据句**：块前导语只引出紧随的代码块或图。cpp-notes 外链若保留，必须单独成句放在工程点讲完之后（小节末尾置「若要系统阅读…」），且禁止「写法依据见 / 依据见 / 机制见 / 选型见 / 承诺见 / 用法见 / 陷阱见」挂链。导语用分号挂外链是多中心句的典型现形，判定口诀见 `writing-quarto` 技能 `references/zh/writing-principles.md`；改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「导语多中心与分号挂外链」「突兀跨仓依据句」。
- 目录树后的正文不复述树内行尾注释：树注释已逐文件交代职责，再列一段「A 组件、B 目录与 C 目录各自带 CMakeLists.txt」是把树翻译成说明书目录。树注释覆盖职责时删复述，至多保留一句组件间的组合关系收束；树后保留的一句读法说明直述机制（「文件名给出位置，行尾注释说明职责」），不写「X 回答 A，Y 回答 B」的问答式并列——那是给工具看的格式规格，不是给读者的解说；改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「目录式堆砌」与「树注释点名文件与问答式读法句」。
- 同一禁令延伸到代码围栏：围栏内 `//` / `#` 注释已写明的意图，块后正文不再同义复述，块后只写注释没覆盖的新工程信息（对照见标识 `bg-chinese-style-cases-v1` 的知识文件「块后复述注释」）；单段夹杂两个并列对象时按对象拆段，新段段首补一句衔接（对照见同文件「单段混并列对象」）。
- **多代码块小节先判递进合并**：同一 `##`/`###` 内出现两个及以上同源代码围栏时，先按标识 `bg-qmd-element-cases-v1` 的知识文件的合并判定判断是否构成递进依赖链；构成则合并为一个围栏，块前一句导语交代这组递进定义、块后列表分项，不适用「一句一导语」。仅非递进的多围栏才适用一句一导语：每个围栏前只留一句完整导语（对象 + 谁调用或做什么），禁止「块前半句 + 块后半句」拆成两段讲同一常量或同一类型，可合并的块前与块后并成块前一句。对象切换仍可新起段，但每段最多「一句 + 一个配套块」，块后再挂多行自然段复述或延伸一律禁止。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「多代码块一句导语」「递进片段合并」。
- 表格与对照表前必须有承接句：先写各对象在做什么，再用一句关系句引出表格（如「配置改计划，构建按计划编译」），禁用「X 与 Y 是两个容易混淆的词：」式元标签开场；表后一句给读者该取走的结论（块级闭环见标识 `bg-qmd-element-cases-v1` 的知识文件）。

## 小节标题与正文对齐

- 小节标题、首句和正文指向同一个动作或对象；标题说「做什么」，正文就只写怎么做、看到什么算成功。
- 标题的名词短语要能还原成读者此刻认识的对象或动作，读不出“确认的是什么”的标题（如「确认依赖方向」）改成动作 + 具体宾语；标题和正文都不得使用读者尚未建立的概念术语（如「依赖」「使用方」「动态库」「稳定边界」）：术语要么已被前文章节建立，要么当场用读者可核对的实物（目录、文件、代码）建立；做不到就把内容下沉到概念建立之后的章节（例：02 章依赖方向的事实删除，下沉到 05 章 CTest 首次出现处）。一句话压缩多个论断而读者无法逐条核对的，拆成可核对表述或删除；首句先给中心判断，再补机制，不先堆名称后给结论。正文论据同受此限：未在正文展示过的代码标识符（如测试概念建立前引用 `BoardTest`）不作论据，验证职责下沉到展示它的章节。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「小节标题抽象与首句无中心」。
- 操作小节（如「运行一键脚本」）只保留动作、顺序与可见结果。「为何不跳过某步 / 幂等 / 配置漂移」类工程取舍，删除后不影响首次跑通与验收的，不进该节正文；确需保留时由代码注释或排查节承担。
- 跨节复述同一取舍视为标题离题的变体：该内容归属最贴合的节（如「修改 CMakeLists 后行为没变」），其余位置只保留一句或链接。

## 与其他规则的边界

- 块级前后闭环（引言 → 块 → 结尾 → Callout）见标识 `bg-qmd-element-cases-v1` 的知识文件；本文件管段落与小节之间的衔接，不重复块内规则。
- 多命令代码块后的逐条讲解用 `**标识符**：一句职责` 无序列表，规则见标识 `bg-paragraph-list-style-v1` 的知识文件。
- 小节承接正文权重与盒子密度见标识 `bg-section-focus-density-v1` 的知识文件。
