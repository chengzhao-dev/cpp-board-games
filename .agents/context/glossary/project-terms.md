# 全书统一术语与替换规则

起因是 02 章同时用「阶段」指阶段目录和脚本输出的四段，并用「切片」「自足」等含混词。此后二十四次修订逐条登记在案：一至七次停用「阶段」「探针」「最小工程」「第一版」「切片」「自足」「链路」「四步」等统称缩写，章节互引改标题链接，流程直书「配置、编译、测试、运行」，停用「接口桩」「静态到动态」与讲义腔开场词（均见禁用与替换）；八次以「棋盘格子」为领域锚点（见统一术语表）；九至十一次停用压缩隐喻与电报体，要求正文用源码完整标识符、层名首次出现给可观察定义、停用「公共头」式省略（见「禁用与替换：压缩隐喻与电报体」一节）；十二至十四次统一书的单位为「章」，本章回顾预告去链接，停用「规则库」改称「井字棋动态库」；十五至十八次对局交流不绑定媒介，全面停用「固定」，获胜事实统一「三连」，停用「遵循同一套规则」式无铺垫套语；十九至二十次停用「职责、负责、承担」角色话术与生僻动词「分进」；二十一次区分声明与定义，完整实体称定义、仅引入名字的成员函数行称声明（见易混概念：声明与定义）；二十二至二十三次要求摘录导语点名块内对象、块后首次提及点名标识符（悬空指代扩到围栏先行词），并统一布尔字面值写行内代码 true/false（均见禁用与替换）；二十四次停用「X 是定义、Y 是声明」式术语标签与区分教学，辨析降为编辑内部口径（见「禁用与替换」与「易混概念：声明与定义」）。术语在全书只用一个词，读者与编写者才不会各说各话；词表的自动执行在 `writing-quarto` 技能的 `verify_content.py`。

## 统一术语表

| 术语 | 含义 | 用法规范 |
| --- | --- | --- |
| 步骤 | 配置、编译、测试、运行中的单个环节 | 全书首次写全四步名，其后用「流程」「脚本输出」「日志」等集合指称；同段不与「终端」「CI」等名词并列堆砌；不用「四步」缩写，不指代目录 |
| 井字棋工程目录 | `games/tictactoe/01-cli-game/`，一局可下完的双人终端程序 | 读者正文用「编号目录」或「井字棋工程目录」，不叫探针，也不叫最小工程 |
| 目录指称 | 指到具体目录的写法（如 `tictactoe/src/`、`apps/`、`tests/`） | 目录统称（「实现目录」式）首次出现写全路径；前文已写全路径的集合指称（如「测试目录」）不受限 |
| 章节互引 | 在正文中指到书的另一章 | 一律用对应章节 title 作链接文字（如「先看清工程」）；相对指称（上一章、下一章、本章）可作主语，但须紧跟标题链接或标题名；例外：本章回顾的「下一章」预告不写链接，直述预告一句（页面导航已有前进按钮） |
| 配置与构建 | CMake 读取规则生成计划；Ninja 按计划编译 | 成对出现时用对照表，不重复展开 |
| 冒烟测试（smoke test） | 程序能启动且基本行为正确的最基础检查 | 术语保留；首次出现处就近放术语 callout（写法见标识 `bg-qmd-element-cases-v1` 的知识文件），不用段落括号夹注 |
| 棋盘格子 | 棋盘上的单个实体 | 正文、类型注释和接口说明均用「棋盘格子」；不单独写「格子」 |
| 九个棋盘格子 | 棋盘上全部九格的合称 | 合称写「九个棋盘格子」，不写孤立「九格」（词表硬拦孤立「九格」）；「格子」无论单数复数一律写「棋盘格子」 |
| 棋盘格子坐标 | 棋盘格子的行列坐标 | `CellPosition` 的首次定义使用此词；说明行列范围时保留「行」和「列」 |
| 棋盘格子状态 | 棋盘格子中记录的 `CellState` | 首次定义与类型上一行注释使用此词；`kEmpty` 行尾写「空格。」；正文不把 `CellState` 叫做标记或棋子 |
| 对局玩家 | 参与当前对局的玩家 | `Player` 的首次定义使用此词；动作说明写「对局玩家」 |
| 三连 | 一行、一列或一条对角线上同方棋子相连 | 获胜判定统一用「三连」，不用「占满一行」「连成三子」；棋盘填满写「下满」 |
| 落子动作 | 目标棋盘格子坐标与对局玩家组成的动作 | `Move` 的首次定义使用此词；不把它简写成「动作」后再切换含义 |
| 井字棋动态库 | `tictactoe/` 目录源码编译成的动态库（`add_library(tictactoe SHARED)`，产物在 `build/lib`），供终端程序与测试链接 | 组件称谓写「井字棋动态库」；首次出现用一句可观察行为带出（如「整个目录编译成一个动态库，供终端程序调用」）；其它工程按实际形态写明动态库或静态库 |
| 声明 | 只引入名字、不提供实体的写法（如 board.h 里只写函数名与参数表的成员函数行） | 辨析仅用于编辑与评审；content 正文不贴「声明」标签，位置与实现写具体事实（见易混概念一节） |
| 定义 | 提供实体的写法：常量给出值、类型给出全部成员、函数给出函数体 | 「定义在 board.h / game.h」作位置动词保留；.cpp 侧沿用「实现写在 board.cpp」描述行为层；正文不与「声明」成对使用（见易混概念一节） |

## 易混概念：声明与定义

声明将名字引入程序，定义提供名字所关联的实体——常量写出值、类型写出全部成员、函数写出函数体；定义本身也是声明，声明未必是定义。判定看内容不看位置：只写函数名与参数表的成员函数行是声明，给出初始值、全部成员或函数体的写法是定义，无论它在头文件还是源文件。这组辨析是编辑与评审的内部口径：content 正文不贴「是定义／是声明」标签、不成对展开两者的区分，位置与实现直接写具体事实（「换算写在 board.cpp」「常量在头文件里给出值」），「定义在 x.h」式位置动词不受限（正例：04 章写「`PlaceResult` ……定义在 game.h 里」）。依据：cppreference「声明将名字引入（或再引入）到 C++ 程序中」「定义是足以使该名字所标识的实体被使用的声明」；C++ Primer「变量能且只能被定义一次，但可以被多次声明」。正文禁令见「禁用与替换」，正反对照见标识 `bg-chinese-style-cases-v1` 的知识文件「术语标签对照句」。

预防性词对（当前全书未启用，出现时按下表区分）：

| 易混词对 | 区分 |
| --- | --- |
| 形参 / 实参 | 形参是函数签名里的变量（parameter）；实参是调用时传入的值（argument） |
| 初始化 / 赋值 | 初始化在创建时给对象首个值；赋值覆盖已初始化对象的现值 |
| 重载 / 重写 | 重载是同名函数不同参数表，编译期选择；重写是派生类覆盖基类虚函数，运行期生效 |

## 禁用与替换

| 禁用 | 替换 | 原因 |
| --- | --- | --- |
| 第 N 章式编号指称（「第 1 章」等，正文与标题均不用） | 章节标题链接：用对应章节 title 作链接文字；章内页互链保持 `.qmd` 相对路径 | 读者从编号看不出章节内容，标题链接同时给出内容与入口 |
| 课（指称书的单位：「这一课」「第 N 课」「每课」「前五课」「课程」） | 章（「这一章」「第 N 章」「每章」「前五章」） | 书的单位一律称「章」，「课」是课程讲法；「语言课旁白」「课堂类比」「课堂笔记」等风格禁令标签不受本条约束 |
| 链路、四步（缩写指称） | 全书首次写全「配置、编译、测试、运行」，其后用「流程」等集合指称 | 未解释的缩写增加理解成本；反复罗列四步名形成名词堆砌；.agents 内部文档可保留「链路四步」作沟通用词 |
| 阶段（content 正文） | 具体路径 + 首次平实说明「`games/tictactoe/` 下的编号目录，每个都能独立配置、编译、测试和运行」，此后用「编号目录」「这个目录」指代 | 读者无法从未定义的统称看出含义；.agents 内部文档保留「阶段目录」作沟通用词 |
| 探针 | 井字棋工程目录；不把目录叫做探针 | 未定义术语；直接写目录里的程序能做什么 |
| 最小工程 / 最小程序 | 井字棋工程目录 | 当前井字棋不是空的工具链程序，读者页不用这个称呼 |
| 第一版 | 去版本化：范围用「井字棋」，完成用「能在终端下完一局」 | 井字棋当前只有一个可玩目录，不存在第一、二版 |
| 切片 | （已随「阶段」一并停用，见上行替换） | 与原「阶段」指同一事物；AGENTS.md 等面向编写者的文档可保留「垂直切片」 |
| 自足 | 具体能力表述（能独立配置、编译、测试和运行） | 抽象形容词，读者无法验证 |
| 悬空指代（「这条路线」「这套流程」「这三个常量」「它们」等；先行词不在同句或紧邻句，或只在代码围栏里；延伸到自测题干的「这个／哪个」——题干合上书单独可读——与节首句以「这些／这个／这一步」作话题的前指，同句列不出对象名即悬空） | 写成具体对象：井字棋学习路径、配置—编译—测试—运行、文件名、`kRows` 等标识符 | 跨段「这/该」让新人找不到所指；条文见标识 `bg-qmd-element-cases-v1` 的知识文件「内容块前后的闭环」与标识 `bg-paragraph-craft-v1` 的知识文件「代词不能代替未写出的对象」，对照见标识 `bg-chinese-style-cases-v1` 的知识文件「块后悬空指代」「定结构与定句子：代词不能代替未写出的对象」 |
| 笔记腔导航（「下面分别精读」「如下分别说明」） | 直接进入对象：目录树后直接接正文，或一句点明要看的文件名 | 像课堂笔记提纲，不像工程文档 |
| 「下一节／上一节」式预告与回指（读者正文） | 新节首句直接接住上文；章末「下一章」保留 | 正文不写小节导航；规则见标识 `bg-paragraph-craft-v1` 的知识文件 |
| 破折号夹心句（正文） | 冒号引出解释，或拆成两句 | 规则见标识 `bg-paragraph-craft-v1` 的知识文件；仅约束 `content/**` 正文，代码注释不受限 |
| 正文引语用直引号或直角引号 | 全角双引号 “ ” | 遵循阮一峰[《中文技术文档写作风格指南》](https://github.com/ruanyf/document-style-guide)标点章；仅约束 `content/**` 正文 |
| 刻意保持 / 刻意……（作者姿态修饰） | 直接陈述对象做了什么、不包含什么 | 姿态词不提供可验证信息 |
| 只可能 / 不可能来自（诊断断言） | 写成可核对的排查范围 | 「只可能 / 不可能」无法保证，读者需要的是排查边界 |
| N 段命令定义…（元计数导语） | 职责顺序导语：先…再…最后… | 计数把命令当清单，读者需要的是职责顺序 |
| 语法细节留到…（真正用到时再展开） / 本章只需认清…（渐进披露元叙述） | 直接陈述对象和结果（如「这段程序对外可见的结果只有两处：…」），延后内容保持沉默 | 把写作策略念给读者听，AI 味元叙述 |
| 「X 只包含：」排除式清单口 | 正面陈述「项目要处理这些内容」，用无序列表枚举 | 「只」把范围讲成排除，读者需要的是正面清单 |
| 读懂 | 理解 / 确认 / 查看 | 语气偏强，读者侧用中性认知动词 |
| 弄清 | 理解 / 确认 / 查看 | 讲义口开场动词，与「动手前先弄清」绑定出现 |
| 动手前 / 咱们 / 搞定 / 别慌 | 进入实现前先确认…；删除对读者的招呼语 | 讲义口语，超出工程文档语域；正向标准见标识 `bg-chinese-voice-register-v1` 的知识文件 |
| 本章规划 / 落点是 / 类型名只是设计方向 / 尚未对应可运行目录 | 直接写这一章要交出的结果，并链到已有源文件 | 这些说法讲的是章节安排，不是棋盘或落子；对照见标识 `bg-chinese-voice-register-v1` 的知识文件 |
| 务必 / 严禁 / 千万不要 / 千万别 | 直接陈述动作或可观察后果 | 命令口与恐吓口，不提供可核对信息 |
| 绝对不要 / 绝对不能 / 绝对禁止 / 绝对必须 / 绝对不行 | 写成可核对的条件或范围 | 语气「绝对」无法验证；技术词「绝对链接」不在禁列 |
| 标明 | 注明 / 写出 / 标出 | 只添书面腔，直白动词同样准确 |
| 技术基线 | 直接列出工具与用途（如「实现用 C++20，构建规则由 CMake 编写、Ninja 执行」） | 伞形词不提供信息，读者需要的是具体工具与用途 |
| smoke test（正文英文直写） | 冒烟检查加中文行为描述（如「用真实输入走完一局并正常退出」） | 术语卡外的正文用中文描述行为；「冒烟测试（smoke test）」术语卡不受限 |
| 跑通 | 执行 / 完成 / 走完（视语境） | 口语化动词，超出工程文档语域 |
| 这正是…的原因 | 正面因果：因此… / 所以… | 倒装强调式，正面因果一句可说清 |
| X 与 Y 是两个容易混淆的词（对照表元标签开场） | 先写各对象在做什么，再用一句关系句（如「配置改计划，构建按计划编译」）引出对照表 | 元标签只宣告「接下来是对照」，不提供工程信息 |
| 回到对应小节重读 | 回到对应小节对照正文 / 核对要点 | 「重读」把没读懂归给读者，指令应指向对照动作 |
| 接口桩 / 桩 | 直接写接口名称与行为边界（如「固定查询、落子与结果三个入口」；尚未实现的规则写明留待后续章节补全） | 「桩」在测试语境指 test stub，与规则 API 的先行定义混用会误导；代码注释同步停用 |
| 静态到动态 | 直接写链接方式与变更内容（如「本目录把规则核心编译成动态库」） | 压缩了静态库与动态库两个事物，读者无法核对具体差异 |
| 单独的「格子」（正文与类型注释） | 棋盘格子 | 省略了现实对应物；类型上一行与接口说明须保留棋盘锚点 |
| 单独的「空格」（正文；类型注释上一行） | 空棋盘格子 / 写清「棋盘格子」语境 | 正文禁单独「空格」；`kEmpty` 行尾注释例外写「空格。」 |
| 空棋盘格子（`kEmpty` 行尾） | 空格。 | enum 上一行已写「棋盘格子状态」时，成员行尾用简洁「空格。」 |
| 格子内容 | 棋盘格子状态 | `CellState` 记录的是棋盘格子中的状态，不写含义不明的「内容」 |
| 棋子或标记（指 `CellState`） | 棋盘格子状态 | 正文和注释都用「棋盘格子状态」；不把 `CellState` 叫做标记或棋子 |
| 规则库（组件称谓） | 井字棋动态库；其它工程按实际形态写明动态库或静态库 | 模糊称谓对不上构建产物，读者不知道指什么；本工程事实是 `tictactoe` 编译成动态库（见 `tictactoe/CMakeLists.txt`） |
| 对局交流绑定媒介（「交流只发生在终端上」式全称限定） | 写交流的形态而不写死媒介，如「一局对局通过文本交流完成：玩家输入行列，程序打印棋盘和结果」；「终端」只指称终端程序、终端界面等具体对象 | 01 章的对局约定是后续编号目录的公共前提，交流媒介随实现演进（双人终端、电脑落子、行协议），绑定媒介会把约定写死，与后续章节冲突 |
| 「固定」「遵循同一套规则」式表述（一律停用） | 章确定约定用「确定」；行为列举导语直接点名列表内容；不变量直陈事实；预定输入写「这组输入」 | 「固定」读作硬编码；「同一套」无对照物（见标识 `bg-chinese-style-cases-v1` 的知识文件「无铺垫的规则指称」） |
| 职责 / 负责 / 承担（「承担源码职责」「目录职责」「负责调用」式角色指称与角色动词） | 直接写对象保存、实现或检查什么（如「`tests/` 目录保存动态库的测试」「`Game` 判定对局是否结束」） | 角色名词不介绍内容，读者需要的是目录里有什么、对象做什么（对照见标识 `bg-chinese-style-cases-v1` 的知识文件「角色总述段」） |
| 分进（生僻动词搭配，如「源码分进三个目录」） | 放在 / 分成 / 由……组成（按语境，如「井字棋工程有四个目录」） | 非常用动词搭配，读者需要停下辨认 |
| 拗口动宾，如「得出胜负与平局」 | 直接写交付对象（如 H2 用「游戏结果」）；正文改说「落子后判定对局是否结束」 | 把两个结果硬拼成一个动宾，读者多读一层才到对象（04 章 `## 得出胜负与平局` 已更名） |
| 用实现细节当章节主叙事，如把「三连算法」当 H2 或 title | 「三连」是胜负判定的实现细节，可一句带过；H2/title 写读者面对的结果（如「游戏结果」） | 读者先要的是「对局是否结束」，算法名当主叙事会把实现细节抬成主题 |
| 用「是定义」「是声明」「……的声明」给代码实体贴标签，或成对展开声明与定义的区分（含把完整定义称「声明」） | 位置与实现写具体事实：「换算写在 board.cpp」「常量在头文件里给出值」；「定义在 x.h」式位置动词保留 | 标签句在教 C++ 术语而不是推进对棋盘工程的理解；辨析降为编辑内部口径（见「易混概念：声明与定义」） |
| 函数原型 | 函数声明 / 成员函数声明 | 「原型」是 C 风格旧称；全书用声明与定义指称 |
| 公开段 / 私有段（指类里 `public:` / `private:` 下的声明） | 写 `` `public:` `` / `` `private:` `` 下（或之后）；成员分别称「公开成员 / 私有成员」 | 自造比喻，读者对不上源码；完整 C++ 术语表见 `bg-cpp-chinese-terms-v1` |
| 公共成员（指 `public:` 成员） | 公开成员 | 「公共」与访问控制术语不一致 |
| 成员变量（作主称呼） | 数据成员 | 「变量」掩盖成员属于对象的事实；C++ 术语用「数据成员」，见 `bg-cpp-chinese-terms-v1` |
| 方法（作主称呼，指成员函数） | 成员函数 | 「方法」是其他语言称呼；C++ 用「成员函数」 |
| 字段（读者正文指结构体成员） | 成员按语义叫名字：`position` 是这一格的坐标，`player` 是落子的玩家，同一句用同一种叫法；C++ 术语仍称数据成员，不把「字段」当它的别名 | 同一句混用两种叫法，读者以为多出一种成员；「字段」只留给读者按名字读取的外部记录（07 章 JSON 键）与 03 章把一行一列填进 `row` / `col` 的那一处，03、07 现有用法不改 |
| 返回假／返回真／为真／为假（指称 C++ 布尔字面值） | 返回 `false`／返回 `true`（行内代码原样书写） | `true`、`false` 是 C++ 关键字，源码注释写「返回 true，否则返回 false」，正文用「假／真」与摘录对不上；惯例依据 cppreference 与 Microsoft Writing Style Guide，自动拦截在 `verify_content.py` |

读者页不单设路线章。正文要写学习顺序时，直接列出各章标题，不写「这条路线」。

改写案例见标识 `bg-chinese-style-cases-v1` 的知识文件。

## 禁用与替换：领域指称与旁白

领域对象的指称必须落到具体标识符与承载位置，语言机制旁白不进工程正文；各行的条文出处见对应原因列。

| 禁用 | 替换 | 原因 |
| --- | --- | --- |
| 映射 / 翻译（领域换算注释与工程旁白） | 由 A 得到 B（如「由对局玩家得到棋盘格子状态」） | 抽象动词看不出两端类型；规则见标识 `bg-comment-style-v1`「领域函数与成员注释」 |
| 位置（指 `CellPosition`） | 棋盘格子坐标 | 坐标包含行列且服务于棋盘范围检查，不能省略对象 |
| 用有符号整型承载 / 坐标字段为什么选定宽有符号 | （删除；选型论证不进工程正文） | 除 01 设计章外，工程 qmd 不讲解有符号选型；依据留在 agent 面 google-cpp-style 与 cpp-notes 类型安全章 |
| 裸 `Result`（正文把 `GameResult` 简写成 `Result`；裸 `Place`、`History`、`CellAt` 同理） | 源码完整标识符：枚举类型写 `GameResult`，成员函数写 `Game::GetResult`、`Game::TryPlace`、`Board::GetCellState` | 读者从简称回不到源码符号，不设「概念简称」层；代码块内照抄源码不受限 |
| 非法落子 | 无效落子（「非法输入」「不合法写入」按对象保留） | 「非法」暗示违规操作，落子只是无效 |
| 经规则接口读写 / 通过接口交互 | 写具体成员与动作（如「调用 `Game` 的成员读写棋盘」） | 读者需先懂架构隐喻才能还原画面；正例模板见标识 `bg-chinese-style-cases-v1` 的知识文件 |
| 枚举成员释义表 /「每个状态码对应…」释义段 | 成员含义写源码行尾注释；正文只写谁调用、如何验收、与邻章关系（如「`Game::GetResult` 返回对局的当前结果，终局判定属于回合与终局章」） | 释义列表是换排版复述代码注释，工程章正文不承载语言机制讲解；写法依据见标识 `bg-comment-style-v1` 的知识文件，对照见标识 `bg-chinese-style-cases-v1` 的知识文件「枚举成员释义列表」 |
| 状态不反向依赖调用者 / 动作只从外部进入 | 写可观察边界（如「`Game` 不调用终端程序，也不读键盘」） | 同上；隐喻句删掉后说不出约束什么 |
| 层名（终端适配层、规则核心、规则接口）首次出现无定义 | 首次出现用一句可观察行为定义（如「规则接口是 `Game` 暴露的成员函数」），图节点用日常说法 | 未定义的层名读者无法对应到磁盘上的文件与函数；图后列表再对上术语 |
| 公共头（含「公共头文件」「公共头 board.h」式省略） | 点名具体对象：文件名（`board.h`）、「动态库 `include/` 下的头文件」、「该头文件」；目录树注释写全「库对外头文件」 | 「公共头」是省略缩略，读者无法核对指称，正文直接写清对象；「库对外头文件」与访问控制的「公开成员」无关联，勿混用 |
| 公共值类型 | 值类型，并点名文件或清单（如「`board.h` 里的尺寸、坐标和格子状态」） | 「公共」前缀不提供信息；指称靠具体文件与清单 |
| 公共定义（反复总称） | 首次出现列清单（哪些定义、各是什么），后文用「这些定义」或文件名指代 | 反复总称让读者回头翻找；一次列清后用具体指称 |
| 公开头文件（目录树行尾注释） | 库对外头文件 | 完整职责短语；「公开」易与访问控制混淆 |

## 禁用与替换：压缩隐喻与电报体

| 禁用 | 替换 | 原因 |
| --- | --- | --- |
| 契约（读者正文） | 点名文件与定义（如「`board.h` 供终端程序与测试读同一组棋盘尺寸」） | 「契约」是编写者沟通用语，读者需要的是具体对象；.agents 内部文档可保留 |
| 契约链 | 写清头文件里有哪些定义、谁读取、谁调用（如「终端程序打印棋盘和测试遍历棋盘格子都读这三个定义」） | 压缩隐喻，读者对不上现实对象；合并围栏导语写「同一组递进定义」 |
| 状态外壳 | 写具体对象（如「棋盘格子的存储与结果状态码」「`Game` 保存的对局结果」） | 压缩隐喻，读者无法核对「外壳」指什么 |
| 地基 | 写可观察的前置条件（如「规则接口稳定后，AI 才有可以调用的入口」） | 压缩隐喻，前置条件要可核对 |
| 执行纪律 | 写具体约束（如「目录门槛与验收顺序」） | 压缩隐喻，「纪律」没有可验证内容 |
| 闭环 | 写具体流程或结果（如「从开局输入到正常退出的一局」「终端双人完整对局」） | 多数出现无先行词，读者找不到所指；确有先行词也优先展开成流程 |
| 消费（读者正文） | 读取 / 调用 / 按…编译（写清谁对什么做什么，如「构建按计划编译源码」） | 压缩隐喻动词，掩盖真实动作；.agents 内部文档可保留「谁消费」作沟通用词 |
| CLI 打印（及同类电报省略） | 完整主谓句（如「终端程序打印棋盘」） | 缩写作主语、谓语缺对象，读者要自行补全动作与对象 |

## 通用规则

- 一个概念全书只用一个词；同义词不得轮换（最小工程与探针、编号目录与阶段）。
- C++ 关键字与字面值（`true`、`false`、`nullptr` 等）在正文指称时一律用行内代码原样书写，不写中文译名；叙述布尔概念（如「布尔值」）可用中文词。
- 术语首次出现处就近放术语 callout，规则见标识 `bg-chapter-structure-v1` 的知识文件；本表只管「用哪个词」，不管「怎么解释」。
- 标题不使用正文之后才解释的术语；标题里的词必须是读者此刻已认识的或字面自明的。
- 标题风格依据：[华为《中文技术文档写作风格指南》](https://zh-style-guide.readthedocs.io)要求描述操作任务的标题用动词加主题词、同级结构一致；[MDN Writing style guide](https://developer.mozilla.org/zh-CN/docs/MDN/Writing_guidelines/Writing_style_guide)要求同层级标题句式一致；[Diátaxis](https://diataxis.fr)主张教程用动词领起的任务式标题。
