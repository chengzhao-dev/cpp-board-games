# 段落、列表与衔接的结构规则

本文件规定 `content/**/*.qmd` 的段落长度、列表选择、加粗使用、段内同义控制与段间衔接（依据阮一峰[《中文技术文档写作风格指南》](https://github.com/ruanyf/document-style-guide)段落章、文本章，强制执行）。各条细则多有起因案例：段落规则起于 02 章引言把七个概念压进一段；凑字数禁令起于「文件只有 14 行，真正执行的代码只有 3 行」式统计句；否定式预告禁令起于 01 章「程序不提供电脑对手」；伪标签冒号禁令起于 03 章散文词条腔。通用降噪 how 见 `writing-quarto` 技能 `references/zh/writing-howto.md`；正反对照见标识 `bg-chinese-style-cases-v1` 的知识文件。

## 适用范围

- 管 `content/**/*.qmd` 与根 `index.qmd` 的读者正文：段落形态、列表与加粗、段内同义堆叠、段间衔接与小节标题对齐。
- `.agents/**` 与源代码注释不套段落形态，但句子级判定见标识 `bg-chinese-quality-v1` 的知识文件载体适配表。
- 页面骨架（引言、六段块序列）与篇幅 token 由标识 `bg-chapter-structure-v1` 的知识文件约束；小节盒子密度见标识 `bg-section-density-v1` 的知识文件。

细则次序：段 → 句 → 列表 → 加粗 → 拆分 → 同义控制 → 衔接 → 块链。

## 段落规则

- 每段只有一个主题或中心句；中心句放在段首，后面的句子都服务于它。
- 一段一对象：同一段不夹杂两个并列对象，对象切换必须新起段；配套列表只服务本段对象，不得跨对象拼装列表项（对照见标识 `bg-chinese-style-cases-v1` 的知识文件「单段混并列对象」）。
- 段落不超过 7 行，最佳 4 行以内；超过即拆或改列表。
- 多个独立概念禁止塞进同一段：承接、目标、范围边界、阅读顺序、术语解释各归各段。
- 段落之间用一个空行分隔，段首不缩进。
- 代码块后的逐条讲解用无序列表：每项格式为「行内代码标识符 + 全角冒号 + 一句职责」（如 `` `enable_testing()`：开启 CTest。``），描述从简，全页标记方式一致；列表前保留一句引言交代工程语境，列表后需要时补一句收束或尾置 Callout。有先后顺序的排查步骤仍用有序列表；块前导语用职责顺序（先…再…最后…），禁用「N 段命令定义」式元计数（规则见标识 `bg-chinese-style-cases-v1` 的知识文件）。
- 删段还是拆段，先按本文件「一次对话」数这段有几件内容：写不出段中心或与导语、围栏注释同义就删整段，不在句内顺手改措辞。

### 拆段触发表

段落拆分不只按行数硬切，命中下表任一信号即拆段或改形态（列表 / 代码 / 图）：

| 信号 | 动作 |
| --- | --- |
| 段内出现第二个互不依赖的对象或主题 | 新起段；新段首句接住上段对象（衔接见本文件「段间」） |
| 段内出现「话题标签：解释」词条腔，或两个以上互不依赖的中心并列推进 | 按「拆核四步」判关系：递进同段衔接推进，并列拆段；词条腔改完整主谓句（见「散文伪标签冒号禁令」） |
| 一段同时承担「承接上一章」+「本章交付物清单」+「源文件位置」+「摘录声明」 | 章引言不拆段：按标识 `bg-chapter-structure-v1` 的知识文件并为单段或一段 + 列表，摘录声明整句删除；其他段落按职责拆段，交付物多项且需扫读 → 列表，禁止顿号串进一句（目录式堆砌禁令见标识 `bg-chinese-style-cases-v1` 的知识文件） |
| 超过约 4 行舒适带、或逼近 7 行 / 篇幅 token 上限 | 先找逻辑边界拆，禁止为凑行数在句中腰斩 |
| 连续 ≥3 段纯散文且无列表/代码/图 | 改「一句中心 + 列表/代码/图」（见标识 `bg-chinese-quality-v1` 的知识文件「句序与段落形态」） |
| 满篇单句段、句间无衔接 | 合并为连贯多句段，或改成列表 |
| 逗号、句号后分句换新主语、新事实，无回指、无承接词 | 按过简断裂改写：收敛主概念后用给定信息衔接（见「过简断裂禁令」） |
| 一段出现第 4 个互不依赖的主概念 | 拆下一段或改「一句中心 + 列表」（见「概念负荷」） |
| 一句多中心、分号串两事、>40 字多动作 | 先拆句，再判是否还需拆段 |

假拆禁令：不为「段数好看」把同一中心拆成两段同义反复（相邻同义合并仍适用）；不为对齐列表而去拆段或填第二中心；章引言多中心时**并段或改列表**，禁止拆成两个散文段（形态契约见标识 `bg-chapter-structure-v1` 的知识文件「六段块序列」）。

## 罗列短句成段禁令

- 禁止把多个各自成句、互不衔接的罗列式短句机械堆进同一段：每句单看成立不等于段落成立，句号串联的清单式段落让读者在句间自行补关系。
- 确认一个中心主题后，围绕段首中心句用衔接关系（先…再…、…时、一旦、则）把相关动作组织成连贯的完整句；单句长度与拆句触发仍守「句子规则」，不为连贯写超长句。
- 真正并列、需要扫读的项改用列表（见「列表选择」），不为段落感做伪连贯。
- 判定信号：段内句子逐句可删、互不引用；句间没有承接、因果或时序词；逐句像要点罗列。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「罗列短句成段」。

## 过简断裂禁令

逗号、句号把一句话切开后，下一分句必须满足 **given-new** 之一，否则为过简断裂：

- 复用上一分句的对象：代词、同名，或「其中」式回指；「这个／这些」只回指同句或上一句已经写出的名词（见「代词不能代替未写出的对象」）；
- 写出关系：因此、这样、然后、用来、以便等承接词。

禁止新主语＋新事实且与上一分句无回指——每截单看都合法、段却不成篇，读者要自己补「因为／所以／其中」。与「罗列短句成段」的分工：那条打**句号清单**（多个各自成句的短句堆成段），本条打**逗号切断**和**过简两句各丢一个事实**（如「对象 → 文件位置 → 入口个数 → 私有存储」逐截并列）。时序句「进入目录，执行入口」合法：后一分句接住前一分句的动作。

判定信号：逗号或句号后的分句引入新的主语或新的行内代码标识，且无回指词、无承接词。改写时按「概念负荷」收敛主概念，用给定信息衔接次要展开；对照见标识 `bg-chinese-style-cases-v1` 的知识文件「过简断裂段」。

## 代词不能代替未写出的对象

「这个／这些／这一步」类代词只在**同句或同一节的上一句已经列出对象名**时合法；对象名只出现在后面的 `###`、只出现在代码围栏、或只出现在另一道自测题里，都算没有先行词。判定以整篇 qmd 为范围，按标题切开后再看代词前面有没有对象名，一句摘出来不能判。段内回指不在此列：上一句已写出「数量」，下一句写「这个数量」仍然合法（given-new 的复用分支）。

- **自测题干**是合上书的一问，只看本题题干：禁止「这个、那个、这些、那些、哪个、哪些、哪一句、哪一层、哪一行、哪一块」，先写出被问的对象，再用「是多少、会不会、A 还是 B」来问；「什么」允许——它在要一个名字或一句文字，不是指上文没出现的东西。答案折叠里的回指不扫。
- **节首句**不得用代词把后文才展开的内容提前捆成一包：节首以「这些／这个／这一步」作话题、同句又没有列出对象名，即失败。「这一章」「下一章」「这一节」指书的单位，是固定说法，不在此禁令内。
- **已经逐个写出名字之后的回指**仍然合法：如前文小节已写出 `Player`、`Move`、`PlaceResult`、`GameResult`，后文「这些类型由类 `Game` 的四个数据成员使用」保留。

条文与自动检查见 `writing-quarto` 技能 `scripts/verify_content.py` 的整篇题干/节首检查；工序挂点：定结构改自测题，定句子改节首与句内代词；对照见标识 `bg-chinese-style-cases-v1` 的知识文件「代词不能代替未写出的对象」。

## 概念负荷

- 主题仍一段一个（与「一段一对象」同向）；该主题下最多 **1–3 个主要概念**——读者读完必须能复述的独立对象或判断。
- 允许若干**次要概念**只服务主概念：出处、约束、可见性、与上一句的关系；次要概念不得另起主语当新主概念。
- **主次判定**：删掉该信息后，段首中心句是否仍成立？成立 → 次要或应删；不成立 → 主要。文件位置、`public:` 段名、入口个数默认是次要；「类 `Game` 编排一局」「棋盘收在对象内部」若本段要讲接口与存储分工，则「接口／内部存储」算两个主概念，须用给定信息衔接，不得并列甩出。
- 超过 3 个主概念：拆下一段，或改「一句中心 + 列表」；禁止用逗号、句号把第 4 个主概念塞进同一段。
- 普通自然段的 token 带与豁免见标识 `bg-chapter-structure-v1` 的知识文件「分层上限」；低于下限时补的是衔接与必要次要概念，不是凑字数句（「凑字数禁令」同时成立）。

## 句子规则

- 单句一般不超过 20 字，40 字以上不可接受；一个句子出现三个以上动作或多个括号时拆句。
- 正文不使用破折号夹心解释：解释用冒号引出，或拆成两句；冒号的合法场合收窄见「散文伪标签冒号禁令」。
- 用主动语态、肯定语气和陈述句；不用感叹句和双重否定。语域判定与口语腔、公文腔的正向标准见标识 `bg-chinese-voice-register-v1` 的知识文件。
- 不写否定式预告：「程序不提供电脑对手」「这一章不实现 X」式否定句一律不写；正文只正面陈述当前程序做什么，后续章节才会出现的能力保持沉默，即使当下为真也不写，否则后文补上该能力时句子失效。范围声明同受此限：章引言只写本章要交出的对象，不点名后续章节的流程（如「不在这里配置、编译、测试或运行」）——即使是否定形式，也把后章内容提前搬进读者视野，超出本章范围。下一章预告同属后章内容，只写在章末本章回顾，引言保持沉默。

## 凑字数禁令

信息密度以读者判断所需为准，不以篇幅为准。篇幅超限时先删下面这些句式，再考虑拆页；以下句式在 `content/**` 正文一律禁止：

- 统计性凑句：「文件只有 X 行」「真正执行的只有 X 行」「一共只有 X 个」这类数字统计。数字本身影响读者判断时（规模超出预期、需要据此决定读法）才允许出现，纯描述规模一律删除。
- 导航复述段：「接下来先看…再看…然后…最后…」式段落，与 `##` 标题结构重复；读者从标题自身即可获得导航。
- 同义反复：同一事实在承接句、代码块 filename、树内注释、列表项中重复出现时只保留一处。相邻段落各自换一种说法讲同一事实（如「程序对外可见的结果」与「自动化检查针对这些结果」）时，合并为一段，不保留两段；删段后主线仍闭合时，不另写替身长论（改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件）。同一禁令延伸到代码围栏：块内注释已写明的信息，块后正文不再同义复述（对照见同文件「块后复述注释」）。同一禁令再延伸到公开接口旁白：禁止「接口清单压缩段」——把私有成员、公开成员名单、`const`、`[[nodiscard]]` 等压进同一段；定稿为场景 → 代码 → 块后只补注释未写的工程信息（对照见同文件「接口清单压缩段」）。
- 判断标准：一句删掉后主线闭环不受影响、且答不出「删掉它读者会做错什么」，默认删除。

## 简洁边界

简洁的上界是不丢失理解所需的信息。为省字而砍掉动作、对象或顺序的电报式省略句一律禁止：

- 禁例：「先自己回答，再展开核对。」——读者不知道怎么算回答、核对什么。改为完整指令：「先不要展开答案，试着自己把回答完整说出来，再展开对照。说不出来的部分，回到对应小节对照正文。」
- 指令与提示句写全三要素：动作（做什么）、对象（对什么做）、顺序（先做什么后做什么）。
- 并列的量名各自带上被计量的对象：「行数、列数」不能配一个光秃的「总数」。对象必须留在引入该名字的短语里；围栏代码注释和隔着代码块的后文都不算补上（03 章 `kCellCount` 的导语因此写成「棋盘格子总数」）。
- 拿不准一句是否过省时写成完整句；多出的字数由篇幅预算吸收（见标识 `bg-chapter-structure-v1` 的知识文件「分层上限」），不由读者的理解力吸收。

## 列表选择

- **无序列表**：并列概念、范围边界、要点枚举——各项之间没有先后或因果；代码块后的逐条讲解也用无序列表（格式见「段落规则」）。
- **有序列表**：有先后顺序的步骤或链路——执行顺序本身就是信息（如配置 → 编译 → 测试 → 运行）。
- 列表项结构平行：起首用同类的词（都是名词短语，或都是动词短语），长度相近。
- **列表字数带**：同一列表各项保持视觉齐长，避免扫读节奏断裂。计量：引导词汉字数、冒号后汉字数（行内代码按标识符计）。失衡判定：冒号后最长 ≥ 最短 × 2，或引导词相差 ≥ 4。改写顺序：删长项多余中心 → 拆多中心 → 过短项按简洁边界补全 → 停止。豁免：出错原因/正确做法；有序步骤；着陆页卡片。列表齐长服从句段主规则，禁止为对齐凑字或拆段填第二中心。
- 列表项起首用加粗引导词标记中心语，读者扫读时先看到分类再决定是否细读；关键词取同类词（如「显示棋盘」「读入坐标」），并按对象的发生顺序排列，读者扫读即得顺序与内容。
- 行为或规则枚举项用「**动词短语引导词**：完整句」格式：引导词命名本项的中心动作（如「**显示棋盘**」「**判定对局结果**」），冒号后保留完整中文句，写全动作、对象与结果。引导词是扫读索引，不替代句子信息，不为省字把冒号后压成电报短句（对照见标识 `bg-chinese-style-cases-v1` 的知识文件）。
- 解释并列名称的引导词列表放在首次使用这些名称的代码块或目录树之前：读者先经列表认识每个名称，再看结构展示；禁止把解释压到块后，读者会带着未解释的名称读块。名称本身用读者可核对的具体形态（如「井字棋动态库」），不用模糊统称（术语依据见标识 `bg-terminology-v1` 的知识文件）。
- 并列成员一次列全：目录、组件等并列对象（含 `build/` 这类构建生成的目录）并入同一个引导词列表，先列全再展示目录树等结构；列表之后不用段落补列遗漏的成员（对照见标识 `bg-chinese-style-cases-v1` 的知识文件「角色总述段」）。
- 三项以上、或每项内含解释的信息优先成列表；只有两项且能写进一句的保留正文；只有一项时不设列表，写进正文（节内无代码块或列表承接时，整节收成一句）。
- **构造后的成员并列成列表**：同一句或同一段用顿号、逗号并列三个及以上数据成员、而且各项状态不同时，改成引导词列表。引导词用读者已认识的对象名，冒号后只写这一项的初始状态；各项共享的一条规则（谁能读、谁能改）留在列表后的一句，不拆进每一项。这和「枚举取值不在正文做释义表」不冲突：枚举成员的含义仍留在源码行尾注释，这里列的是构造之后每个数据成员的状态，不是把枚举成员再解释一遍。
- **公式不拆列表**：公式按「定义 — 原理 — 代入」三层讲清，不把每一项写成「公式项：一句职责」列表项（对照见标识 `bg-chinese-style-cases-v1` 的知识文件「公式与换算讲解段」）。版式：定义就是围栏里与源码相同的那一行（如 `return` 行），导语只交代对象与出处；原理写「每行多宽、跳过几个整行」的条件，第 0 行写出具体下标；代入只给数字，单句成段低于 token 下限时留在原理段末尾，不凑字数。禁止把取值、跳过整行和得数写进同一句，禁止把公式塞进导语的反引号，也禁止正文另排 `$$` 或行内数学模式：`verify_content.py` 对围栏外的数学模式判失败。

## 加粗使用

- 加粗只用于列表项或段首的引导词（中心语前置），标记结构，不强调情绪。
- 同一页加粗不成片：一段正文内至多一两处加粗，连续多句加粗等于没有重点。
- 标题不加粗（层级已由 `##`/`###` 表达）；行内代码与加粗不叠加在同一对象上。

## 拆分判据

读到一句话同时回答两个问题时必须拆分，典型信号：

- 一段里出现两次以上括号补充；
- 读者无法用一句话复述这段在说什么；
- 段落同时含「结论 + 原因 + 反例 + 后续动作」中三项以上，拆成按职责分的短段。

## 多问一答拆分

自测答案或正文若同时回答两个以上独立问题，按「引言 → 按问拆段或引导词列表 → 收束」组织，禁止把多个问题压进一段：

- **引言**：一句点明对象之间的关系（如「配置和构建是两件不同的事」）。
- **展开**：每个问题一段，或用加粗引导词列表（`**配置**：…` / `**构建**：…`）；两项且能写进一句的仍可保留正文。
- **收束**：一句写出操作后果或因果（如「改了 CMakeLists.txt 要重跑配置」）。
- 典型禁例：把「谁做配置、谁做构建、何时重配」压进同一段；改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件。

## 段内同义堆叠禁令

一个自然段围绕中心句推进时，同一机制至多给一句展开；再补一句换说法复述同一机制即为段内同义堆叠，主次不清，命中即删辅句或合并。判定信号：

- 段内两句主语不同、谓语同义（如「长度用常量固定」与「长度由常量在编译期确定」），删掉任一句主线仍闭合；
- 中心句之后连续多句都在解释同一个词，没有引入新机制、新对象或新边界；
- 句间只靠「也就是说／换句话说／即」类复述连接，没有因果或递进。

改写形态：中心一句 + 至多一句机制 + 可选一句桥接（引出下一段对象）；需要更多细节时下沉列表、代码块或后续小节，不在段内堆叠。

豁免与边界：

- **公式递进豁免**：「定义 — 原理 — 代入」三句各答一层，是递进不是堆叠（见「列表选择」公式条）。
- **简洁边界反向保护**：删辅句不得造成电报省略；动作、对象、顺序三要素仍写全（见「简洁边界」）。
- **跨章固定表述不复述判重**：「九个棋盘格子」这类全书统一表述在各章按需出现，不受「同一事实只讲一次」限制。
- **自测答案豁免**：答案可对照题面复述一次再展开。

与「同义反复」（凑字数禁令）的分工：同义反复管跨位置重复（承接句、filename、列表项同讲一个事实）；本条管同一段内的同义展开；命中任一即删。

## 散文伪标签冒号禁令

散文自然段禁止「短名词话题 / 行内代码话题 + 全角冒号 + 解释」的词条腔（如 `` `Foo`：……``、`数组长度写成 X：……`）；这是列表项 `` `id`：职责 `` 的形态落进散文，版式像词条、读感怪异。命中改写成完整主谓句，或改真列表项。

冒号只保留两种合法场合：完整句引出紧随其后的列表、代码围栏或图（如「约定如下：」「定义在 board.h 里：」）；列表项引导词之后。其余散文冒号一律按词条腔处理。

判定信号：句首或句中出现「≤12 汉字话题或行内代码 + 全角冒号」，且该冒号没有引出列表/围栏/图。

豁免（不得误杀）：列表项（含 `` `enable_testing()`：开启 CTest。``）；列举/代码/图导语（下一块是列表、围栏或图）；终端与协议字面量（如 `对局结果：X 获胜`）；表格单元格与代码注释。

与「破折号夹心改冒号引出」（句子规则）的关系是**收窄**：破折号解释改冒号时，只允许改成上述两种合法场合，不允许改成散文词条腔。

## 拆核四步（多核混段的拆段方法）

同一自然段并行推进两个以上互不依赖的中心即为多核混段，读者分不清本段在讲什么。写作或改写涉及捆绑概念（如「长度 / 容器 / 坐标换算」）时，强制走四步：

1. **拆核**：列出本段必须交代的独立核（例：长度常量的含义；使用该长度的容器；行列到下标的换算）。
2. **判关系**：核是「属性 → 承载」递进还是并列。递进可同段用衔接推进（如长度定型 → 容器选用该长度，先长度后容器）；并列必须拆段。
3. **一句一核推进**：每句主语明确（长度 / 数组 / 换算），不夹第二个核的细节；禁止伪标签把两核糊成词条。
4. **衔接与次序**：段内用「因此 / 所以 / 这样」接住上句对象；换核新段时首句点名上段产物（例：先讲 `kRows`、`kCols` 给出合法范围，新段首句写「范围确定后，坐标检查才有了依据」；递进同一核的展开留在同一段，拆段判据见「句内骨架」）；若某核由后续小节专讲，本段只留一句明确桥接或整句下沉为其首句，禁止悬空预告。

拆段触发表已收录「词条腔 / 多核并列」信号行；改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「散文伪标签冒号与多核混段」。

## 一次对话

面向读者的一次说话只推进一件内容：可以是一句，也可以是紧挨着的两句，但必须沿用同一套说法。对话不是新的切分单位，也不是标题层级：判定挂在定段落和定句子上——定段落先问这段有几件内容、决定删或拆，定句子才改措辞。脚本不统计对话数；自动失败只有下面四条判定里的三类高精度信号（见「机械闸」）。

- **一件内容**是读者能单独复述的一件事，例如「这次有没有写进棋盘」。两件内容用顿号或逗号放进同一句，再补「是两个不同的问题」「用两个枚举分开回答」，就是把两次说话写成一次；读者读到围栏前，要回头拿开头的问题去猜后面的编号各指哪个。
- **写不出本段中心，或这句与导语、围栏注释同义，就删本段**，不另写替身句。要换对象必须另起段，而且该对象得是本节正在讲的，不能提前交给后文才展开的成员或函数（如 04 章的 `current_player_` 与 `Game::TryPlace`）。
- **后文还讲这件事时，沿用开头的说法和类型名**，不改口成「接着看」「第一个枚举」「第二个枚举」。序数可以指真实位置（03 章「第一个格子」），不能用来给前面并列过的类型、成员、入口、步骤重新编号；格子、行、列和「第二次写入」这类真实次序豁免。改写是每件内容紧挨它自己的围栏，说法从开头保持到围栏。
- **数量词和「这些」必须对着紧接着的名单或围栏**：写「四个入口」「覆盖四类」，下一块就要列出四个名字或四类场景；对不上就改成点名对象（03 章写「读写用 `IsValidPosition`、`GetCellState`、`PlacePiece` 和 `IsFull`，`Board()` 只建出空棋盘」，不再说「只留四个入口」）。
- **一句里的全称（全部、所有、唯一）读完下一句仍然成立**；被下一句否定就改范围或删除。**类型接线**（两个逗号分句各自是「成员叫法 + 使用 + 某一章的类型」）若两项都已出现在紧邻导语和围栏里，整段删除，不走「拉链句」的推迟、拆句、一项一行。

条文与自动检查见 `writing-quarto` 技能 `scripts/verify_content.py` 的句子模块切分；工序挂点：定段落删段或拆段，定句子改措辞；对照见标识 `bg-chinese-style-cases-v1` 的知识文件「定段落：类型接线段整段删除」「定句子：两次说话拆成一次对话」「定句子：数量词对着下一块点名」。

## 句内骨架

写作工序的定句子步骤。本条管**设计说明**（为什么这样存、这样判定、这样分工）——一段解释代码决策的正文；步骤句、列表项、自测导语不套这条。它不与邻条重复：拆核四步管多核怎么拆段，过简断裂管分句之间的衔接，本条管**分句各自担任什么角色、按什么次序排列**：

- 每个分句只担任一种角色：可观察事实、不变约束、因此作出的选择。次序固定为**事实 → 约束 → 因此选择**；选择句不得出现在依据之前——先写「长度取常量」再补「九个格子」，读者要把因果倒过来读。
- 光有回指不够。后一分句若不是同一谓语的延续，必须写出「因此 / 所以」；删掉关系词后读者仍要自己补因果，判废。可观察事实（「棋盘一共九个格子」）可以在前，读者据此才知道选择成立。
- 「是井字棋规则的一部分」这类只贴类别、不改变下一步的分句删除：它不回答「所以代码怎么办」。
- 一句里用逗号甩出的独立判断，最多留「事实，约束」或「约束，所以选择」一对；第三个判断另起句或删除。单句仍守「句子规则」的 40 字与一动作上限。
- 递进同一核不拆段复述：长度和装下它的数组是同一个核，同段用「因此」接住，不另起一段再说一遍「正好装下」。
- 后续小节专讲的对象，本段不写「由 X 完成」：换算如果由下一小节专讲，本段不提前交接（「换算由 `ToFlatIndex` 完成」）；块内注释或下节首句已经说出的职责，整句删除。
- 与「对象先行」（标识 `bg-chinese-quality-v1` 的知识文件「句序与段落形态」）同向：先写读者能看见的对象（九个棋盘格子），再写名字（`cells_`、`kCellCount`），不用标识符开句。

判定信号：设计说明句里选择先于依据；逗号甩出第三个独立判断；分句只贴类别不改变下一步；删掉关系词后因果要读者自补；段末提前交接后续小节的对象。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「句内骨架：先依据后选择」。类型接线句与被下一句否定的全称按本文件「一次对话」判删留，不按本节改写句内次序。

## 拉链句

一句话里把两组对象两两配对（左组对右组），删掉任一配对，剩下的配对仍能单独成立，原句就是拉链句：读者要按顺序把左组一一配到右组，且两个配对共用同一个判据（如「棋盘格子在哪、上面是什么，分别交给 `CellPosition` 和 `CellState`」——删掉任一配对，另一配对照样成立）。它不是一个中心，也不是工序链；现有的「一句一动作」「不提前交接」拦不住它，因为它把两件事合法地写进了同一句。旧「分号双主语」豁免（两个行内代码主语用分号并列，如「`CellPosition` 定位一个棋盘格子；`CellState` 保存格子的状态」）已废除：这类分号句通常就是拉链句，按本节改写。

三条改写，按顺序选，停在第一条适用的：

1. **推迟**。`##` 有 `###` 时仍按顺序点名子节，但至多两句、一句只点一个对象，只用读者已经看见的白话，不点后文才定义的类型名。类型名留在该 `###` 的块前导语里，紧挨声明。
2. **拆句**。两个都能单独成立的观察分成两句。后句用「因此 / 所以 / 接着」接住前句对象。禁用「分别交给 / 各说一层 / 分别是」。
3. **一项一行**。同一对象的三项及以上取值或属性，放进列表或表格，一项一行。列表项内部也不再用「分别是 A、B 和 C」再拉一次链。

与相邻规则的分工（避免改到不该改的句子）：

- **工序链保留**：后一步用到前一步的结果，用「先 / 再 / 最后」串的是同一条操作（如 05 章「先执行验证脚本，再看显示格式，最后输入坐标」），不按拉链改写。
- **同物两处可留一句**：主语只有一个，只是指出声明文件和实现文件；句中再塞第二个任务（接受、拒绝、判定终局）时，第二个任务拆掉。
- **回顾保留 1–2 句**：回顾只收束本章已经做成的一件能力，不用顿号把三个独立交付物再拉一遍，也不改成列表（规则见标识 `bg-chapter-structure-v1` 的知识文件「六段块序列」）。
- **块后复述仍删**：围栏注释已经写出的字段职责，不在块后再拉链一遍（对照见标识 `bg-chinese-style-cases-v1` 的知识文件「块后复述注释」）。

判定信号：同一句里用「分别交给」「各说一层」「分别是」连接两组对象；或一句内两组配对删掉任一仍成立。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「拉链句」；「分别交给」「各说一层」由 `check_zh_lint.py` 对读者正文硬拦。类型接线句是本节的例外出口：两项都已在紧邻导语和围栏出现时整段删除，不走推迟、拆句、一项一行（见本文件「一次对话」）。

## 章级：总—分—总

- **总起**：无标题引言承接上一章并给出本章任务，规则见标识 `bg-chapter-structure-v1` 的知识文件「六段块序列」。
- **分述**：正文 `##` 序列沿一条主线递进展开，每个 `##` 是一个可验证结果。
- **收束**：本章回顾照应引言提出的任务；首尾照应要求回顾能对上引言的承诺，不引入新概念。回顾的句数、句式与承接正文的要求以标识 `bg-chapter-structure-v1` 的知识文件为准。
- 已有源文件的章要补齐自测与回顾。没有源文件的章不进目录。

## 节内：递进式为默认，并列式处理枚举

- 有先后或因果的内容用递进式展开：概念 → 示例 → 操作 → 验证（顺序依据见标识 `bg-chapter-structure-v1` 的知识文件），段落顺序与执行顺序一致。
- 无先后关系的要点（边界清单、原则枚举）用并列式：并列内容优先成列表，不强行排序成递进（列表选择规则见本文件「列表选择」）。
- 同一小节内不混用：一条主线递进到底；并列枚举整体作为一个环节嵌在递进中。

## 段间：过渡句只在话题切换处

- 需要过渡的位置：段落话题或对象发生切换时（上一段讲 A 命令，下一段讲 B 命令；前一小节配置，本节运行）。同一段内句子推进、或下一段直接继续当前对象时，不加过渡。
- 形式：一句，放在新段段首，先接住上文（点明与上段的关系或结果），再引出本段中心。范例（02 章注册冒烟测试节首句）：「可执行目标之外，同一份构建规则还注册了本章唯一的自动化检查」——前半句接住上文的可执行目标，后半句引出新对象。
- 边界：过渡句服务主线判断，不复述标题结构。「接下来先看…再看…然后…」式导航复述段仍然禁止（见「凑字数禁令」）；`##` 开头承接不超过 2 句、`###` 不超过 1 句（规则见标识 `bg-chapter-structure-v1` 的知识文件「六段块序列」）。
- 相邻小节的首句同时是上一小节的承接位：写完上一小节结尾后检查下一小节首句是否接住读者，不在小节尾部再补预告句（与凑字数禁令同源）。
- **读者正文禁写「下一节／上一节」**：`content/**` 正文不得用「下一节…」「上一节…」预告或回指小节，衔接靠新节首句接住上文；章末的「下一章」保留。本文件讨论衔接位置时引用的这两个词是规则描述用语，不是允许正文照写的句式（`check_zh_lint.py` 对读者 qmd 与 agent 文档判失败，紧贴引号或反引号的术语引用豁免）。
- 相邻段落同义合并：相邻两段各自换一种说法讲同一事实时合并为一段，由后段的机制或结论接住前段的对象；合并后其余段落、列表和 Callout 不得再以第三种说法复述该事实。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件。
- 相邻两段不得各成独立说明书：第一段讲工具、第二段讲目录而彼此无衔接时，第二段段首要接住第一段的对象（工具基线 → 这些工具在编号目录上如何使用）；只删不接，两段仍然是两个条目。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件。
- **外链默认零条；禁止突兀依据句**：块前导语只引出紧随的代码块或图。cpp-notes 外链若保留，必须单独成句放在工程点讲完之后（小节末尾置「若要系统阅读…」），且禁止「写法依据见 / 依据见 / 机制见 / 选型见 / 承诺见 / 用法见 / 陷阱见」挂链。导语用分号挂外链是多中心句的典型现形，判定口诀见 `writing-quarto` 技能 `references/zh/writing-howto.md`；改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「导语多中心与分号挂外链」「突兀跨仓依据句」。
- 目录树后的正文不复述树内行尾注释：树注释已逐文件交代职责，再列一段「A 组件、B 目录与 C 目录各自带 CMakeLists.txt」是把树翻译成说明书目录。树注释覆盖职责时删复述，至多保留一句组件间的组合关系收束；树后保留的一句读法说明直述机制（「文件名给出位置，行尾注释说明职责」），不写「X 回答 A，Y 回答 B」的问答式并列——那是给工具看的格式规格，不是给读者的解说；改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「目录式堆砌」与「树注释点名文件与问答式读法句」。注释没写过的新信息，主语仍须是本节标题的对象；换成工具配置、依赖方向或「不参与 / 不依赖」类边界，即使树注释没写过，也删除或下沉，不得靠「新工程信息」留下（改写对照见同文件「树后换对象收束句」）。
- 同一禁令延伸到代码围栏：围栏内 `//` / `#` 注释已写明的意图，块后正文不再同义复述，块后只写注释没覆盖的新工程信息（对照见标识 `bg-chinese-style-cases-v1` 的知识文件「块后复述注释」）；单段夹杂两个并列对象时按对象拆段，新段段首补一句衔接（对照见同文件「单段混并列对象」）。
- **多代码块小节先判一次只摘一块**：同一 `##`/`###` 内出现两个及以上同源代码围栏时，先看是否是紧邻常量与其直接使用行——常量紧接着被下一行使用时才放在同一个围栏；类型定义和后一步使用它的函数是两步，即使函数用到该类型也分成两块，一个围栏只放正在讲的那一个声明或函数（判定见标识 `bg-qmd-element-cases-v1` 的知识文件）。每个围栏前只留一句完整导语（对象 + 谁调用或做什么），禁止「块前半句 + 块后半句」拆成两段讲同一常量或同一类型，可合并的块前与块后并成块前一句。对象切换仍可新起段，但每段最多「一句 + 一个配套块」，块后再挂多行自然段复述或延伸一律禁止。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「多代码块一句导语」「递进片段合并」。
- 表格与对照表前必须有承接句：先写各对象在做什么，再用一句关系句引出表格（如「配置改计划，构建按计划编译」），禁用「X 与 Y 是两个容易混淆的词：」式元标签开场；表后一句给读者该取走的结论（块级闭环见标识 `bg-qmd-element-cases-v1` 的知识文件）。

## 小节标题与正文对齐

- 小节标题、首句和正文指向同一个动作或对象；标题说「做什么」，正文就只写怎么做、看到什么算成功。块后许可的新信息不豁免标题对齐：树后或块后补写的内容，主语仍须是本节标题的对象，换成另一对象即视为换节。后文小节专讲的对象，本段不提前交接：预告只能用读者已认识的词，不点后文才定义的名字（交叉见「句内骨架」）。
- 标题的名词短语要能还原成读者此刻认识的对象或动作，读不出“确认的是什么”的标题（如「确认依赖方向」）改成动作 + 具体宾语；标题和正文都不得使用读者尚未建立的概念术语（如「依赖」「使用方」「动态库」「稳定边界」）：术语要么已被前文章节建立，要么当场用读者可核对的实物（目录、文件、代码）建立；做不到就把内容下沉到概念建立之后的章节（例：02 章依赖方向的事实删除，下沉到 05 章 CTest 首次出现处）。一句话压缩多个论断而读者无法逐条核对的，拆成可核对表述或删除；首句先给中心判断，再补机制，不先堆名称后给结论。正文论据同受此限：未在正文展示过的代码标识符（如测试概念建立前引用 `BoardTest`）不作论据，验证职责下沉到展示它的章节。改写对照见标识 `bg-chinese-style-cases-v1` 的知识文件「小节标题抽象与首句无中心」。
- 操作小节（如「运行一键脚本」）只保留动作、顺序与可见结果。「为何不跳过某步 / 幂等 / 配置漂移」类工程取舍，删除后不影响首次跑通与验收的，不进该节正文；确需保留时由代码注释或排查节承担。
- 跨节复述同一取舍视为标题离题的变体：该内容归属最贴合的节（如「修改 CMakeLists 后行为没变」），其余位置只保留一句或链接。
