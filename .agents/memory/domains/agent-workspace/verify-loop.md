# 验证闸有界

## 现象与根因

长任务里出现「跑闸 → 改 → 再跑闸 → 仍红 → 再跑闸」的死循环（temp/ 留有 verify-out.txt → verify2.txt → verify-now.txt 的现场）。三层根因：新闸上线当日多章同红、改写互相牵动；verify 慢且输出长，对话里反复执行烧上下文；会话回收机制把以「我再验证一下」收尾（无证据）的回合反复拉起。

## 对策

- 每批次只跑一次闸（首验 + 至多一次复验），输出重定向 temp/，对话只读失败摘要；同 FAIL 指纹连续 2 轮停手转人工；WARN 只记台账不追清零。
- 先对照目标形态写完再首跑闸；禁止把闸报错当逐条修改依据边写边闸。
- 每轮以「已完成 | 阻塞 + 证据路径」收尾，不以未兑现的「再验证」承诺收尾。
- 规则正文：`.agents/skills/testing/references/verification-matrix.md`「闸次与退出」；AGENTS.md 有 ≤3 行短条。来源：`.zcode/plans/plan.md`「段内同义堆叠禁令」阶段 J。
